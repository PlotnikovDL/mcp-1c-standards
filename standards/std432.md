# #std432 Использование реквизитов строкового типа

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Длина строки

### 1.1. Переменная длина (по умолчанию)

Для реквизитов строкового типа следует использовать **переменную длину** строки:
- Свойство `Допустимая длина` = **Переменная**
- Указывать **максимально допустимую длину** строки

⚠️ Свойство `Допустимая длина` = **Фиксированная** только когда необходимо иметь гарантию определённой длины строки (за счёт автоматического дополнения концевыми пробелами).

### 1.2. Регламентированная длина

Когда максимальная длина строки **заранее известна** (регламентирована), следует указывать её в свойстве `Длина` (или `Длина наименования` для стандартного реквизита `Наименование`).

**Пример:** Реквизит `ИНН` справочника `ФизическиеЛица` = **12 символов**

### 1.3. Конкатенация строк

Если строка является **конкатенацией** других строк, то её длина = сумма длин исходных строк.

**Пример:** Длина представления адреса = сумма длин полей, в которых хранятся части адреса.

### 1.4. Нерегламентированная длина

Если длина строки не регламентирована, рекомендуется выбирать длину, **достаточную для большинства случаев**.

**Рекомендуемые длины:**

| Данные | Длина |
|--------|-------|
| Полное наименование контрагента | 250 |
| Максимальная длина имени файла | 260 |
| Полное имя физического лица | 100 |

---

## 2. Строки неограниченной длины

Допускается использование строк неограниченной длины в **отдельных случаях**.

### 2.1. Пользовательский текст значительного объёма

Предполагается, что пользователь может ввести текст большого объёма. Как правило, это **многострочные поля** на форме.

**Примеры:**
- Поле `ДополнительноеОписание` в заказе клиента — менеджер может поместить всю историю переписки
- Поле `Комментарий` — произвольный многострочный текст

### 2.2. Техническая информация

В строковом реквизите хранится техническая информация, которая:
- Генерируется программами
- Не предназначена для чтения пользователем
- Используется в алгоритмах обработки

**Примеры:**
- XML-документы
- Заголовки почтовых сообщений

---

## 3. Ограничения в языке запросов

При использовании строковых реквизитов неограниченной длины возникают ограничения.

### 3.1. Сравнение, группировка, РАЗЛИЧНЫЕ

При необходимости сравнения значений, группировки и получения различных — реквизиты необходимо **выражать как строку определённой длины**.

```1c
ВЫРАЗИТЬ(РеквизитСтрока КАК СТРОКА(1000))
```

### 3.2. Отчёты СКД

Для полей с неограниченной длиной следует задавать параметр **Тип значения** поля (на закладке **Наборы данных**).

### 3.3. Признак неправильного проектирования

⚠️ Частое приведение неограниченной строки к определённой длине в запросах и отчётах СКД может быть признаком **неправильного проектного решения** и сигналом для пересмотра типа в пользу **ограниченной длины**.

### 3.4. Когда не урезать

В остальных случаях урезать строку в запросах **не требуется**.

---

## 4. Печатные формы

Если в печатных формах предусмотрено отображение строкового поля, необходимо обеспечить **вывод строк полностью**, без обрезания части строки.

⚠️ В противном случае может быть утеряна значимая часть информации.

**Пример:** Номер дома и квартиры в поле с адресом доставки товара.

---

## 5. Сводная таблица

| Ситуация | Рекомендация |
|----------|--------------|
| Обычный реквизит | Переменная длина + максимум |
| Регламентированная длина (ИНН и т.п.) | Точная длина |
| Многострочный пользовательский текст | Неограниченная длина |
| Техническая информация (XML и т.п.) | Неограниченная длина |
| Частое приведение к длине в запросах | Пересмотреть в пользу ограниченной |
