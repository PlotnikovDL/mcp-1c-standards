# #std708 Разрешение итогов для периодических регистров сведений

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

*Методическая рекомендация (полезный совет)*

---

## 1. Когда разрешать итоги

### 1.1. Условия для включения итогов

Разрешайте итоги для периодического регистра сведений, если выполнены **все** условия:

| Условие | Описание |
|---------|----------|
| Большой объём данных | Оправдано для цен номенклатуры; не имеет смысла для курсов валют |
| Частые запросы к срезам | Запросы к `СрезПоследних` / `СрезПервых` **без указания периода** (на текущий момент) |
| Простые условия | Условия только на значения **измерений** (и разделителей в режиме «Независимо и совместно») |
| Простые ограничения RLS | В ограничениях доступа используются только **измерения** |

**Пример запроса**, который ускорится при включении итогов:

```1c
ВЫБРАТЬ
    Номенклатура.Артикул КАК Артикул,
    ЦеныНоменклатуры.Цена КАК Цена,
    ...
ИЗ
    Справочник.Номенклатура КАК Номенклатура
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.ЦеныНоменклатуры.СрезПоследних(, ВидЦены = &ВидЦены) КАК ЦеныНоменклатуры
    ПО ЦеныНоменклатуры.Номенклатура = Номенклатура.Ссылка
```

**Результат:** Установка свойства `Разрешить итоги: срез последних` ускорит запрос — выборка будет из дополнительных таблиц с последними/первыми значениями.

### 1.2. Адаптация запросов под итоги

Рассмотрите возможность **переписать запросы** так, чтобы условия выполнялись.

**Пример:** Данные записываются будущей датой, но запросы всегда на текущую дату (явно задана в параметре `СрезПоследних`) — итоги **не ускорят** такие запросы.

**Решение:** При открытии формы подбора проверить, есть ли записи с будущей датой:
- Если **нет** → запрос к `СрезПоследних` **без даты** (использует итоги)
- Если **есть** → запрос с явной датой

---

## 2. Когда НЕ разрешать итоги

**Не включайте** итоги, если:

| Ситуация | Причина |
|----------|---------|
| Запросы на конкретный период | Всегда/часто указана дата (например, дата документа) |
| Подзапросы в условиях | Используются подзапросы и соединения в параметрах виртуальной таблицы |
| Обращения «через точку» | Условия обращаются к полям связанных таблиц |

❌ **Пример, когда итоги НЕ помогут:**

```1c
ВЫБРАТЬ ...
ИЗ
    РегистрСведений.КурсыВалют.СрезПоследних(, Валюта.Код = &КодВалютыСклада) КАК КурсыВалют
```

Здесь `Валюта.Код` — обращение «через точку» к связанной таблице.

---

## 3. Пересчёт итогов

**Не требуется** создавать отдельный механизм пересчёта — актуализация таблиц итогов выполняется **автоматически** при каждой записи набора записей.

⚠️ **Исключение:** Если использование итогов отключалось принудительно:

```1c
РегистрыСведений.ЦеныНоменклатуры.УстановитьИспользованиеИтогов(Ложь);
```

---

## 4. Сводка

| Включать итоги | Не включать итоги |
|----------------|-------------------|
| Большой объём данных | Малый объём данных |
| Запросы без указания периода | Запросы на конкретную дату |
| Условия только на измерения | Подзапросы, соединения, «через точку» |
| RLS только на измерениях | Сложные ограничения RLS |
