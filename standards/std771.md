# #std771 Интеграция прикладных решений через формат EnterpriseData

> Область применения: управляемое приложение.

---

## 1. Выбор технологии обмена

| Сценарий | Технология |
|----------|------------|
| Переходы с конфигурации на конфигурацию | Правила конвертации (ПК) |
| Обмены между конфигурациями на БСП | **Формат EnterpriseData** |
| Решения для бюджетных организаций | Правила конвертации (ПК) — исключение |

❌ **Запрещается** разрабатывать новые обмены на основе ПК (кроме бюджетных решений).

---

## 2. Версии EnterpriseData

Актуальные версии содержатся в последней опубликованной версии БСП в виде объектов метаданных **Пакет XDTO**.

**Именование:** `EnterpriseData_{X|XX}_{Y|YY}_{Z|ZZ}`

- X, Y — Major версия
- Z — Minor версия

**Политика версий:** список поддерживается для оптимального баланса между затратами на поддержку и совместимостью версий.

*Пример:* версии 1.0, 1.1 сняты с поддержки — интервала 1.2-1.4 достаточно для широкого диапазона версий прикладных решений.

---

## 3. Поддержка всех актуальных версий

При разработке новых версий прикладных решений необходимо стремиться к поддержке **всех актуальных версий** EnterpriseData.

**Преимущества:**
- Асинхронный выпуск новых версий для разработчиков
- Асинхронный переход на новые версии для пользователей

❌ **Запрещается** выпускать версию конфигурации, не поддерживающую какую-либо из версий формата, поддерживаемых в версии БСП, встроенной в конфигурацию.

**Пример:**
При выпуске конфигурации с БСП 2.4.1 необходимо поддержать версии 1.2, 1.3 и 1.4 формата EnterpriseData.

---

## 4. Исключение версий по требованиям функциональности

Версия формата **не должна поддерживаться**, если она не соответствует требованиям к функциональности обмена.

**Пример:**
Для интеграции необходим обмен документами «Чек ККМ». Поддержка передачи этих данных есть только в версии 1.4 → поддерживаемые версии должны быть **не младше 1.4**.

---

## 5. Информирование пользователей (рекомендация)

В редких случаях обмен невозможен из-за отсутствия совместно поддерживаемых версий EnterpriseData (например, когда одна из версий прикладного решения сильно устарела).

✅ **Рекомендуется** информировать пользователей о том, какие версии EnterpriseData поддерживаются в прикладном решении.

---

## 6. Использование AdditionalInfo

❌ **Запрещено** использовать свойство `AdditionalInfo` для передачи сведений между информационными базами в типовых обменах.

Для расширения состава свойств формата необходимо вносить **согласованные изменения в формат**, чтобы все группы разработки типовых конфигураций имели возможность поддержать новые возможности.

### Исключения (когда AdditionalInfo разрешён)

| Ситуация | Описание |
|----------|----------|
| Поддержка законодательства | Когда не остаётся времени на выпуск новой версии формата |
| Обход критических ошибок | Ошибки, блокирующие синхронизацию вызовом исключений |

⚠️ **Важно:** после добавления данных в AdditionalInfo потребуется долгое время поддерживать этот сценарий для совместимости с прошлыми версиями.

---

## Сводка

| Правило | Описание |
|---------|----------|
| Обмены на БСП | Только EnterpriseData |
| Новые обмены на ПК | Запрещены (кроме бюджетных) |
| Поддержка версий | Все актуальные версии из встроенной БСП |
| Минимальная версия | Определяется требованиями функциональности |
| AdditionalInfo | Запрещён в типовых обменах |
