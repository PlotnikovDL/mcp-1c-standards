# #std704 Использование определяемых типов

> Область применения: управляемое приложение, обычное приложение.

---

## 1. Назначение определяемых типов

Определяемые типы предназначены для определения типов данных, которые:
- Описывают **часто используемые сущности**
- С **высокой вероятностью могут изменяться** при внедрении

Они позволяют **многократно использовать** описываемый тип или набор типов без уточнения состава в различных местах конфигурации:
- Реквизиты объектов
- Свойства форм
- Ресурсы регистров
- Макеты

---

## 2. Рекомендуемые случаи использования

### 2.1. Простой тип с прикладным смыслом

Для определения **простого типа и его квалификаторов**, который используется в различных местах подсистемы или всего решения.

**Преимущества:**
- Гарантирует **одинаковую длину и точность** данных везде
- Упрощает доработку при изменении требований

**Примеры:**

| Определяемый тип | Тип | Использование |
|------------------|-----|---------------|
| `НомерСчетаФактуры` | Строка, 30 | Документы: ПоступлениеТоваровИУслуг, ЗаписьКнигиПокупок, ВозвратТоваровОтКлиента |
| `АдресДоставки` | Строка, 500 | Документы: ЗаказПоставщику, ЗаявкаНаВозвратТоваровОтКлиента; Обработка: ПомощникПродаж |

### 2.2. Составной тип для подсистемы

Для определения **составного типа**, который **массово используется** в объектах подсистемы.

**Преимущества:**
- Гарантирует **одинаковый состав типов** везде
- Упрощает **внедрение подсистем** в прикладные конфигурации

**Пример: подсистема "Взаимодействия"**

Определяемый тип `КонтактВзаимодействий`:
```
СправочникСсылка.ФизическиеЛица
СправочникСсылка.Партнеры
СправочникСсылка.КонтактныеЛицаПартнеров
```

Используется в:
- Документ `Встреча` — табличная часть `Участники`
- Документ `ЗапланированноеВзаимодействие` — табличная часть `Участники`
- Документ `СообщениеSMS` — табличная часть `Адресаты`
- Документ `ТелефонныйЗвонок` — реквизит `АбонентКонтакт`
- Общие формы `АдреснаяКнига`, `ВыборКонтакта`
- Параметр макета журнала `Взаимодействия`

**Без определяемого типа** пришлось бы снимать объекты с поддержки и задавать состав типов во всех местах вручную.

### 2.3. Переопределяемый тип при внедрении

При разработке **внедряемой подсистемы** — для типа, который будет **уточнён при внедрении**.

**Пример:**
- Тип подсистемы: `Поставщики`
- При внедрении заменяется на: `Контрагенты` (прикладной тип конфигурации)

## 3. Некорректное использование

**НЕ используйте** определяемые типы:

| Антипаттерн | Почему плохо |
|-------------|--------------|
| «Синоним» существующего типа | Размывает прикладной смысл |
| «Подмена» сущностей | Ошибка проектирования |
| Локальное использование без внедрения | Избыточная абстракция |
| «На всякий случай» для лёгкости доработки | Методологически неверно |

**Пример некорректного использования:**

В конфигурации есть справочник `Контрагенты`, ссылки на который используются в регистрах и формах. Справочник:
- **НЕ является** частью встраиваемой подсистемы
- **НЕ является** сущностью, которая может быть расширена другими типами

❌ **Неправильно:** Создавать определяемый тип из единственного типа `Контрагенты` "на всякий случай"

✅ **Правильно:** Использовать `СправочникСсылка.Контрагенты` напрямую
