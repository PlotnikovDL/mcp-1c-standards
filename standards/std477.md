# #std477 Самодостаточность регистров

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Основное правило

При разработке структуры регистров необходимо придерживаться правила:

> **Регистр должен быть логически независим от регистраторов.**

---

## 2. Требования

Любая логика, опирающаяся или анализирующая данные регистра, а также любые отчёты по этому регистру:

| Требование | Описание |
|------------|----------|
| ⛔ Не должны | Обращаться к полям регистратора |
| ✅ Должны | Использовать только данные самого регистра |

---

## 3. Причины

### 3.1. Производительность

Обращение к полям регистратора «через точку» приводит к **неявному соединению** с дополнительными таблицами.

```1c
// ⛔ Неправильно — неявное соединение с документом
ВЫБРАТЬ
    Движения.Регистратор.Контрагент  // Обращение к полю регистратора
ИЗ
    РегистрНакопления.Продажи КАК Движения

// ✅ Правильно — данные хранятся в самом регистре
ВЫБРАТЬ
    Движения.Контрагент  // Поле регистра
ИЗ
    РегистрНакопления.Продажи КАК Движения
```

### 3.2. Распределённая информационная база (РИБ)

В распределённой ИБ **регистратора может не быть**, если:
- Движения в регистрах мигрируют между узлами
- Регистраторы (документы) не мигрируют

---

## 4. Практическая рекомендация

При проектировании регистра — все данные, необходимые для отчётов и анализа, должны быть **продублированы в измерениях или ресурсах** регистра.

| Данные | Где хранить |
|--------|-------------|
| Контрагент | Измерение регистра |
| Организация | Измерение регистра |
| Сумма | Ресурс регистра |
| Комментарий | Реквизит регистра |
