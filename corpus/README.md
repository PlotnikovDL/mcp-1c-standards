# Корпус стандартов 1С

Markdown-стандарты разработки 1С — корпус MCP-сервера `mcp-1c-standards` для поиска, чтения и подбора правил разработки. Хранится в подкаталоге `corpus` репозитория сервера; до 16 октября 2026 года был отдельным репозиторием `1c-docs`, история которого перенесена вместе с файлами.

## Состав

На 7 октября 2026 года перенесён весь каталог ИТС: **321 стандарт и 320 иллюстраций**. Прямые ссылки на каждый документ, его источник и изображения собраны в [каталоге](CATALOG.md).

```text
standards/
  std411.md
  std799.md
  ...
  assets/
    std411/
      01.png
      02.png
      03.png
    std799/
      01.png
      02.png
```

Путь источника MCP по умолчанию: `corpus/standards` относительно корня репозитория сервера (переопределяется `ONEC_STANDARDS_DIR`).

## Формат документов

- Стабильное имя `std<ID>.md`, заголовок с ID и названием оригинала.
- Область применения, если она указана в оригинале; раздел ИТС, ссылка на источник и дата сверки.
- Текст, исходная нумерация, условия, исключения и примеры кода сохраняются. Авторские конспекты и сводки не подменяют требования оригинала.
- Код хранится в блоках Markdown; исходные отступы сохранены. Нормализованы окончания строк и хвостовые пробелы.
- Таблицы сохранены как HTML внутри Markdown: это позволяет сохранить вложенные таблицы, объединённые ячейки, списки, код и цветовые образцы.
- Изображения сохранены без перекодирования. Относительные ссылки разрешаются от каталога файла стандарта. Нейтральные подписи служат идентификаторами иллюстраций; они не заменяют просмотр изображения.
- Дата сверки обозначает дату проверки источника, а не дату публикации стандарта. Исторические рекомендации для интерфейсов 8.2 и обычного приложения сохраняют свою исходную область применения.

Служебный журнал новых и изменённых разделов [ИТС № 788](https://its.1c.ru/db/v8std/content/788/hdoc) не включён в `standards`.

## Чтение через MCP

После поиска нужно читать полный текст через `read_standard`. Если правило зависит от иллюстрации, следует открыть её локальный файл по ссылке из документа. Текущий `read_standard` возвращает Markdown со ссылками; изображение не передаётся в его ответе автоматически.

Перед непустым поиском сервер сверяет список файлов, их размеры и время изменения. При изменении этих данных он обновляет индекс. Правка с сохранением размера и времени может остаться незамеченной. `list_standards` и `read_standard` читают файлы с диска.

## Связанные файлы

- `../server.py`, `../standards_index.py` — MCP-сервер поиска в этом же репозитории ([README сервера](../README.md)).
- `../.cache` — технический кэш embeddings; исключён из Git и пересоздаётся из стандартов.

## Проверка переноса

Для всего корпуса проверяются читаемость UTF-8, соответствие списка файлов каталогу ИТС, полнота текста, структура списков и таблиц, примеры кода, ссылки и якоря. Все локальные изображения проверяются по SHA-256 относительно загруженных оригиналов. После обновления выполняются `list_standards`, `read_standard` и контрольные поисковые запросы через MCP.
