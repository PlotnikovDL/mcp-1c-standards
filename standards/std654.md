# #std654 Разыменование ссылочных полей составного типа в языке запросов

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Проблема обращения «через точку»

### 1.1. Неявные соединения

При обращении к полям «через точку» от ссылочного поля происходит **неявное соединение** с дополнительными таблицами.

```1c
ВЫБРАТЬ
    ТоварныеЗапасы.Товар КАК Товар,
    ТоварныеЗапасы.Количество КАК Количество,
    ТоварныеЗапасы.Товар.Артикул КАК Артикул  // ← неявное соединение
ИЗ
    РегистрНакопления.ТоварныеЗапасы КАК ТоварныеЗапасы
```

Кроме таблицы `РегистрНакопления.ТоварныеЗапасы` неявно подключается `Справочник.Товары` для получения поля `Артикул`. При использовании RLS добавляются ещё и таблицы из ограничений доступа.

### 1.2. Составные типы — особая опасность

⚠️ Если поле имеет **составной тип**, то происходит соединение со **всеми** таблицами, ссылки на которые могут быть в этом поле.

```1c
ВЫБРАТЬ
    ТоварныеЗапасы.Регистратор.Дата  // ← соединение со ВСЕМИ документами-регистраторами!
ИЗ
    РегистрНакопления.ТоварныеЗапасы
```

**Пример:** Регистратор может быть одним из 56 видов документов → SQL-запрос будет содержать **56 левых соединений** с таблицами документов.

> Обращение «через точку» от ссылочных полей составного типа **крайне нежелательно**.

---

## 2. Решения

### 2.1. Ограничивайте типы при создании полей

Указывайте **ровно столько типов**, сколько необходимо.

| ❌ Неправильно | ✅ Правильно |
|----------------|--------------|
| Любая ссылка | Конкретные справочники/документы |
| Ссылка на любой документ | Только нужные виды документов |

### 2.2. Денормализация — добавление реквизитов

Жертвуйте компактностью хранения ради производительности.

❌ **Неправильно:**
```1c
ВЫБРАТЬ
    ТоварныеЗапасы.Регистратор.Дата
ИЗ
    РегистрНакопления.ТоварныеЗапасы
```

✅ **Правильно:** Добавить реквизит `ДатаРегистратора` в регистр и заполнять при проведении:
```1c
ВЫБРАТЬ
    ТоварныеЗапасы.ДатаРегистратора
ИЗ
    РегистрНакопления.ТоварныеЗапасы
```

### 2.3. Использование ВЫРАЗИТЬ для ограничения типов

Жертвуйте компактностью и универсальностью кода ради производительности.

❌ **Неправильно:** (56 соединений)
```1c
ВЫБРАТЬ
    Продажи.Регистратор.Номер,
    Продажи.Регистратор.Дата
ИЗ
    РегистрНакопления.Продажи КАК Продажи
ГДЕ ...
```

✅ **Правильно:** (2 соединения)
```1c
ВЫБРАТЬ
    ВЫБОР
        КОГДА Продажи.Регистратор ССЫЛКА Документ.РеализацияТоваровУслуг
            ТОГДА ВЫРАЗИТЬ(Продажи.Регистратор КАК Документ.РеализацияТоваровУслуг).Номер
        КОГДА Продажи.Регистратор ССЫЛКА Документ.ЗаказПокупателя
            ТОГДА ВЫРАЗИТЬ(Продажи.Регистратор КАК Документ.ЗаказПокупателя).Номер
    КОНЕЦ КАК Номер,
    ВЫБОР
        КОГДА Продажи.Регистратор ССЫЛКА Документ.РеализацияТоваровУслуг
            ТОГДА ВЫРАЗИТЬ(Продажи.Регистратор КАК Документ.РеализацияТоваровУслуг).Дата
        КОГДА Продажи.Регистратор ССЫЛКА Документ.ЗаказПокупателя
            ТОГДА ВЫРАЗИТЬ(Продажи.Регистратор КАК Документ.ЗаказПокупателя).Дата
    КОНЕЦ КАК Дата
ИЗ
    РегистрНакопления.Продажи КАК Продажи
ГДЕ
    Продажи.Регистратор ССЫЛКА Документ.РеализацияТоваровУслуг
    ИЛИ Продажи.Регистратор ССЫЛКА Документ.ЗаказПокупателя
```

**Для универсальных запросов:** формируйте текст динамически, подставляя в `ВЫРАЗИТЬ` нужный тип.

---

## 3. Сводка

| Проблема | Решение |
|----------|---------|
| Обращение «через точку» от составного типа | Избегать или использовать `ВЫРАЗИТЬ` |
| Регистратор.Дата, Регистратор.Номер | Добавить реквизит в регистр (денормализация) |
| Поле с «любой ссылкой» | Ограничить конкретными типами |
| Универсальный запрос для разных типов | Динамическое формирование с `ВЫРАЗИТЬ` |
