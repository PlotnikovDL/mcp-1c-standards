# #std778 Денежные поля: требования по локализации

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Разрядность денежных полей

Для обеспечения работы конфигурации в странах с низким курсом национальной валюты необходимо предусмотреть увеличение разрядности целой части числовых полей, содержащих денежный эквивалент — **денежные поля**.

**Примеры денежных полей:** Сумма, Цена, Себестоимость.

### Определяемые типы в метаданных

| Условие | Определяемый тип |
|---------|------------------|
| Только положительные значения | **ДенежнаяСуммаНеотрицательная** |
| Отрицательные значения допустимы | **ДенежнаяСуммаЛюбогоЗнака** (флаг «Неотрицательное» сброшен) |

### Когда определяемый тип невозможен

Когда определяемый тип невозможно указать (например, для параметра формы или в составном типе), следует задать числовой тип максимальной длины — **Число(31, 2)**.

**Исключение:** В отдельных случаях длина должна быть снижена из-за ограничений СУБД (например, в ресурсах регистров).

---

## 2. Описание типа денежного поля в коде (БСП)

При использовании **Библиотеки стандартных подсистем** не следует использовать конструктор типа **Число** для получения описания типа денежного поля. Вместо этого использовать функцию, возвращающую описание на основании определяемого типа.

❌ **Неправильно:**

```1c
ОписаниеТиповСумма = Новый ОписаниеТипов("Число", Новый КвалификаторыЧисла(15,2));
```

✅ **Правильно:**

```1c
ОписаниеТиповСумма = РаботаСКурсамиВалют.ОписаниеТипаДенежногоПоля();
```

---

## 3. ВЫРАЗИТЬ в запросах

При использовании **ВЫРАЗИТЬ** в текстах запросов для денежных полей использовать приведение к типу **ЧИСЛО(31,2)**, что обеспечивает поддержку максимальной длины целой части 29.

**Примечание:** Ограничение длины целой части 29 обусловлено поддержкой сервера DB2.

❌ **Неправильно:**

```1c
ВЫРАЗИТЬ(Т.Сумма / Т.Количество КАК ЧИСЛО(15,2))
```

✅ **Правильно:**

```1c
ВЫРАЗИТЬ(Т.Сумма / Т.Количество КАК ЧИСЛО(31,2))
```

---

## 4. Функция Формат и свойства форматирования

При использовании функции **Формат** и при задании формата в свойствах элементов формы, свойствах полей наборов схем компоновки данных и т.д. **не следует задавать общую длину** (ЧЦ).

❌ **Неправильно:**

```1c
Формат(Выборка.СуммаДокумента, "ЧЦ=15; ЧДЦ=2")
```

✅ **Правильно:**

```1c
Формат(Выборка.СуммаДокумента, "ЧДЦ=2")
```

### В настройках СКД

> На скриншоте: в свойствах поля СКД параметр «Формат» = `ЧДЦ=2` (без указания ЧЦ).

---

## Сводка

| Контекст | Рекомендация |
|----------|--------------|
| Метаданные (положительные) | `ДенежнаяСуммаНеотрицательная` |
| Метаданные (любой знак) | `ДенежнаяСуммаЛюбогоЗнака` |
| Параметры формы, составные типы | `Число(31, 2)` |
| Код (БСП) | `РаботаСКурсамиВалют.ОписаниеТипаДенежногоПоля()` |
| ВЫРАЗИТЬ в запросах | `ЧИСЛО(31,2)` |
| Функция Формат | `ЧДЦ=2` без ЧЦ |
