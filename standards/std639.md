# #std639 Использование переменных в программных модулях

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.
>
> Раздел ИТС: Соглашения при написании кода / Использование конструкций встроенного языка
>
> Источник: https://its.1c.ru/db/v8std/content/639/hdoc
>
> Проверено по источнику: 2026-10-07

<a id="1"></a>1\. В большинстве случаев, вместо переменных программных модулей следует использовать более подходящие средства разработки платформы **1С:Предприятие**. Поскольку область видимости (использования) таких переменных сложно контролировать, то они зачастую становятся источником трудновоспроизводимых ошибок.

Примеры некорректного использования и исключений из этого правила приведены далее. Рекомендации по оформлению переменных в коде программных модулей см. в статье [Структура модуля](<https://its.1c.ru/db/v8std/content/455/hdoc>).

<a id="2"></a>2\. Неоправданные примеры использования переменных в модулях объектов (справочников, документов, наборов записей, обработок, отчетов и пр.).

<a id="2.1"></a>2.1. Для передачи параметров между обработчиками подписок на события и в обработчики событий модуля объекта из внешнего кода рекомендуется использовать свойство объекта **ДополнительныеСвойства**. Например, неправильно:

```bsl
Перем КонвертацияФайлов Экспорт;
```

```bsl
Процедура ПередЗаписью(Отказ)

  Если КонвертацияФайлов Тогда
  ...

КонецПроцедуры
```

```bsl
// вызывающий код
ФайлОбъект.КонвертацияФайлов = Истина;
ФайлОбъект.Записать();
```

Правильно:

```bsl
Процедура ПередЗаписью(Отказ)

  Если ДополнительныеСвойства.Свойство("КонвертацияФайлов") Тогда
  ...

КонецПроцедуры
```

```bsl
// вызывающий код
ФайлОбъект.ДополнительныеСвойства.Вставить("КонвертацияФайлов", Истина);
ФайлОбъект.Записать();
```

В то же время, для передачи внутренних параметров между обработчиками событий модуля объекта целесообразно использовать неэкспортные переменные модуля объекта, которые недоступны из внешнего кода. <br>

Например:

```bsl
Перем ПредыдущееЗначениеОрганизации; // значение реквизита "Организация" до записи объекта в базу
```

```bsl
Процедура ПередЗаписью(Отказ)
  ПредыдущееЗначениеОрганизации = ...; // с помощью запроса выясняем значение до записи объекта в базу
КонецПроцедуры
```

```bsl
Процедура ПриЗаписи(Отказ)
  Если ПредыдущееЗначениеРеквизита <> Организация Тогда
    // отрабатываем изменение значения реквизита при записи
    ...
  КонецЕсли;
```

```bsl
КонецПроцедуры
```

<a id="2.2"></a>2.2. Для обработки кодов возврата (ошибок) в логике программного модуля рекомендуется использовать строковые константы. <br>

Например, неправильно:

```bsl
Перем НетОшибок,
Ошибка_ОбработкиПроверкиЗаполнения, // возникает, если обработка проверки заполнения вернула отказ
Ошибка_ЗаписиОбъекта, // возникает, если во время записи объекта возникло исключение
Ошибка_БлокировкиОбъекта, // возникает, при попытке блокировки объекта
```

```bsl
Процедура ВыполнитьПерерасчет()
  ...
  Результат = ОбработатьДокументы(...);
  Если Результат = Ошибка_ЗаписиОбъекта Тогда
    ...
  ИначеЕсли Результат = Ошибка_БлокировкиОбъекта Тогда
    ...
  ИначеЕсли ...
```

```bsl
КонецПроцедуры
```

```bsl
...
```

```bsl
НетОшибок     = 1;
Ошибка_ОбработкиПроверкиЗаполнения = 2;
Ошибка_ЗаписиОбъекта    = 3;
Ошибка_БлокировкиОбъекта   = 4;
```

правильно:

```bsl
Процедура ВыполнитьПерерасчет()
  ...
  Результат = ОбработатьДокументы(...);
  Если Результат = "ОшибкаЗаписиОбъекта" Тогда
    ...
  ИначеЕсли Результат = "ОшибкаБлокировкиОбъекта" Тогда
    ...
  ИначеЕсли ...
```

```bsl
КонецПроцедуры
```

<a id="2.3"></a>2.3. Для кеширования долго-вычисляемых и часто-используемых значений в процедурах и функциях рекомендуется применять [модули с повторным использованием возвращаемых значений](<https://its.1c.ru/db/v8std/content/459/hdoc>) на время вызова сервера.

Исключение из этого правила составляют случаи, когда по соображениям безопасности возвращать результат вычисления в экспортной функции недопустимо. В этом случае они размещаются в локальной переменной модуля.

<a id="3"></a>3\. Неоправданные примеры использования переменных в модулях форм.

<a id="3.1"></a>3.1. Для кеширования долго-вычисляемых и часто-используемых значений в процедурах и функциях рекомендуется применять [модули с повторным использованием возвращаемых значений](<https://its.1c.ru/db/v8std/content/459/hdoc>).

При этом не следует кешировать статическую и легко вычисляемую информацию. В частности, не следует кешировать в клиентских переменных модуля формы значения предопределенных элементов и перечислений. Для их получения на клиенте предназначен [метод **ПредопределенноеЗначение**](<https://its.1c.ru/db/v8std/content/443/hdoc>).

<a id="3.2"></a>3.2. Для хранения и передачи промежуточных результатов вычислений между разными процедурами и функциями формы следует использовать

- [Параметры процедур и функций](<https://its.1c.ru/db/v8std/content/640/hdoc>) – для передачи результатов по цепочке вызовов дочерних процедур и функций в контексте одного вызова.

- Реквизиты формы – если требуется сохранять промежуточные результаты между разными вызовами с клиента. (Следует иметь в виду, что значения серверных переменных модуля формы не сохраняются между вызовами с клиента.)

Исключение из этого правила составляют случаи использования клиентских переменных формы для хранения промежуточных результатов в обработчиках ожидания формы, в обработчиках внешних событий и в клиентских обработчиках событий элементов формы.<br>

Например:

```bsl
&НаКлиенте
Перем ПорядковыйНомерИзображения; // счетчик-нумератор для наименования файлов при сканирования нескольких изображений
...
&НаКлиенте
Процедура ВнешнееСобытие(Источник, Событие, Данные)
 Если Источник = "TWAIN" И Событие = "ImageAcquired" Тогда
  Если ПорядковыйНомерИзображения = Неопределено Тогда
   ПорядковыйНомерИзображения = 1;
  КонецЕсли;
  ПорядковыйНомерИзображения = ПорядковыйНомерИзображения + 1;
  // Сохранение отсканированного документа в файл с номером ПорядковыйНомерИзображения
  // ...
 КонецЕсли;
КонецПроцедуры
```

<a id="4"></a>4\. Переменные управляемого и обычного приложения следует использовать для хранения «клиентских параметров сеанса». Подробнее см. статью [Использование параметров сеанса](<https://its.1c.ru/db/v8std/content/413/hdoc>).<br>
