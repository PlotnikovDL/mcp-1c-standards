# #std531 Реквизит «Комментарий» у документов

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

> *Методическая рекомендация (полезный совет)*

---

## 1. Рекомендация

Для всех документов рекомендуется создавать реквизит **Комментарий** (строка неограниченной длины).

### 1.1. Назначение

В этом реквизите пользователи могут записывать различные **заметки служебного характера**, которые не относятся к прикладной специфике документа.

**Примеры:**
- Причина пометки на удаление
- Служебные заметки
- Информация для других пользователей

### 1.2. Права доступа

Доступ к реквизиту должен быть настроен **так же, как и к самому документу**:

| Права на документ | Права на комментарий |
|-------------------|---------------------|
| Только чтение | Только чтение |
| Запись | Запись |

---

## 2. Разделение служебного и прикладного

Если штатный сценарий работы пользователя предусматривает внесение **произвольной текстовой информации** в документ, необходимо предусмотреть **отдельные реквизиты «прикладного» характера**.

| Назначение | Реквизит |
|------------|----------|
| Служебные заметки | `Комментарий` |
| Прикладная информация | Отдельный реквизит |

**Пример:**

Документ `ЗаказКлиента`:
- ✅ Для дополнительных договорённостей с клиентом → реквизит `ДополнительнаяИнформация`
- ⛔ Не использовать служебный `Комментарий` для прикладных данных

---

## 3. Редактирование комментария

### 3.1. Простейший случай

Использовать функцию `ВвестиСтроку` в качестве внешнего редактора текста комментария.

### 3.2. При использовании БСП

Использовать процедуру общего модуля `ОбщегоНазначенияКлиент`:

```1c
ОбщегоНазначенияКлиент.ПоказатьФормуРедактированияКомментария(
    Элемент,
    "Комментарий",
    ЭтаФорма
);
```
