# #std798 Использование ботов системы взаимодействия

> Область применения: управляемое приложение.
>
> Раздел ИТС: Создание и изменение объектов метаданных / Организация работы конфигурации
>
> Источник: https://its.1c.ru/db/v8std/content/798/hdoc
>
> Проверено по источнику: 2026-10-07

<a id="1"></a>1\. Для работы ботов в конфигурации должно быть предусмотрено регламентное задание, которое вызывает метод **СистемаВзаимодействия.ВыполнитьОбработкуБотов()** ([см. документацию](<https://its.1c.ru/db/v8327doc/bookmark/dev/TI000002350>)). Этот метод имеет следующие особенности реализации

- работает без учета разделителей. Он обращается к данным о регистрации системы взаимодействия в каждой области разделенной ИБ, а также к системной таблице экземпляров ботов этой области. Если область зарегистрирована в системе взаимодействия и есть боты, то для этой области запускается системный процесс, в рамках которого устанавливается WebSocket-соединение с сервером взаимодействия

- системный процесс запускается по одному на каждую область, независимо от количества экземпляров ботов

- предопределенные боты создаются при первом вызове метода **ВыполнитьОбработкуБотов()**

Для учета особенностей работы метода **ВыполнитьОбработкуБотов()** в прикладных решениях, ориентированных на работу в модели сервиса по [Технологии 1cFresh](<https://v8.1c.ru/platforma/tekhnologiya-1cfresh/>), необходимо придерживаться перечисленных ниже рекомендаций.

<br>

1.1. В конфигурации не должно быть предопределенных ботов системы взаимодействия и должны быть предусмотрены настройки для включения использования бота, а также его отключения. При включении настройки нужно программно создавать бота, при выключении – удалять.

<br>

1.2. Регламентное задание, вызывающее метод **ВыполнитьОбработкуБотов()**

- В конфигурации должно быть одно, независимо от того, сколько объектов метаданных **БотСистемыВзаимодействия** добавлено

- Регламентное задание не должно включаться в состав любого из разделителей, т.е. оно должно быть неразделенным

Несоблюдение этих правил приводит к неоправданному расходу ресурсов как со стороны сервера **1С:Предприятие**, так и со стороны сервера **Системы взаимодействия**.

<br>

2\. При создании бота необходимо указывать пользователя системы взаимодействия, не связанного с пользователем информационной базы, т.к. в противном случае пользователь информационной базы не сможет работать с **Системой взаимодействия**.

<br>

3\. При создании нескольких экземпляров ботов, связанных с одним и тем же объектом метаданных, необходимо связывать их с разными пользователями **Системы взаимодействия**. В противном случае будет работать только тот экземпляр бота, который создан последним.

<br>

4\. Код обработки сообщений ботов должен быть написан таким образом, чтобы при его выполнении не возникало [необработанных исключений](<https://its.1c.ru/db/v8std/content/499/hdoc>). Это требование обусловлено следующими особенностями реализации.

<br>

Сообщения, адресованные ботам, после получения их от сервера **Системы взаимодействия** сохраняются в системную таблицу очереди сообщений информационной базы. Затем платформа **1С:Предприятие** последовательно для каждого сообщения в очереди вызывает обработчик **ОбработкаСообщенияСистемыВзаимодействия** модуля бота, которому было адресовано сообщение. Сообщение удаляется из очереди после его успешной обработки (подробнее – [см. документацию](<https://its.1c.ru/db/v8327doc/bookmark/dev/TI000002350>)).

Если в процессе обработки сообщения происходит исключение, то сообщение не будет удалено из очереди и будет предпринята попытка его повторной обработки.

<br>

Таким образом, если при обработке сообщения всегда будет возникать исключение, то следующие сообщения никогда не будут обработаны.

<br>
