# #std553 Переопределяемые и поставляемые объекты библиотеки

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Категории объектов библиотеки

С точки зрения возможностей по настройке функциональности [библиотеки](#std551) для работы в конкретной конфигурации-потребителе все объекты библиотеки условно делятся на три категории:

| Категория | Описание | Пример |
|-----------|----------|--------|
| **Непереопределяемые объекты** | «Готовые» объекты, которые можно брать и использовать «как есть». Не следует изменять в конфигурации-потребителе. Обязательно должны присутствовать | Справочник **Пользователи** |
| **Переопределяемые объекты** | «Изменяемые» объекты для настройки библиотеки под конкретную конфигурацию. Могут или должны быть изменены | Общие модули с постфиксом «Переопределяемый» |
| **Определители типов** | Объекты-«классификаторы» без базовой реализации. Формируют единое пространство имён, реализация может различаться | Справочник **Организации** |

### Назначение переопределяемых объектов

- Изменение поведения библиотечной функциональности
- Параметризация спецификой конфигурации-потребителя
- Подключение библиотечной функциональности к объектам конфигурации-потребителя

---

## 2. Правила поставки

| Категория объектов | Правило поставки |
|--------------------|------------------|
| Непереопределяемые объекты | «Изменения не рекомендуются» |
| Переопределяемые объекты | «Изменения разрешены» |
| Определители типов | «Изменения разрешены» |

### Обоснование

**Непереопределяемые объекты** — зона ответственности разработчиков библиотеки. Не должны разрабатываться «по месту» в конфигурациях-потребителях.

⚠️ **Исключение:** допускается вносить изменения при:
- Срочном исправлении критичной ошибки
- Других особых соображениях

При этом изменения могут быть потеряны при следующем обновлении версии библиотеки, если не:
- Донести до разработчиков библиотеки необходимость внесения изменений
- Задокументировать отход от общей инструкции по обновлению

---

## 3. Минимизация количества переопределяемых объектов

Для упрощения настройки библиотеки и снижения трудоёмкости последующих обновлений следует **минимизировать количество переопределяемых объектов**.

### 3.1. Методики минимизации

| Методика | Описание | Пример |
|----------|----------|--------|
| Настройка состава типов | Расширение состава типов реквизитов для подключения функциональности | Общая команда составного типа, измерение в регистре сведений |
| Предопределённые элементы | Параметризация библиотечной функциональности | Справочник **ВидыКонтактнойИнформации** — какие виды предусмотрены для объектов |
| Переопределяемые общие модули | Изменение поведения через обработчики событий | `ПриПодготовкеМакетаОписанияОбновлений`, `ПриДобавленииОбработчиковОбновления` |

## 4. Переопределяемые общие модули

### 4.1. Именование

Переопределяемые общие модули следует называть с постфиксом **Переопределяемый**.

> См. также: правила создания общих модулей (#std469)

### 4.2. Вызовы только из библиотеки

Переопределяемые общие модули должны содержать **только экспортные процедуры**, которые вызываются из кода самой библиотеки.

❌ **Запрещается** вызывать процедуры переопределяемых модулей непосредственно из кода конфигурации-потребителя.

✅ К программному интерфейсу библиотеки следует относить только экспортные процедуры и функции **непереопределяемых** общих модулей.

**Пример правильной архитектуры:**

Модуль **ПапкиФайлов** (библиотечный, программный интерфейс):

```1c
Функция ПапкаФайлов(ВладелецФайловСсылка) Экспорт

  СтандартнаяОбработка = Истина;
  Результат = Неопределено;
  ПапкиФайловПереопределяемый.ПриПолученииПапкиФайлов(ВладелецФайловСсылка, Результат, СтандартнаяОбработка);

  Если СтандартнаяОбработка Тогда
    // реализация по умолчанию
    Результат = ...
  КонецЕсли;
  Возврат Результат;

КонецФункции
```

Модуль **ПапкиФайловПереопределяемый**:

```1c
// Вызывается из библиотеки при необходимости получить папку файлов для указанного владельца.
//
// Параметры:
//  ВладелецФайловСсылка – ЛюбаяСсылка                - владелец файлов, для которого нужно вернуть папку.
//  ПапкаФайлов          – СправочникСсылка.ПапкиФайлов - в этот параметр нужно записать результат.
//  СтандартнаяОбработка – Булево                      - по умолчанию, Истина. В этом случае папка будет получена способом по умолчанию.
//    Если значение параметра установить в Ложь, то в этой процедуре можно реализовать свой способ,
//    которым в конфигурации получают папки файлов.
//
Процедура ПриПолученииПапкиФайлов(ВладелецФайловСсылка, ПапкаФайлов, СтандартнаяОбработка) Экспорт

КонецПроцедуры
```

✅ Все вызовы из конфигурации-потребителя → только к **ПапкиФайлов**
✅ Обращение к **ПапкиФайловПереопределяемый** → только из **ПапкиФайлов**

### 4.3. Только пустая реализация

В переопределяемом модуле следует располагать **только экспортные процедуры с пустой реализацией**.

❌ Не должно быть каких-либо других не-экспортных процедур или функций.
✅ Базовую реализацию располагать в непереопределяемом коде.

**Неправильно** — поставлять переопределяемый модуль с реализацией:

```1c
Функция НастройкаПараметровРаботы() Экспорт

  ПараметрыРаботы = Новый Структура;
  // если настройки по умолчанию не подходят, то измените их.
  ПараметрыРаботы.Вставить("ПоказыватьЕдинственныйРаздел",     Ложь);
  ПараметрыРаботы.Вставить("ЗадаватьДатуДляПрочихРазделов",    Ложь);
  ПараметрыРаботы.Вставить("ИспользоватьВнешнихПользователей", Ложь);
  Возврат ПараметрыРаботы;

КонецФункции
```

**Правильно** — переопределяемый модуль:

```1c
// Позволяет настроить работу подсистемы.
//
// Параметры:
//  ПараметрыРаботы - Структура - содержит свойства:
//    * ПоказыватьЕдинственныйРаздел     - Булево - по умолчанию Ложь.
//    * ЗадаватьДатуДляПрочихРазделов    - Булево - по умолчанию Ложь.
//    * ИспользоватьВнешнихПользователей - Булево - по умолчанию Ложь.
//
Процедура ПриПолученииНастроекПараметровРаботы(ПараметрыРаботы) Экспорт

КонецПроцедуры
```

А установку значений по умолчанию перенести в общий модуль библиотеки:

```1c
Функция НастройкаПараметровРаботы()

  ПараметрыРаботы = Новый Структура;
  // настройки по умолчанию
  ПараметрыРаботы.Вставить("ПоказыватьЕдинственныйРаздел",     Ложь);
  ПараметрыРаботы.Вставить("ЗадаватьДатуДляПрочихРазделов",    Ложь);
  ПараметрыРаботы.Вставить("ИспользоватьВнешнихПользователей", Ложь);

  // а теперь запросим конфигурацию-потребитель на случай,
  // если эти умолчания не устраивают
  МояБиблиотекаПереопределяемый.ПриПолученииНастроекПараметровРаботы(ПараметрыРаботы);
  Возврат ПараметрыРаботы;

КонецФункции
```

### 4.4. Обновление переопределяемых модулей

При обновлении версии библиотеки особого внимания требуют:
- Модули корневого объекта конфигурации
- Переопределяемые общие модули

Автоматическое обновление таких «узких мест» невозможно.

**При первой настройке:**
1. Ознакомиться с документацией к экспортным процедурам и функциям (комментарии)
2. При необходимости вписать реализацию

**При каждом обновлении:**
1. Перенести новые экспортные процедуры и функции
2. Удалить устаревшие
3. Убедиться, что комментарии, количество и имена параметров совпадают с библиотечными эквивалентами
4. При необходимости вписать реализацию в новые функции
5. Актуализировать реализацию существующих функций, если изменено их назначение или состав параметров

## Сводка

| Категория объекта | Правило поставки | Может изменяться |
|-------------------|------------------|------------------|
| Непереопределяемые | Изменения не рекомендуются | Только в исключительных случаях |
| Переопределяемые | Изменения разрешены | Да, по назначению |
| Определители типов | Изменения разрешены | Да, реализация индивидуальна |

| Правило переопределяемых модулей | Описание |
|----------------------------------|----------|
| Постфикс **Переопределяемый** | Именование модулей |
| Вызов только из библиотеки | Конфигурация-потребитель не вызывает напрямую |
| Пустая реализация | Только экспортные процедуры без кода |
| Базовая реализация в библиотеке | Значения по умолчанию в непереопределяемом модуле |
