# #std748 Таймауты при работе с внешними ресурсами

> Область применения: управляемое приложение, обычное приложение.

---

## 1. Обязательность таймаутов

При работе с внешними ресурсами **следует задавать таймаут** — предельное время ожидания операции.

**Объекты, требующие таймаут:**
- `WSОпределения`
- `WSПрокси`
- `HTTPСоединение`
- `FTPСоединение`
- `ИнтернетПочтовыйПрофиль`

**Без таймаута:** программа «зависнет» или часть функционала станет недоступна.

**Защита от внешних факторов:**
- Нестабильное подключение к Интернету
- Антивирусные программы / неправильные настройки брандмауэра
- Неправильная настройка прокси-сервера
- Ненадёжная работа веб-сервера (нагрузка, некорректные скрипты)

---

## 2. Этапы выполнения операции

Время выполнения операции с внешними ресурсами складывается из:

| Этап | Описание |
|------|----------|
| DNS Lookup | Определение IP-адреса по доменному имени |
| Connect | Установка соединения с веб-сервером |
| Send | Отправка данных на веб-сервер |
| Wait | Ожидание обработки сервером |
| Receive | Получение ответа от веб-сервера |
| Cache Read | Получение данных от веб-сервера |

При таймауте 60 секунд все этапы должны уложиться в это время.

---

## 3. Рекомендации по выбору таймаута

| Тип операции | Рекомендация |
|--------------|--------------|
| Быстрые операции (проверка доступности) | Небольшой таймаут |
| Общий случай | Не более **3 минут** |
| Передача больших объёмов данных | Большой таймаут (оценка объёма), но не более **12 часов** |

---

## 4. Рекомендуемые значения таймаутов

| Операция | Таймаут (сек) |
|----------|---------------|
| Получение описания веб-сервиса | 7 |
| Проверка адреса, «быстрые» операции | 10-20 |
| Получение сведений о контрагенте, отправка SMS ¹ | 60-120 |
| Передача сообщений обмена, файлы до 1 Мб ¹ | 120-180 |
| Загрузка файлов более 1 Мб | Размер (Мб) × 128 ², иначе ≤ 43200 ³ |

> ¹ Вызывать только после контрольной операции `Ping`
>
> ² 1 Мб за 128 сек при скорости 64 кбит/с (ограничение сотовых операторов)
>
> ³ 43200 сек (12 часов) — компромисс: процесс «отвиснет» на следующее утро

---

## 5. Контрольная операция Ping

### 5.1. Для веб-сервисов с таймаутом > 20 сек

Рекомендуется:
1. Предусмотреть в веб-сервисе операцию `Ping`
2. Получить прокси с таймаутом **7 секунд** и вызвать `Ping`
3. Только после успеха — получать основной прокси

**❌ Неправильно:**

```1c
// Модуль веб-сервиса
Функция Pong(Знач Параметр)
  Возврат СтроковыеФункцииКлиентСервер.ПодставитьПараметрыВСтроку(
    НСтр("ru = 'Привет, %1'"), Параметр);
КонецФункции

// Вызывающая сторона — ждём до минуты
PingPong = Новый WSПрокси(АдресВебСервиса, , , , , 60);
Результат = PingPong.Pong(НСтр("ru = 'Мяч'"));
```

**✅ Правильно:**

```1c
// Модуль веб-сервиса
Функция Ping()
  Возврат Истина; // Проверка связи
КонецФункции

Функция Pong(Знач Параметр)
  Возврат СтроковыеФункцииКлиентСервер.ПодставитьПараметрыВСтроку(
    НСтр("ru = 'Привет, %1'"), Параметр);
КонецФункции

// Вызывающая сторона
// Сначала проверка — ждём не более 3 сек
PingPong = Новый WSПрокси(АдресВебСервиса, , , , , 3);
PingPong.Ping();

// Сервис жив — работаем с большим таймаутом
PingPong = Новый WSПрокси(АдресВебСервиса, , , , , 60);
Результат = PingPong.Pong(НСтр("ru = 'Мяч'"));
```

### 5.2. При использовании БСП

```1c
// Контрольный вызов Ping + таймаут 60 сек для операций
PingPong = ОбщегоНазначения.WSПрокси(АдресВебСервиса, ..., 60, Истина);
Результат = PingPong.Pong(НСтр("ru = 'Мяч'"));
```

### 5.3. Для других внешних ресурсов

| Тип ресурса | Аналог Ping |
|-------------|-------------|
| REST API | Тестовая команда (ответ 200 = сервис работает) |
| FTP/WebDAV | Загрузка/отправка файла-пустышки |

## 6. Асинхронные операции

Для «тяжёлых» операций, которые объективно долго выполняются на сервере (этап Wait), использовать **асинхронный режим**:

**❌ Неправильно:**

```1c
// Модуль веб-сервиса
Функция GetData()
  Результат = <очень длительные вычисления>;
  Возврат Результат;
КонецФункции

// Вызывающая сторона
Long = Новый WSПрокси(АдресВебСервиса, , , , , 600);
Результат = Long.GetData();
```

**✅ Правильно:**

```1c
// Модуль веб-сервиса
Функция StartDoLong()
  // Запуск фонового задания
  ИдентификаторОперации = ...
  Возврат ИдентификаторОперации;
КонецФункции

Функция IsReady(Знач ИдентификаторОперации)
  // Проверка завершения фонового задания
  Готовность = ...
  Возврат Готовность;
КонецФункции

Функция GetData(Знач ИдентификаторОперации)
  Результат = <получаем готовый результат>;
  Возврат Результат;
КонецФункции

// Вызывающая сторона
Long = Новый WSПрокси(АдресВебСервиса, , , , , 600);
ИдентификаторОперации = Long.StartDoLong();

Пока Не Long.IsReady(ИдентификаторОперации) Цикл
  <ждём определённый интервал>
КонецЦикла;

Результат = Long.GetData(ИдентификаторОперации);
```

> Вызывающая сторона также должна быть асинхронной: регламентное задание или обработчик ожидания на клиенте.

## Сводка

| Правило | Рекомендация |
|---------|--------------|
| Таймаут обязателен | Всегда задавать для внешних ресурсов |
| Быстрые операции | 7-20 сек |
| Стандартные операции | 60-180 сек (после Ping) |
| Большие файлы | Размер (Мб) × 128 сек |
| Максимальный таймаут | 12 часов (43200 сек) |
| Операция Ping | Предварительная проверка с коротким таймаутом |
| Долгие операции | Асинхронный режим (фоновое задание) |
