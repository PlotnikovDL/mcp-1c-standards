# #std552 Имена объектов метаданных в иерархии библиотек

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Конфликты имён в иерархии библиотек

При разработке конфигурации с использованием одной или нескольких библиотек следует **избегать конфликтов имён** объектов метаданных (справочников, документов, общих модулей и др.), поставляемых из библиотек, с объектами самой конфигурации.

### Правило разрешения конфликтов

За библиотекой более **«низкого» уровня** закрепляется преимущественное право выбора названия. Если в потребителе оказывается объект с таким же именем — следует **переименовать объект в потребителе**, используя более конкретное название.

**Пример:**
В конфигурации «Управление предприятием» есть группа команд `Настройки`, конфликтующая с одноимённой группой из библиотеки «Базовая функциональность».

**Решение:** переименовать в конфигурации-потребителе:
- `НастройкиУправленческогоУчета`
- `НастройкиРасчетаСебестоимости`

---

## 2. Предотвращение конфликтов

При разработке **независимых (одноуровневых) библиотек** конфликты могут быть выявлены поздно — при внедрении в конфигурацию-потребитель.

**Правило:** всегда **предметно называть** объекты метаданных. Название должно кратко описывать сущность объекта и **не должно** быть слишком «универсальным».

### 2.1. Универсальные названия — в библиотеках нижнего уровня

Наиболее «универсальные» названия следует использовать **только в библиотеках самого нижнего уровня иерархии**.

**Примеры:**
- `ОбщегоНазначения`
- `СтроковыеФункции`
- `РаботаСФормами`

### 2.2. Специфичные названия — в конфигурациях и библиотеках высокого уровня

В конечных конфигурациях-потребителях и в библиотеках более высокого уровня использовать **более специфичные** для прикладной области названия.

**Примеры:**
- `ТорговыйУчет`
- `ЗарплатаКадры`
- `ПроведениеСкладскихДокументов`

### 2.3. Уточняющие постфиксы

Функционал, который расширяет аналогичный функционал библиотеки более низкого уровня или конфликтует с «соседней» одноуровневой библиотекой, рекомендуется именовать с добавлением **уточняющих постфиксов** (имя библиотеки или конфигурации).

**Примеры:**

| Объект | Постфикс | Описание |
|--------|----------|----------|
| `ОбновлениеИнформационнойБазыМФ` | **МФ** | Функции обновления ИБ для конфигурации «Мои финансы» |
| `СтроковыеФункцииРегл` | **Регл** | Функции для библиотеки регламентированного учёта |
| `РаботаСФормамиЗарплатаКадры` | **ЗарплатаКадры** | Функции для библиотеки зарплатно-кадровой функциональности |
| `УстановитьПометкуУдаленияПрисоединенныхФайловЗарплатаКадры` | **ЗарплатаКадры** | Подписка на событие в библиотеке ЗК |

---

## Сводка

| Уровень | Правило именования | Примеры |
|---------|-------------------|---------|
| Библиотека нижнего уровня | Универсальные названия | `ОбщегоНазначения`, `СтроковыеФункции` |
| Библиотека высокого уровня | Специфичные названия + постфикс | `СтроковыеФункцииРегл` |
| Конфигурация-потребитель | Предметные названия + постфикс | `ОбновлениеИнформационнойБазыМФ` |

| При конфликте | Действие |
|---------------|----------|
| С библиотекой нижнего уровня | Переименовать объект в потребителе |
| С одноуровневой библиотекой | Добавить уточняющий постфикс |
