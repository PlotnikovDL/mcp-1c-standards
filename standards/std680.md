# #std680 Поддержка толстого клиента, управляемое приложение, клиент-сервер

> Область применения: управляемое приложение, обычное приложение.

---

## 1. Проблема

В управляемом режиме из-за ограничений тонкого клиента может потребоваться поддержка **толстого клиента** (в режиме управляемого приложения).

---

## 2. Компиляция модулей на клиенте

### 2.1. Ожидаемое поведение

В клиент-серверной архитектуре следующие модули **должны** компилироваться и выполняться **только на сервере**:

- Модуль менеджера
- Модуль объекта
- Модуль сеанса

### 2.2. Проблемные ситуации в толстом клиенте

В толстом клиенте (управляемое приложение, клиент-сервер) указанные модули могут **начать компилироваться на клиенте**:

| Ситуация | Причина |
|----------|---------|
| Явное создание объекта в клиентском коде | `Справочники.Контрагенты.СоздатьЭлемент()` на клиенте |
| Неявное обращение платформы | Вызов обработчиков событий модулей менеджеров на клиенте |

Это приводит к ошибкам компиляции и выполнения.

---

## 3. Решение — инструкции препроцессора

### 3.1. Модуль объекта (набора записей и т.п.)

Полностью исключить из клиентского контекста + добавить исключение:

```1c
#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда

  // Весь код модуля объекта

#Иначе
  ВызватьИсключение НСтр("ru = 'Недопустимый вызов объекта на клиенте.'");
#КонецЕсли
```

### 3.2. Модуль сеанса

Полностью исключить из клиентского контекста (параметры сеанса нужны только серверному коду):

```1c
#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда

  // Весь код модуля сеанса

#КонецЕсли
```

### 3.3. Модуль менеджера

Полностью исключить из клиентского контекста:

```1c
#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда

  // Весь код модуля менеджера

#КонецЕсли
```

---

## 4. Ограничения

При использовании инструкций препроцессора для модуля менеджера:

| Обработчик | Поведение в толстом клиенте |
|------------|----------------------------|
| `ОбработкаПолученияПредставления` | Представление формируется по умолчанию (без вызова обработчика) |
| `ОбработкаПолученияПолейПредставления` | Представление формируется по умолчанию |
| `ОбработкаПолученияДанныхВыбора` | Всегда вызывается на сервере — ограничение не распространяется |
| `ОбработкаПолученияФормы` | Всегда вызывается на сервере — ограничение не распространяется |

---

## 5. Снятие ограничения (рекомендация)

Если требуется работа обработчиков `ОбработкаПолученияПредставления` и `ОбработкаПолученияПолейПредставления` на клиенте:

### 5.1. Вынос кода за инструкции препроцессора

Код обработчиков разместить **за пределами** инструкций `#Если ... #КонецЕсли`.

### 5.2. Переход на сервер

При вызове серверных процедур использовать модули с признаком **Вызов сервера**.

**Неправильно** — вызов серверного модуля:

```1c
Процедура ОбработкаПолученияПредставления(Данные, Представление, СтандартнаяОбработка)

  Взаимодействия.ОбработкаПолученияПредставления(Данные, Представление);
  СтандартнаяОбработка = Ложь;

КонецПроцедуры
```

**Правильно** — вызов модуля с признаком ВызовСервера:

```1c
Процедура ОбработкаПолученияПредставления(Данные, Представление, СтандартнаяОбработка)

  ВзаимодействияВызовСервера.ОбработкаПолученияПредставления(Данные, Представление);
  СтандартнаяОбработка = Ложь;

КонецПроцедуры
```

⚠️ **Важно:** Не следует принудительно устанавливать флажок «Вызов сервера» всем серверным модулям.

---

## 6. Краткий чек-лист

- [ ] Модуль объекта обёрнут в `#Если Сервер ...` с исключением в `#Иначе`
- [ ] Модуль сеанса обёрнут в `#Если Сервер ...`
- [ ] Модуль менеджера обёрнут в `#Если Сервер ...`
- [ ] Мутабельные типы не передаются через границу клиент-сервер
