# #std463 Обработчик события ОбработкаПроверкиЗаполнения

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Назначение обработчика

### 1.1. Основная задача

В обработчике `ОбработкаПроверкиЗаполнения` модуля объекта выполняются действия по **проверке правильности заполнения** значений реквизитов объектов (измерений, ресурсов, реквизитов табличных частей и т.п.).

### 1.2. Когда использовать

Обработчик следует использовать когда:
- Обычной проверки на заполненность **недостаточно** (значение реквизита логически связано с другим)
- Требование к заполнению **не является безусловным**

---

## 2. Условная проверка заполнения

### 2.1. Схема проверки

При условной проверке (зависящей от других реквизитов или функциональных опций):

1. Создать массив `НепроверяемыеРеквизиты`
2. Добавлять в него имена непроверяемых реквизитов
3. Вызвать процедуру `УдалитьНепроверяемыеРеквизитыИзМассива`

### 2.2. Правильный пример

```1c
Процедура ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)

    НепроверяемыеРеквизиты = Новый Массив();

    // Проверка значения реквизита на соответствие требованиям
    Если НЕ ИННСоответствуетТребованиям(ИНН) Тогда
        Сообщение = Новый СообщениеПользователю();
        Сообщение.Текст = НСтр("ru = 'ИНН задан неверно.'");
        Сообщение.Поле = "ИНН";
        Сообщение.УстановитьДанные(ЭтотОбъект);
        Сообщение.Сообщить();
        Отказ = Истина;
        НепроверяемыеРеквизиты.Добавить("ИНН");
    КонецЕсли;

    // Условная проверка: реквизит не должен быть пустым в зависимости от другого
    Если ЮрФизЛицо <> Перечисления.ЮрФизЛицо.ФизЛицо Тогда
        НепроверяемыеРеквизиты.Добавить("ИндивидуальныйПредприниматель");
    КонецЕсли;

    УдалитьНепроверяемыеРеквизитыИзМассива(ПроверяемыеРеквизиты, НепроверяемыеРеквизиты);

КонецПроцедуры
```

### 2.3. Вспомогательная процедура

```1c
Процедура УдалитьНепроверяемыеРеквизитыИзМассива(МассивРеквизитов, МассивНепроверяемыхРеквизитов) Экспорт

    Для Каждого ЭлементМассива Из МассивНепроверяемыхРеквизитов Цикл

        // Проверить, что реквизит есть в массиве (не был удалён ранее)
        ПорядковыйНомер = МассивРеквизитов.Найти(ЭлементМассива);
        Если ПорядковыйНомер <> Неопределено Тогда
            МассивРеквизитов.Удалить(ПорядковыйНомер);
        КонецЕсли;

    КонецЦикла;

КонецПроцедуры
```

### 2.4. Неправильный пример

⛔ Не следует **добавлять** реквизиты в массив проверяемых:

```1c
// ⛔ Неправильно
Если ЮрФизЛицо = Перечисления.ЮрФизЛицо.ФизЛицо Тогда
    ПроверяемыеРеквизиты.Добавить("ИндивидуальныйПредприниматель");
КонецЕсли;
```

**Причина:** Такой подход скрывает условную проверку из свойства «Проверка заполнения» и затрудняет анализ логики.

## 3. Особенности вызова

### 3.1. Когда НЕ вызывается

⚠️ Обработчик `ОбработкаПроверкиЗаполнения` **не вызывается** при программной записи объекта.

### 3.2. БСП: отложенное проведение

> *Методическая рекомендация*

При использовании подсистемы «Обмен данными» БСП обработчик вызывается при проведении документов после загрузки из сообщения обмена.

Для отключения некоторых проверок в этом режиме:

```1c
Если ДополнительныеСвойства.Свойство("ОтложенноеПроведение") Тогда
    // Отключить определённые проверки
КонецЕсли;
```

## 4. Проверки в и вне транзакции

### 4.1. Внетранзакционные проверки

Проверки в `ОбработкаПроверкиЗаполнения` выполняются **вне транзакции** записи объекта.

✅ **Преимущество:** Операция прерывается **до записи** в БД — это наиболее эффективно.

⚠️ **Учитывать:** Новое состояние объекта ещё не записано. При необходимости запроса к данным — использовать временные таблицы.

### 4.2. Транзакционные проверки

Для проверок **целостности данных** использовать обработчики внутри транзакции:

| Обработчик | Когда использовать |
|------------|-------------------|
| `ПередЗаписью` | Проверки до записи в БД |
| `ПриЗаписи` | Проверки после записи |
| `ОбработкаПроведения` | Проверки движений документа |

### 4.3. Правила транзакционных проверок

**Проверка остатков (оперативный учёт):**
- Имеет смысл только если **все** документы, изменяющие ресурс, выполняют такую проверку
- Исключение: документы, вводимые крайне редко (например, «Инвентаризация товаров»)

**Взаимосвязанные объекты:**
- Если при записи `Подразделения` проверяется должность руководителя, то при записи `Сотрудника` должна быть **встречная** проверка
- Проверка выполняется **в транзакции обоих объектов** или **вне транзакции обоих**
