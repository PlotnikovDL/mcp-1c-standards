# #std690 Обработчики обновления информационной базы

> Область применения: управляемое приложение, обычное приложение.

> Действует для конфигураций на базе **Библиотеки стандартных подсистем**.
> Содержит уточнения к требованиям других стандартов.
> См. документацию к подсистеме «Обновление версии ИБ» на ИТС.

---

## Содержание

1. Основные сведения о библиотеке (основной конфигурации)
2. Расположение обработчиков обновления
3. Реализация обработчиков обновления
4. Переход на новые версии библиотек

## 1. Основные сведения о библиотеке

### 1.1. Обязательные сведения

Каждая библиотека должна сообщить о себе:

| Сведение | Описание |
|----------|----------|
| Имя | Идентификатор библиотеки |
| Версия | Номер версии в формате Р.П.В.С |
| Список обработчиков обновления | Процедуры обновления данных |
| Зависимости от других библиотек | Порядок выполнения обработчиков |

Эти сведения размещаются в общем модуле с именем **ОбновлениеИнформационнойБазы…**

**Пример:** `ОбновлениеИнформационнойБазыУТ`

### Регистрация модулей библиотек

В модуле **ПодсистемыКонфигурацииПереопределяемый**:

```1c
Процедура ПриДобавленииПодсистем(МодулиПодсистем) Экспорт

  МодулиПодсистем.Добавить("ОбновлениеИнформационнойБазыУТ");

КонецПроцедуры
```

### Шаблон модуля обновления

```1c
////////////////////////////////////////////////////////////////////////////////
// Обновление информационной базы <библиотеки или конфигурации>.
//
/////////////////////////////////////////////////////////////////////////////

#Область ПрограммныйИнтерфейс

////////////////////////////////////////////////////////////////////////////////
// Получение сведений о библиотеке (или конфигурации).

// Заполняет основные сведения о библиотеке или основной конфигурации.
// Библиотека, имя которой имя совпадает с именем конфигурации в метаданных, определяется как основная конфигурация.
//
// Параметры:
//  Описание - Структура - сведения о библиотеке:
//
//   Имя                 - Строка - имя библиотеки, например, "СтандартныеПодсистемы".
//   Версия              - Строка - версия в формате из 4-х цифр, например, "2.1.3.1".
//
//   ТребуемыеПодсистемы - Массив - имена других библиотек (Строка), от которых зависит данная библиотека.
//   РежимВыполненияОтложенныхОбработчиков - Строка - "Последовательно" или "Параллельно".
//
Процедура ПриДобавленииПодсистемы(Описание) Экспорт

  Описание.Имя    = "<Имя библиотеки>";
  Описание.Версия = "XX.XX.XX.XX";
  Описание.ТребуемыеПодсистемы.Добавить("СтандартныеПодсистемы");
  Описание.РежимВыполненияОтложенныхОбработчиков = "Последовательно";

КонецПроцедуры

////////////////////////////////////////////////////////////////////////////////
// Обработчики обновления информационной базы.

// Добавляет в список процедуры-обработчики обновления данных ИБ
// для всех поддерживаемых версий библиотеки или конфигурации.
//
// Параметры:
//  Обработчики - ТаблицаЗначений - см. ОбновлениеИнформационнойБазы.НоваяТаблицаОбработчиковОбновления
//
Процедура ПриДобавленииОбработчиковОбновления(Обработчики) Экспорт

  // Обработчики, выполняемые при каждом обновлении ИБ

  // Обработчики, выполняемые при переходе на определенную версию

  // Обработчики, выполняемые при заполнении пустой ИБ

КонецПроцедуры

// Вызывается перед процедурами-обработчиками обновления данных ИБ.
//
Процедура ПередОбновлениемИнформационнойБазы() Экспорт

КонецПроцедуры

// Вызывается после завершения обновления данных ИБ.
//
Процедура ПослеОбновленияИнформационнойБазы(Знач ПредыдущаяВерсия, Знач ТекущаяВерсия,
  Знач ВыполненныеОбработчики, ВыводитьОписаниеОбновлений, МонопольныйРежим) Экспорт

КонецПроцедуры

// Вызывается при подготовке табличного документа с описанием изменений в программе.
//
Процедура ПриПодготовкеМакетаОписанияОбновлений(Знач Макет) Экспорт

КонецПроцедуры

// Позволяет переопределить режим обновления данных информационной базы.
//
Процедура ПриОпределенииРежимаОбновленияДанных(РежимОбновленияДанных, СтандартнаяОбработка) Экспорт

КонецПроцедуры

// Добавляет в список процедуры-обработчики перехода с другой программы.
//
Процедура ПриДобавленииОбработчиковПереходаСДругойПрограммы(Обработчики) Экспорт

КонецПроцедуры

// Вызывается после выполнения всех процедур-обработчиков перехода с другой программы.
//
Процедура ПриЗавершенииПереходаСДругойПрограммы(Знач ПредыдущееИмяКонфигурации,
  Знач ПредыдущаяВерсияКонфигурации, Параметры) Экспорт

КонецПроцедуры

#КонецОбласти

#Область СлужебныеПроцедурыИФункции

////////////////////////////////////////////////////////////////////////////////
// Заполнение пустой ИБ

////////////////////////////////////////////////////////////////////////////////
// Обновление ИБ

#КонецОбласти
```

### 1.2. Назначение обработчиков обновления

Обработчики предназначены для дополнительной обработки данных после реструктуризации:

- Инициализация новых констант, реквизитов, предопределённых элементов
- Перенос данных из устаревших структур в новые
- Генерация новых данных

> См. также: Автогенерированные данные в информационной базе: требования по локализации (#std784)

### 1.3. Структура обработчика

Обработчик состоит из двух частей:

| Часть | Описание |
|-------|----------|
| Описательная | Когда выполняется и где находится |
| Программная | Код модификации данных ИБ |

### Добавление описания обработчика

```1c
Обработчик = Обработчики.Добавить();
Обработчик.Версия = "<номер версии>";
Обработчик.Процедура = "<полное имя экспортной процедуры>";
Обработчик.НачальноеЗаполнение = {Истина|Ложь};
Обработчик.РежимВыполнения = {"Монопольно"|"Оперативно"|"Отложенно"};
```

### Поля описания обработчика

**Версия** (Строка):
- Формат «Р.П.В.С» (редакция.подредакция.версия.сборка)
- `*` — выполнять при каждом обновлении (системные данные)
- Не задано — должно быть установлено `НачальноеЗаполнение = Истина`

**Процедура** (Строка):
- Полный путь к процедуре-обработчику
- Пример: `"Справочник.Валюты.ЗаполнитьКодДляПоиска"`

**НачальноеЗаполнение** (Булево):
- `Истина` — вызывается при первом запуске пустой ИБ (версия «0.0.0.0»)

**РежимВыполнения** (Строка):

| Режим | Описание | Применение |
|-------|----------|------------|
| **Монопольно** | При отсутствии активных сеансов | Небольшой объём данных текущего периода |
| **Оперативно** | При активных сеансах | Исправительные релизы без изменений структуры |
| **Отложенно** | В фоне после монопольных обработчиков | Архивы данных, неактивные позиции |

### Пример описания обработчика

```1c
Обработчик = Обработчики.Добавить();
Обработчик.РежимВыполнения = "Монопольно";
Обработчик.Версия = "11.1.0.0";
Обработчик.Процедура = "Справочник.МойСправочник.ЗаполнитьКодДляПоиска";
```

### Пример реализации в модуле менеджера

```1c
// Обработчик обновления УТ 11.1.0.0
//
// Перебираются все элементы справочника, в которых не заполнен код для поиска,
// и заполняется кодом справочника без лидирующих нулей и префиксов
//
Процедура ЗаполнитьКодДляПоиска() Экспорт
...
```

## 2. Расположение обработчиков обновления

### 2.1. Основное правило

Процедура-обработчик должна быть **экспортной** и располагаться в **модуле менеджера** того объекта, обновление которого она выполняет.

**Пример:** добавили новый реквизит в справочник «Подразделения» → процедура в модуле менеджера этого справочника.

### 2.2. Альтернативное размещение

Когда невозможно соотнести обработчик с конкретным объектом — размещать в **серверном общем модуле**, связанном по смыслу с выполняемой обработкой.

**Пример:** процедуры складской функциональности → модуль `СкладСервер`

Процедура должна располагаться в **служебной части** модуля, в подразделе **«Обновление ИБ»**.

## 3. Реализация обработчиков обновления

### 3.1. Требования к обработчику

| Требование | Описание |
|------------|----------|
| Без интерактивного взаимодействия | Не должен содержать логики взаимодействия с пользователем |
| Устойчивость | Не прерывать, не зацикливать, не оставлять необработанные данные |
| Идемпотентность | На одних данных результат идентичен при любом количестве вызовов |
| Независимость в пределах версии | Не зависеть от очередности выполнения |
| Учёт РИБ с отборами | Пропускать обновление неполных данных в подчинённом узле |

**Обработка ошибок:**
- Неуникальный номер документа → присвоить новый незанятый
- Битая ссылка → пропустить или использовать значение по умолчанию
- В параллельных отложенных обработчиках — не вызывать исключение

### 3.2. Оптимизация производительности

#### 3.2.1. Отключение бизнес-логики

```1c
ДокументОбъект.ОбменДанными.Загрузка = Истина;
```

Для частичного отключения:

```1c
ДокументОбъект.ДополнительныеСвойства.Вставить("ОтключитьМоюБизнесЛогику");
```

#### 3.2.2. Отключение регистрации на узлах обмена

- В РИБ обработка выполняется независимо в каждом узле
- При обмене между конфигурациями обработка не должна приводить к выгрузке

**Исключение:** создание ссылочных объектов для переноса в другие узлы РИБ с тем же значением Ссылка.

#### 3.2.3. Правильная запись данных

❌ Неправильно:
```1c
ДокументОбъект.Записать();
```

✅ Правильно:
```1c
ДокументОбъект.ОбменДанными.Загрузка = Истина; // отключить бизнес-логику
ДокументОбъект.ДополнительныеСвойства.Вставить("ОтключитьМеханизмРегистрацииОбъектов");
ДокументОбъект.ОбменДанными.Получатели.АвтоЗаполнение = Ложь;
ДокументОбъект.Записать();
```

✅ При использовании БСП 2.1.4+:
```1c
ОбновлениеИнформационнойБазы.ЗаписатьДанные(ДокументОбъект);
```

### 3.3. Комментарий к обработчику

Первая строка — версия конфигурации. Далее — ответы на вопросы:
- Какие данные будут изменены?
- Какие изменения будут внесены?

```1c
// Обработчик обновления УТ 11.1.0.0
//
// Перебираются все элементы справочника, в которых не заполнен код для поиска,
// и заполняется кодом справочника без лидирующих нулей и префиксов
//
Процедура ЗаполнитьКодДляПоиска() Экспорт
```

## 4. Переход на новые версии библиотек

### 4.1. Увеличение версии конфигурации

При постановке конфигурации на поддержку к новой версии библиотеки следует **увеличивать номер версии конфигурации**.

Это необходимо для запуска обработчиков обновления информационной базы.

## Сводка

| Режим выполнения | Когда используется | Условия |
|------------------|-------------------|---------|
| Монопольно | Небольшой объём текущих данных | Отсутствие активных сеансов |
| Оперативно | Исправительные релизы | Активные сеансы разрешены |
| Отложенно | Архивы, неактивные данные | В фоне после входа пользователей |

| Правило | Описание |
|---------|----------|
| Размещение | В модуле менеджера обновляемого объекта |
| Бизнес-логика | Отключать через `ОбменДанными.Загрузка = Истина` |
| Регистрация обмена | Отключать `Получатели.АвтоЗаполнение = Ложь` |
| Идемпотентность | Повторный запуск даёт тот же результат |
| Комментарий | Версия + что и как меняем |
