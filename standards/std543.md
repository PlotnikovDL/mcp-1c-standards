# #std543 Использование подсистем

> Область применения: управляемое приложение, обычное приложение.
> *Методическая рекомендация*

---

## 1. Назначение подсистем

Подсистемы решают **две задачи**:

| Задача | Описание |
|--------|----------|
| **Командный интерфейс** | Формирование глобального интерфейса основного окна для пользователя |
| **Группировка метаданных** | Объединение объектов по функциональному признаку для разработки |

---

## 2. Два типа подсистем

| Тип | Флажок "Включать в командный интерфейс" | Назначение |
|-----|----------------------------------------|------------|
| **Интерфейсные** | ✅ Установлен | Разделы для пользователей (Закупки, Продажи, НСИ и администрирование...) |
| **Функциональные** | ❌ Снят | Логическое объединение объектов для разработки |

---

## 3. Правила использования

### 3.1. Объекты в нескольких подсистемах

Один объект метаданных может входить в **несколько интерфейсных** подсистем.

**Пример:** Справочник `Номенклатура` может быть включён:
- В раздел «НСИ» — как справочник для администратора
- В раздел «Маркетинг» — для работы с товарами

### 3.2. Объекты без визуального представления

**Объекты без визуального представления** следует включать только в **функциональные** подсистемы:

| Тип объекта | Включать в |
|-------------|------------|
| Общие модули | Функциональные подсистемы |
| Регламентные задания | Функциональные подсистемы |
| Константы | Функциональные подсистемы |
| Подписки на события | Функциональные подсистемы |
| Параметры сеанса | Функциональные подсистемы |

**Причина:** Эти объекты не отображаются в командном интерфейсе пользователя, поэтому включение их в интерфейсные подсистемы не имеет смысла.

---

## 4. Рекомендации по структуре

### 4.1. Интерфейсные подсистемы

- Создавать по **функциональным областям** бизнеса (Продажи, Закупки, Склад, Финансы...)
- Названия должны быть **понятны пользователю**
- Группировать объекты по **частоте использования** и **смыслу**

### 4.2. Функциональные подсистемы

- Создавать для **группировки связанных объектов**
- Названия — для разработчиков (могут быть техническими)
- Упрощают навигацию в конфигураторе
- Позволяют логически разделить конфигурацию на части
