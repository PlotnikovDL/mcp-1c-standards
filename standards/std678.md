# #std678 Безопасность прикладного программного интерфейса сервера

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## Введение

При работе в режиме управляемого приложения клиент (тонкий или веб-клиент) обращается к серверу 1С:Предприятия через **открытый HTTP-протокол**. Сервер может быть вызван извне сторонними программами тем же способом, что и клиентское приложение.

**Угрозы:**
- Несанкционированный доступ к пользовательским данным
- Нарушение работоспособности сервера

---

## 1. Несанкционированный вызов серверного кода с клиента

### 1.1. Прикладной программный интерфейс сервера

Потенциальную угрозу представляют все серверные процедуры и функции, доступные для вызова с клиента:

| Источник | Описание угрозы |
|----------|-----------------|
| Общие модули с признаками **"Сервер"** и **"Вызов сервера"** | Вызов экспортных процедур возможен напрямую с клиента |
| Модули форм с `&НаСервере`, `&НаСервереБезКонтекста` | Вызов возможен после получения формы, даже если процедуры не экспортные |

### Пример уязвимости в модуле формы

**Код формы `Справочник.Сотрудники.ФормаЭлемента`:**

```1c
&НаКлиенте
Процедура УволитьСотрудника(Команда)
  Если ДатаРегистрацииУвольнения > ДатаЗапрета Тогда
    ЗарегистрироватьУвольнение();
  КонецЕсли;
КонецПроцедуры

&НаСервере
Процедура ЗарегистрироватьУвольнение()
  ...
КонецПроцедуры
```

**Вредоносный код для обхода проверки:**

```1c
ПараметрыФормы = Новый Структура("Ключ", ВыбранныйСотрудник);
Форма = ПолучитьФорму("Справочник.Сотрудники.ФормаЭлемента", ПараметрыФормы);
Форма.ЗарегистрироватьУвольнение(); // Вызов напрямую, минуя проверку!
```

### 1.2. Рекомендация

**Не рекомендуется** размещать в серверных процедурах модулей форм код бизнес-логики, не относящийся к клиент-серверному взаимодействию и обработке реквизитов формы.

### 1.3. Особое внимание

Серверные процедуры и функции, использующие:
- `УстановитьПривилегированныйРежим(Истина)`
- Размещённые в модулях с признаком **Привилегированный**

---

## 2. Проникновение небезопасного кода на сервер

Любые возможности выполнения **"внешнего" кода** или произвольных текстов запросов на сервере представляют **серьёзную опасность**.

### Опасные элементы

| Элемент | Угроза |
|---------|--------|
| Внешние отчёты и обработки | Обращение к общим модулям без "Вызов сервера", модулям объектов, переход в привилегированный режим |
| COM-объекты | Выполнение произвольного кода |
| Внешние компоненты | Выполнение произвольного кода |
| Произвольные тексты запросов | SQL-инъекции, доступ к данным |

### Последствия

- Порча или похищение данных
- Зависание или остановка рабочего процесса
- Зацикливание
- Утечки памяти
- Ресурсоёмкие операции и запросы

---

## 3. Безопасность данных на клиенте

Клиентское приложение (тонкий клиент или веб-браузер) **не гарантирует** безопасность данных, переданных на сторону клиента.

**Угроза:** данные могут быть перехвачены и прочитаны вредоносным ПО на клиентском компьютере.

### Рекомендация

Серверные процедуры должны возвращать в форму только **окончательный результат** расчёта.

**Избегать** передачи на клиент:
- Исходных данных
- Промежуточных данных
- Информации, раскрывающей приватные детали бизнес-процесса

---

## Сводка

| Угроза | Защита |
|--------|--------|
| Прямой вызов серверных процедур форм | Не размещать бизнес-логику в модулях форм |
| Обход клиентских проверок | Дублировать проверки на сервере |
| Привилегированный код | Минимизировать, тщательно проверять |
| Внешние обработки | Ограничить через профили безопасности |
| Утечка данных на клиенте | Возвращать только итоговый результат |
