# #std551 Разработка конфигураций с повторным использованием общего кода и объектов метаданных

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

> *Методическая рекомендация (полезный совет)*

---

## 1. Библиотечный подход

При разработке нескольких конфигураций (линейки продуктов) задачу повторного использования общего кода и объектов рекомендуется решать с использованием **библиотек**.

**Библиотечная конфигурация (библиотека)** — конфигурация, которая:
- Не предназначена для использования конечными пользователями
- Служит только для поддержки конфигураций, пользующихся её функциональностью
- Содержит функциональность, общую для прикладных решений

### Преимущества библиотечного подхода

| Преимущество | Описание |
|--------------|----------|
| Централизованная разработка | Общая функциональность разрабатывается в одном месте, а не в каждом решении |
| Версионирование | Выпуск версий в виде дистрибутива или файла поставки |
| Повторное использование | Код и объекты используются через механизм постановки на поддержку |
| Унификация | Конфигурации имеют общий набор объектов метаданных и подсистем |

---

## 2. Иерархия библиотек

Библиотека может стоять на поддержке у другой библиотеки, образуя **иерархию библиотек**.

| Термин | Описание |
|--------|----------|
| **Библиотека-родитель** | Библиотека, от которой зависит другая библиотека |
| **Библиотека-наследник** | Библиотека, стоящая на поддержке у библиотеки-родителя |

Библиотеки не являются самостоятельным предметом разработки — они предназначены для создания прикладных решений. **Прикладные решения** являются конечными конфигурациями-потребителями в иерархии библиотек.

---

## 3. Области видимости программного кода

При взаимодействии конфигураций, библиотек и внешних потребителей выделяются следующие области видимости:

### 3.1. Программный интерфейс

Экспортные процедуры и функции, предназначенные для использования **сторонними потребителями**.

**а) Для любых внешних потребителей:**
- Вызов из произвольного места в коде конфигурации
- Потребители: расширения конфигурации, сторонние доработки, другие программы

**б) Для конкретных потребителей:**
- Располагается в определённом месте, указанном в документации
- Может быть вызван только определённым потребителем
- Размещается в подразделе **«Для вызова из других подсистем»**

### 3.2. Служебный программный интерфейс

Экспортные процедуры и функции, которые допустимо вызывать **только из других функциональных подсистем этой же библиотеки (конфигурации)**.

### 3.3. Служебные процедуры и функции

Внутренняя реализация функциональной подсистемы. Экспортные процедуры и функции этого раздела предназначены **только для вызова из других объектов этой же подсистемы**.

---

## Сводка

| Область видимости | Кто может вызывать |
|-------------------|-------------------|
| Программный интерфейс (общий) | Любые внешние потребители |
| Программный интерфейс (для подсистем) | Определённые подсистемы библиотеки |
| Служебный программный интерфейс | Другие подсистемы этой же библиотеки |
| Служебные процедуры и функции | Только объекты этой же подсистемы |
