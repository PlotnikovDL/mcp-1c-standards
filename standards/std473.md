# #std473 Использование кодов (номеров) объектов конфигурации

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

> *Методическая рекомендация (полезный совет)*

---

## 1. Когда применять коды (номера)

Необходимость применения кодов (номеров) определяется из **прикладного смысла**.

### 1.1. Большое количество элементов

Пользователям предстоит работать со списками, содержащими большое количество элементов.

**Пример:** справочник `Номенклатура`

### 1.2. Удобство поиска по коду

Искать данные по коду (номеру) удобнее, чем по другим свойствам.

**Пример:** справочник `СтатьиРасходов` — пользователю проще запомнить код, чем каждый раз вчитываться в название статьи. Кроме того, названия статей могут меняться.

### 1.3. Прикладной смысл кода

Код имеет прикладной смысл, продиктованный спецификой автоматизируемой области.

**Примеры:**
| Справочник | Смысл кода |
|------------|------------|
| ЕдиницыИзмерения | Код единицы измерения в ОКЕИ |
| НомераГТД | Номер грузовой таможенной декларации |

---

## 2. Когда НЕ применять автонумерацию

### 2.1. Код как краткое представление

Код используется как **краткое представление** элемента данных в виде строки.

**Пример:** справочник `Пользователи` — в коде хранится краткое имя пользователя (логин).

### 2.2. Код из внешних источников

Код (номер) получается из **внешних источников** (входящие данные).

**Примеры:**
- Все классификаторы
- Справочник `НомераГТД` — код вводится из данных входящих документов

---

## 3. Длина кода (номера)

Длина устанавливается в зависимости от **прикладного назначения** и **метода получения** (ввода).

### 3.1. Объекты с автонумерацией

Длина выбирается исходя из:
- Потенциального количества всех объектов в базе данных
- Объектов, относящихся к определённому периоду (документы, бизнес-процессы)
- Объектов, относящихся к определённому владельцу (иерархические и подчинённые справочники, задачи)

⚠️ В длине номера необходимо учитывать **длину префиксов нумерации**:
- Префикс информационной базы
- Префикс организации
- Другие префиксы, предусмотренные конфигурацией

### 3.2. Рекомендуемые длины

**Для типовых конфигураций:**

| Длина | Применение |
|-------|------------|
| 3 | Небольшие справочники |
| 5 | Средние справочники |
| 9 | Документы, большие справочники |
| 11 | С учётом префиксов |

**При использовании БСП (подсистема «Префиксация объектов»):**

Совокупную длину номеров документов и кодов справочников рекомендуется устанавливать **не менее 11 символов**: 11, 13, 15, …

### 3.3. Код как краткое представление

Длина устанавливается достаточной для хранения краткого строкового представления объектов исходя из **прикладного смысла** кода.

### 3.4. Код из внешних источников

Длина зависит от **источника**.

### 3.5. Переменная длина

✅ Рекомендуется устанавливать допустимую длину кода (номера) **переменной**.

---

## 4. Префиксация для распределённых систем

Если прикладное решение рассчитано на работу с данными, которые могут вводиться **параллельно из нескольких мест** (РИБ, другие программы), должна быть реализована **автоматическая префиксация** для объектов, у которых:

- Используется строковый код (номер)
- Используется автонумерация
- Данные могут вводиться параллельно и впоследствии консолидироваться

**При использовании БСП:** подсистема **«Префиксация объектов»**

---

## 5. Сводная таблица

| Ситуация | Автонумерация | Рекомендуемая длина |
|----------|---------------|---------------------|
| Большой справочник | Да | 9-11 |
| Документы | Да | 9-11 (с учётом префиксов) |
| Код = логин/имя | Нет | По смыслу |
| Код из классификатора | Нет | По источнику |
| С БСП префиксацией | Да | ≥ 11 |
