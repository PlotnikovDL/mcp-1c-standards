# #std644 Обеспечение совместимости библиотек

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Обратная совместимость версий

При разработке библиотек необходимо обеспечивать обратную совместимость между различными версиями библиотек **в пределах одной [подредакции](#std483)** библиотеки.

**Пример:** версии 2.0.1, 2.0.2 и 2.0.5 должны быть совместимы. Однако допустимо, если следующая подредакция 2.1 будет содержать существенные изменения, нарушающие это правило.

### Преимущества совместимости

| Преимущество | Описание |
|--------------|----------|
| Минимизация затрат на обновление | Не требуется многократно пересматривать код и адаптировать объекты |
| Уверенное использование API | Прикладное решение может использовать старые возможности, не «торопясь» переходить на новые |
| Совместная разработка библиотек | Можно вести разработку «соседних» библиотек на разных версиях базовой библиотеки |

### 1.1. Структура номера версии

| Что изменилось | РР | .ПП | .ВВ | .СС |
|----------------|:--:|:---:|:---:|:---:|
| Архитектурные изменения, нарушена совместимость (есть инструкция по переходу) | ✅ | ✅ | ❌ | ❌ |
| Новые функции | ✅ | ✅ | ✅ | ❌ |
| Исправлены ошибки | ✅ | ✅ | ✅ | ✅ |

**Расшифровка:**

| Цифра | Название | Описание |
|-------|----------|----------|
| **РР** | Редакция | Существенно нарушена совместимость (серьёзные архитектурные или «знаковые» изменения) |
| **ПП** | Подредакция | Нарушена совместимость (требуется отработать инструкцию по переходу), удалены устаревшие объекты |
| **ВВ** | Версия | Только новые функции (возможна «механическая» автозаливка, инструкция необязательна) |
| **СС** | Сборка | Только исправление ошибок (возможна «механическая» автозаливка) |

### Исключения

| Ситуация | Описание |
|----------|----------|
| Отработка изменений законодательства | Исправительные сборки для всех веток на поддержке, даже если нарушают совместимость |
| LTS-версии | Включаются важные доработки, даже если нарушают совместимость |

**Удаление устаревших объектов:**
- Не чаще раза в год
- В версиях, запланированных к выпуску ближе к концу года
- Удаляемые объекты должны существовать не менее двух лет
- Указывать в документации, что версия обязательна для перехода

### 1.2–1.4. Правила нарушения совместимости

- Нарушение совместимости хотя бы в одной подсистеме → увеличение номера подредакции (2-я цифра)
- При незапланированном нарушении в 3-й или 4-й цифре → отозвать релиз, устранить, выпустить новый
- Незапланированное добавление новых функций в 4-й цифре → также отозвать релиз

### 1.5. Обеспечение совместимости

Для обеспечения совместимости следует:
- **Выделить программный интерфейс** библиотеки, скрыв от потребителей все остальные детали реализации
- **Не изменять** программный интерфейс и поведение — его допустимо только **расширять**

⚠️ Требования обратной совместимости имеют **приоритет** над стандартами:
- Имя, синоним, комментарий (#std474)
- Названия процедур и функций (#std647)

### 1.6. Состав программного интерфейса

К программному интерфейсу библиотеки относятся:

| Элемент | Что контролируется |
|---------|-------------------|
| Экспортные процедуры/функции [раздела «Программный интерфейс»](#std455) | Имена, состав параметров, поведение |
| Процедуры [переопределяемых общих модулей](#std553) | Имена, состав параметров, поведение |
| Роли и элементы стилей | Имена |
| Объекты метаданных для прямого обращения | Имена (включая реквизиты, табличные части) |

### 1.7. Расширение без нарушения совместимости

В 3-й цифре (ВВ) **допустимо**:
- Добавление новой функции в программный модуль
- Добавление процедуры в переопределяемый модуль
- Добавление необязательного параметра в конец списка формальных параметров
- Добавление нового реквизита в справочник, регистр и т.п.

**Недопустимо:**
- Добавление нового API в исправительных релизах (4-я цифра)
- Изменение поведения процедуры без изменения сигнатуры (допустимо только во 2-й цифре)

**Пример нарушения:** процедура `Сумма(а, б)` вместо суммы стала вычислять разность.

### 1.8. Документирование изменений

При нарушении совместимости (в 2-й цифре) следует документировать изменения с инструкцией для разработчиков.

**Примеры фрагментов документации:**

- Общий модуль **ВнешниеЗадачиСервер** переименован в **ВнешниеЗадачи**. Необходимо заменить все обращения к этому модулю в коде конфигурации.
- Процедура **УстановитьПроизвольныйЗаголовокПриложения** переименована в **УстановитьРасширенныйЗаголовокПриложения**.
- Отчёт **СправкаПоИсполнительскойДисциплине** удалён. Вместо него следует использовать одноимённый вариант отчёта **Задачи**.
- В общий модуль **ЗащитаПерсональныхДанныхПереопределяемый** добавить процедуру **ДополнитьДанныеОрганизацииОператораПерсональныхДанных**.

### 1.9. Размещение программного интерфейса

✅ Рекомендуется размещать программный интерфейс библиотеки только в **общих модулях**
❌ Не рекомендуется в модулях объектов, менеджеров, наборов записей

## 2. Разделение программного и служебного интерфейса

### 2.1. Служебные модули

Для разделения программного интерфейса от служебных процедур и функций размещать их в разных разделах модуля или в **разных общих модулях**.

К модулям со служебными процедурами добавляется постфикс **Служебный** (англ. **Internal**).

**Пример:**
- `ОбменСообщениями`, `ОбменСообщениямиКлиент` — программный интерфейс подсистемы
- `ОбменСообщениямиСлужебный` — служебные процедуры, не для кода конфигурации-потребителя

**Преимущества:**
- Весь программный интерфейс в обозримом количестве модулей
- В контекстной подсказке выводятся только нужные процедуры

### 2.2. Подраздел «Для вызова из других подсистем»

Процедуры для вызова конкретными потребителями из других подсистем выделять в область **ДляВызоваИзДругихПодсистем** (англ. **InterfaceImplementation**).

```1c
#Область ПрограммныйИнтерфейс
// Код процедур и функций

#Область ДляВызоваИзДругихПодсистем

// СтандартныеПодсистемы.ГрупповоеИзменениеОбъектов
// Код процедур и функций
// Конец СтандартныеПодсистемы.ГрупповоеИзменениеОбъектов

// ТехнологияСервиса.ВыгрузкаЗагрузкаДанных
// Код процедур и функций
// Конец ТехнологияСервиса.ВыгрузкаЗагрузкаДанных

#КонецОбласти

#КонецОбласти
```

## 3. Практические рекомендации

### 3.1. Устаревшие функции

При необходимости переименовать или удалить экспортную функцию — оставить прежнюю реализацию с комментарием:

```1c
// Устарела: Следует использовать функцию ПересчитатьПоКурсу
// …
Функция ПересчитатьИзВалютыВВалюту(Сумма, ВалютаНач, ВалютаКон, ПоКурсуНач, ПоКурсуКон, ПоКратностьНач = 1, ПоКратностьКон = 1) Экспорт
```

(Англоязычный аналог — **Deprecated**)

Устаревшую функцию перенести в область **УстаревшиеПроцедурыИФункции** (англ. **Deprecated**) внутри области **ПрограммныйИнтерфейс**.

В сопроводительной документации:
> Процедура **ПересчитатьИзВалютыВВалюту** общего модуля **ОбщегоНазначения** устарела, вместо неё следует использовать **ПересчитатьПоКурсу**. Устаревшая функция оставлена для обратной совместимости.

### 3.2. Исправление ошибок с изменением поведения

Даже при исправлении ошибки рекомендуется оставлять прежнюю ошибочную функцию (пометив как устаревшую) и размещать исправленную версию с новым именем.

**Причина:** прикладной код мог заложиться на неправильное поведение, но работает корректно.

### 3.3. Расширение состава параметров

Использовать **опциональные параметры**, добавляемые в конец списка:

```1c
Функция ПересчитатьИзВалютыВВалюту(Сумма, ВалютаНач, ВалютаКон, ПоКурсуНач, ПоКурсуКон, ПоКратностьНач = 1, ПоКратностьКон = 1) Экспорт
```

При большом числе параметров — последний параметр типа **Структура**:

```1c
Функция ПересчитатьИзВалютыВВалюту(Сумма, ВалютаНач, ВалютаКон, ПоКурсуНач, ПоКурсуКон, ПараметрыПересчета = Неопределено) Экспорт
```

### 3.4. Структура для настроек

Параметры типа **Структура** позволяют библиотеке добавлять новые режимы работы без потери совместимости:

```1c
Процедура ПриОпределенииНастроек(Настройки) Экспорт
  Настройки.ВыводитьОписания = Истина;
  Настройки.События.ПриСозданииНаСервере = Истина;
  Настройки.... = ...;
КонецПроцедуры
```

Появление нового события не потребует обязательного добавления пустых обработчиков во всех конфигурациях-потребителях.

### 3.5. Минимизация прямых обращений

Вместо прямого запроса к библиотечному регистру:

```1c
Запрос = Новый Запрос;
Запрос.Текст = "ВЫБРАТЬ
    | ОбластиДанных.Представление
    |ИЗ
    | РегистрСведений.ОбластиДанных КАК ОбластиДанных
    |ГДЕ
    | ОбластиДанных.ОбластьДанных = &ОбластьДанных";
Запрос.УстановитьПараметр("ОбластьДанных", ПараметрыСеанса.ОбластьДанныхЗначение);
ТаблицаОбластейДанных = Запрос.Выполнить().Выгрузить();
ИмяПриложения = ?(ТаблицаОбластейДанных.Количество() = 0, "", ТаблицаОбластейДанных.Получить(0).Получить(0));
```

✅ Предусмотреть экспортную функцию:

```1c
ИмяПриложения = РаботаВМоделиСервиса.ИмяПриложения();
```

### 3.6. Скрытие деталей реализации

✅ Размещать программный интерфейс в **обычном общем модуле** вместо специализированного (**ПовтИсп**, **ВызовСервера**).

**Причина:** проектное решение может измениться, но местоположение API для потребителя не будет меняться.

Модули **ВызовСервера** должны быть служебными, не содержать программный интерфейс и не быть переопределяемыми (требования [безопасности](#std678) и [производительности](#std487)).

## 4. Контроль изменений

Для упрощения контроля изменений программного интерфейса в новых версиях библиотек рекомендуется воспользоваться специальной обработкой (доступна на ИТС).

## Сводка

| Цифра версии | Что допустимо | Совместимость |
|--------------|---------------|---------------|
| РР (редакция) | Архитектурные изменения | ❌ Нарушена |
| ПП (подредакция) | Нарушение совместимости, удаление устаревших объектов | ❌ Нарушена |
| ВВ (версия) | Новые функции | ✅ Сохранена |
| СС (сборка) | Только исправление ошибок | ✅ Сохранена |

| Рекомендация | Описание |
|--------------|----------|
| Устаревшие функции | Помечать комментарием «Устарела:», переносить в область Deprecated |
| Новые параметры | Добавлять в конец как опциональные или использовать Структуру |
| Скрытие реализации | API в обычных модулях, не в ПовтИсп/ВызовСервера |
| Прямые обращения | Минимизировать, предоставлять экспортные функции |
