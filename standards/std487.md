# #std487 Минимизация количества серверных вызовов и трафика

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Общие правила

### 1.1. Контроль серверных вызовов

Разработку управляемого приложения необходимо вести с контролем количества серверных вызовов из клиентского кода.

**Общее количество серверных вызовов:**
- Обращения на сервер, которые выполняет платформа 1С:Предприятие
- Вызовы из клиентского кода конфигурации (отклонение от платформы)

**Правило:** На каждое действие пользователя в клиентском коде конфигурации **не должно** выполняться дополнительных вызовов на сервер.

**Типовое исключение:** неявный серверный вызов при первом обращении к клиентскому общему модулю (компиляция модуля).

### 1.2. Режим низкой скорости соединения

Для мобильного клиента и режима с низкой скоростью соединения следует оптимизировать не только количество вызовов, но и **объем передаваемых данных** (трафик).

Отладку рекомендуется проводить в режиме имитации задержек серверных вызовов.

## 2. Запуск клиентского приложения

### 2.1. Минимизация вызовов при запуске

В простейшем случае код в `ПередНачаломРаботыСистемы` и `ПриНачалеРаботыСистемы` **не должен** обращаться на сервер.

Если всё же нужны данные с сервера:
- ❌ Не вызывать серверные процедуры напрямую из модуля приложения
- ✅ За **один вызов** передавать все параметры для запуска

**Пример** (модуль с повторным использованием):

```1c
// Общий серверный модуль ПараметрыПовтИсп (с повторным использованием)
Функция ПараметрыРаботыКлиента()
  Параметры = Новый Структура();
  Параметры.Вставить("ИнформационнаяБазаФайловая", ОбщегоНазначения.ИнформационнаяБазаФайловая());
  // Другие параметры...
  Возврат Параметры;
КонецФункции

// Клиентский код в ПриНачалеРаботыСистемы
ИнформационнаяБазаФайловая = ПараметрыПовтИсп.ПараметрыРаботыКлиента().ИнформационнаяБазаФайловая;
```

### 2.2. При использовании БСП

- Серверный код размещать в `ОбщегоНазначенияПереопределяемый.ПриДобавленииПараметровРаботыКлиентаПриЗапуске`
- Клиентский код: вызывать `СтандартныеПодсистемыКлиент.ПараметрыРаботыКлиентаПриЗапуске()`

## 3. Периодические серверные вызовы

### 3.1. Объединение вызовов

Примеры периодических задач:
- Передача данных о замерах производительности
- Проверка изменения конфигурации/прав
- Проверка завершения работы пользователей
- Проверка актуальности курсов валют
- Проверка напоминаний

**Рекомендации:**
- Объединять вызовы в один
- Период — **не чаще раза в 20 минут**
- Использовать `МенеджерУведомленийКлиента` вместо периодических проверок

### 3.2. При использовании БСП

**3.2.1.** Для длительных операций — `ДлительныеОперацииКлиент.ОжидатьЗавершение()`

**3.2.2.** Для форм на начальной странице:
- Рекомендуется кнопка **Обновить** вместо периодических вызовов
- Если вызовы необходимы — отключены по умолчанию, период не чаще **раза в минуту**

**3.2.3.** Для серверных оповещений:
- `ОбщегоНазначенияПереопределяемый.ПриДобавленииСерверныхОповещений`
- `ПриОтправкеСерверногоОповещения` (сервер)
- `ПриПолученииСерверногоОповещения` (клиент)

**3.2.4.** Для периодической отправки данных с клиента:
- `ОбщегоНазначенияКлиентПереопределяемый.ПередПериодическойОтправкойДанныхКлиентаНаСервер`
- `ОбщегоНазначенияПереопределяемый.ПриПериодическомПолученииДанныхКлиентаНаСервере`
- `ОбщегоНазначенияКлиентПереопределяемый.ПослеПериодическогоПолученияДанныхКлиентаНаСервере`

## 4. Открытие управляемой формы

### 4.1. Открытие формы из кода

Открывать форму за **один вызов** с помощью `ОткрытьФорму`. Параметры передавать через параметр `Параметры`.

### 4.2. Запрет серверных вызовов при открытии

**Не допускается** обращение к серверу из `ПриОткрытии` и `ПриПовторномОткрытии`.

**❌ Неправильно:**

```1c
НастройкаПроксиСервера = СерверныйМодуль.НастройкаПроксиСервера();
ОткрытьФорму("ОбщаяФорма.ПараметрыПроксиСервера", Новый Структура("Настройка", НастройкаПроксиСервера));
```

**✅ Правильно:**

```1c
ОткрытьФорму("ОбщаяФорма.ПараметрыПроксиСервера");
// Получение значения — в ПриСозданииНаСервере формы
```

**Фоновые задания:** запускать в `ПриСозданииНаСервере`, проверку готовности — в `ПриОткрытии`.

**Функции с повторным использованием:** не вызывать при открытии формы (при первом вызове — избыточный серверный вызов).

### 4.3. Обработчики ожидания

**Не следует** подключать несколько обработчиков ожидания для проверки фоновых заданий.

**Правильно:** объединять в один обработчик, который за один серверный вызов проверяет готовность и забирает результат.

При использовании БСП — использовать `ДлительныеОперации` и `ДлительныеОперацииКлиент`.

## 5. Выполнение локальной команды формы

Выполнение локальной команды должно приводить **не более чем к одному** вызову сервера.

Если команда выполняет только клиентские операции — данные готовить заранее в `ПриСозданииНаСервере`.

**Пример:** проверка "является ли элемент группой"

```1c
// Данные готовим в ПриСозданииНаСервере (реквизит ЭтоГруппа)
// На клиенте проверяем без серверного вызова:
ТекущаяСтрока = Элемент.ТекущиеДанные;
Если ТекущаяСтрока.ЭтоГруппа Тогда
  Сообщение = Новый СообщениеПользователю();
  Сообщение.Текст = НСтр("ru = 'Выбор группы запрещен.'");
  Сообщение.Сообщить();
  Возврат;
КонецЕсли;
```

---

## 6. Выбор из справочника

- Допускается **один** серверный вызов (`ОткрытьФорму`)
- После выбора, если нужна бизнес-логика на сервере — **один дополнительный** вызов

---

## 7. Выполнение глобальной команды

Допускается **один** серверный вызов из кода. Если команда открывает форму — вызов при `ОткрытьФорму`.

---

## 8. Формирование отчета

**Не допускается** дополнительных серверных вызовов.

**❌ Неправильно:**

```1c
&НаКлиенте
Процедура ПриОткрытии(Отказ)
  ВывестиОтчет();
КонецПроцедуры

&НаСервере
Процедура ВывестиОтчет()
  // код формирования отчета
КонецПроцедуры
```

**✅ Правильно:**
- Открывать форму с параметром `СформироватьПриОткрытии = Истина`
- Или установить этот параметр в `ПриСозданииНаСервере`

## 9. Подбор элементов

### 9.1. Проблема

При подборе передается список выбранных элементов между формами. Объем данных может быть большим.

**Не рекомендуется** передавать большой массив как параметр формы подбора.

### 9.2. Решение — временное хранилище

**Открытие формы подбора** (≤2 серверных вызова):

```1c
// В форме документа
&НаКлиенте
Процедура ОбработчикКомандыПодбора()
  АдресТоваровВХранилище = ПоместитьТоварыВХранилище(); // 1-й вызов
  ПараметрыПодбора = Новый Структура("АдресТоваровДокумента", АдресТоваровВХранилище);
  ФормаПодбора = ОткрытьФорму("...", ПараметрыПодбора, ...); // 2-й вызов
КонецПроцедуры

&НаСервере
Функция ПоместитьТоварыВХранилище()
  Возврат ПоместитьВоВременноеХранилище(Объект.Товары.Выгрузить(), УникальныйИдентификатор);
КонецФункции
```

**Форма подбора** получает данные в `ПриСозданииНаСервере`:

```1c
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
  АдресТоваровДокумента = Параметры.АдресТоваровДокумента;
  Объект.Товары.Загрузить(ПолучитьИзВременногоХранилища(АдресТоваровДокумента));
КонецПроцедуры
```

### 9.3. Управление временным хранилищем

Два варианта:
1. Помещать на время жизни формы + **очищать после использования**
2. Предварительно инициализировать и **переиспользовать**

```1c
// Инициализация для переиспользования
&НаСервере
Процедура ПриСозданииНаСервере(Отказ)
  АдресТоваров = ПоместитьВоВременноеХранилище(Неопределено, УникальныйИдентификатор);
КонецПроцедуры
```

---

## 10. Запись формы

Вместо серверных вызовов в клиентских `ПередЗаписью` и `ПослеЗаписи` — размещать логику в серверных обработчиках:
- `ПередЗаписьюНаСервере`
- `ПриЗаписиНаСервере`
- `ПослеЗаписиНаСервере`

Данные передавать через `ПараметрыЗаписи` или реквизиты формы.

---

## 11. Неявные серверные вызовы

Методы и свойства, приводящие к серверному вызову:
- `ПолучитьИзВременногоХранилища`, `УдалитьИзВременногоХранилища`
- Свойства поля формы: `Заголовок`, `Доступность`, `Подсказка`, `ТолькоПросмотр`
- `ПолучитьФункциональнуюОпциюИнтерфейса`, `ПолучитьФункциональнуюОпциюФормы`

**Избегать** многократного вызова — объединять в один серверный вызов.

---

## 12. Передача данных между клиентом и сервером

### 12.1. Минимизация передаваемых данных

**❌ Неправильно** (контекстный вызов):

```1c
&НаСервере
Процедура ОбновитьПанельКонтактнойИнформацииСервер()
  КонтактнаяИнформацияПанель.ОбновитьДанныеПанели(ЭтотОбъект, ТекущийКонтрагент);
КонецПроцедуры
```

**✅ Правильно** (без контекста):

```1c
&НаСервереБезКонтекста
Функция ДанныеПанелиКонтактнойИнформации(Контрагент)
  Возврат КонтактнаяИнформацияПанель.ДанныеПанелиКонтактнойИнформации(Контрагент);
КонецФункции
```

### 12.2. Использование Знач

**Рекомендуется** указывать параметры с префиксом `Знач` для серверных процедур, вызываемых с клиента:

```1c
// ❌ Неправильно
Функция НовоеОбсуждение(ПользовательСсылка)

// ✅ Правильно
Функция НовоеОбсуждение(Знач ПользовательСсылка)
```

Это касается:
- Экспортных процедур в модулях с признаком **Вызов сервера**
- Процедур с директивами `&НаСервере`, `&НаСервереБезКонтекста`

## Сводка

| Действие | Допустимо серверных вызовов |
|----------|----------------------------|
| Запуск приложения | 0 (или 1 через ПовтИсп) |
| Открытие формы | 1 (ОткрытьФорму) |
| Локальная команда формы | ≤1 |
| Выбор из справочника | 1 (+1 для бизнес-логики) |
| Глобальная команда | 1 |
| Формирование отчета | 0 дополнительных |
| Подбор (открытие/закрытие) | ≤2 + ≤2 |
| Запись формы | 0 дополнительных |

| Рекомендация | Описание |
|--------------|----------|
| Периодические вызовы | Не чаще 1 раза в 20 минут |
| Параметры серверных функций | Использовать `Знач` |
| Контекстные вызовы | Избегать, если нужно только одно значение |
| Временное хранилище | Очищать или переиспользовать |
