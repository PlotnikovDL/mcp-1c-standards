# #std661 Блокирующее чтение остатков в начале транзакции

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Зачем нужно блокирующее чтение

### 1.1. Контроль остатков

При проведении документа необходимо проверить, что остатки не станут отрицательными. Если станут — транзакция должна быть отменена.

### 1.2. Почему чтение должно быть блокирующим

Нужно **запретить** двум пользователям одновременно читать один и тот же остаток.

**Проблема без блокировки:**

| Шаг | Пользователь 1 | Пользователь 2 |
|-----|----------------|----------------|
| 1 | Читает остаток: 10 ед. | Читает остаток: 10 ед. |
| 2 | Списывает 8 ед. (8 < 10 ✓) | Списывает 6 ед. (6 < 10 ✓) |
| 3 | **Результат:** -4 ед. ❌ | |

Оба пользователя приняли решение на основании **устаревших данных**.

---

## 2. Проблема: контроль в начале транзакции

Обычно контроль остатков выполняется запросом в модуле набора записей регистра **перед записью**. Проблемы:

| Проблема | Описание |
|----------|----------|
| Порядок записи | Платформа записывает регистры автоматически. Если контролируемый регистр записывается первым — блокировка держится всю транзакцию |
| Избыточный контроль | Иногда контроль не нужен (приходные документы, перепроведение) |

---

## 3. Решение: перенос контроля в конец транзакции

### Алгоритм

1. **В начале транзакции** (например, в `ОбработкаПроведения`):
   - Записать движения по регистрам, **не требующим** контроля остатков
   - Порядок записи — **всегда одинаковый** (например, алфавитный)
   - Разделение итогов — **включено**
   - `БлокироватьДляИзменения = Ложь`

2. **Выполнить все остальные действия** в рамках транзакции

3. **В конце транзакции**:
   - Записать движения по регистрам, **требующим** контроля
   - `БлокироватьДляИзменения = Истина` (предотвращает взаимоблокировку)

4. **Выполнить запрос контроля остатков**:
   - `ДЛЯ ИЗМЕНЕНИЯ` не нужен — остатки уже заблокированы записью
   - Запрос возвращает только **отрицательные** остатки
   - Есть записи → отменить транзакцию
   - Пустой результат → зафиксировать

---

## 4. Когда контроль не нужен

| Ситуация | Причина |
|----------|---------|
| Приходный документ | Только увеличивает остатки |
| Перепроведение без увеличения списания | Контроль уже проводился при первом проведении |

---

## 5. Пример

### ❌ Неправильно — контроль в начале

В процедуре `ПередЗаписью` модуля набора записей регистра бухгалтерии:

```1c
Запрос.Текст = "ВЫБРАТЬ
    | СуммаОстаток,
    | СуммаОстатокДт,
    | СуммаОстатокКт
    |ИЗ
    | РегистрБухгалтерии.Хозрасчетный.Остатки(&Период, &Счет, , Организация = &Организация)";
```

**Проблема:** блокируются остатки для **всех** пользователей на время всей транзакции. Разделение итогов не помогает — ресурсы объединяются при чтении.

### ✅ Правильно — контроль в конце

Вынести проверку в `ОбработкаПроведения` **после** явной записи всех движений по всем регистрам.

---

## Сводка

| Правило | Описание |
|---------|----------|
| Контроль остатков | Переносить в конец транзакции |
| Регистры без контроля | Записывать первыми, `БлокироватьДляИзменения = Ложь` |
| Регистры с контролем | Записывать последними, `БлокироватьДляИзменения = Истина` |
| Порядок записи | Всегда одинаковый (алфавитный) |
| Запрос контроля | Без `ДЛЯ ИЗМЕНЕНИЯ`, только отрицательные остатки |
