# #std693 Использование объектов типа Структура

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## Цель стандарта

Требования направлены на **повышение читаемости кода** и упрощение внесения изменений разными разработчиками — как при коллективной разработке, так и при доработке на внедрениях.

---

## 1. Не более 3 значений в конструкторе

При создании объекта типа **Структура** не рекомендуется передавать в конструктор **более 3-х значений** свойств. Вместо этого использовать метод **Вставить** или присваивание.

**❌ Неправильно:**

```1c
ПараметрыФормы = Новый Структура(
    "Параметр1, Параметр2, Параметр3, Параметр4, Параметр5",
    Значение1, Значение2, Значение3, Значение4, Значение5);
```

**✅ Правильно:**

```1c
ПараметрыФормы = Новый Структура;
ПараметрыФормы.Вставить("Параметр1", Значение1);
ПараметрыФормы.Вставить("Параметр2", Значение2);
ПараметрыФормы.Вставить("Параметр3", Значение3);
ПараметрыФормы.Вставить("Параметр4", Значение4);
ПараметрыФормы.Вставить("Параметр5", Значение5);
```

---

## 2. Не использовать вложенные конструкторы

Не рекомендуется в конструкторе структуры использовать **конструкторы других объектов** с параметрами. В частности — не создавать вложенные структуры.

**❌ Неправильно:**

```1c
Параметры = Новый Структура("Свойство1, Свойство2",
    Новый Структура("Ключ", "Значение"),
    Новый Структура("Ключ", "Значение"));
```

**✅ Правильно:**

```1c
Параметры = Новый Структура;
Параметры.Вставить("Свойство1", Новый Структура("Ключ", "Значение"));
Параметры.Вставить("Свойство2", Новый Структура("Ключ", "Значение"));
```

---

## 3. Не вызывать функции с многими параметрами в конструкторе

Не рекомендуется в конструкторе структуры вызывать функции с **более чем 3 параметрами**.

**❌ Неправильно:**

```1c
Данные = Новый Структура("Результат",
    ПолучитьДанные(Параметр1, Параметр2, Параметр3, Параметр4, Параметр5));
```

**✅ Правильно:**

```1c
Данные = Новый Структура("Результат");
Данные.Результат = ПолучитьДанные(Параметр1, Параметр2, Параметр3, Параметр4, Параметр5);
```

---

## 4.1. Создавать структуру со значениями по умолчанию

Не рекомендуется в разных частях кода добавлять свойства и затем **проверять их наличие**. Следует сразу создавать структуру со значениями по умолчанию.

**❌ Неправильно:**

```1c
ПараметрыВыполнения = Новый Структура;
// ...
УникальныйИдентификатор = ?(ПараметрыВыполнения.Свойство("УникальныйИдентификатор"),
    ПараметрыВыполнения.УникальныйИдентификатор, Неопределено);
```

**✅ Правильно:**

```1c
ПараметрыВыполнения = ПараметрыВыполнения();
УникальныйИдентификатор = ПараметрыВыполнения.УникальныйИдентификатор;
// ...

Функция ПараметрыВыполнения()
    Результат = Новый Структура;
    Результат.Вставить("УникальныйИдентификатор", Неопределено);
    Возврат Результат;
КонецФункции
```

---

## 4.2. Исключения

Допустимо проверять наличие свойств для структур **нефиксированного формата**:

- Структуры из **внешних источников**: результат HTTP-запроса, данные сканера штрихкодов, ТСД и т.п.
- **Системные параметры формы**, параметры выбора в параметрах формы

> **Примечание:** пользовательские параметры формы необходимо объявлять явно на закладке «Параметры» редактора формы.

## Сводка

| Правило | Рекомендация |
|---------|--------------|
| Значений в конструкторе | Не более 3 |
| Вложенные конструкторы | ❌ Избегать |
| Функции с >3 параметрами в конструкторе | ❌ Избегать |
| Проверка наличия свойств | Создавать функцию-конструктор со значениями по умолчанию |
