# #std469 Правила создания общих модулей

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Назначение общих модулей

**1.1.** Общие модули создаются для реализации процедур и функций, объединённых по некоторому признаку:
- Процедуры и функции **одной подсистемы** конфигурации (продажи, закупки)
- Процедуры и функции **сходного функционального назначения** (работа со строками, общего назначения)

**1.2.** При разработке общих модулей следует выбирать **один из четырёх контекстов** выполнения кода:

| # | Тип общего модуля | Пример наименования | Вызов сервера | Сервер | Внешнее соединение | Клиент (обычное) | Клиент (управляемое) |
|---|-------------------|---------------------|---------------|--------|-------------------|------------------|---------------------|
| 1 | Серверный | ОбщегоНазначения | | + | + | + | |
| 2 | Серверный для вызова с клиента | ОбщегоНазначенияВызовСервера | + | + | | | |
| 3 | Клиентский | ОбщегоНазначенияКлиент | | | | + | + |
| 4 | Клиент-серверный | ОбщегоНазначенияКлиентСервер | | + | + | + | + |

---

## 2. Типы общих модулей

### 2.1. Серверные общие модули

**Назначение:** Размещение серверных процедур и функций, **не доступных** для использования из клиентского кода. Реализация внутренней серверной бизнес-логики.

**Признаки модуля:**
- ✅ **Сервер** (флажок «Вызов сервера» **снят**)
- ✅ **Клиент (обычное приложение)**
- ✅ **Внешнее соединение**

**Когда использовать:**
- Обработчики подписок на события (принимают мутабельные объекты)
- Серверные процедуры с параметрами типа `СправочникОбъект`, `ДокументОбъект` и т.п.

**Именование:**
- По общим правилам: `РаботаСФайлами`, `FilesOperations`
- При конфликте имён — постфикс **«Сервер»** (`Server`): `РегламентныеЗаданияСервер`

---

### 2.2. Серверные общие модули для вызова с клиента

**Назначение:** Серверные процедуры и функции, **доступные** для использования из клиентского кода. Составляют клиентский программный интерфейс сервера приложения.

**Признаки модуля:**
- ✅ **Сервер** (флажок «Вызов сервера» **установлен**)

**Именование:** Постфикс **«ВызовСервера»** (`ServerCall`)
- `РаботаСФайламиСлужебныйВызовСервера`
- `FilesOperationsInternalServerCall`

⚠️ **Ограничение:** Экспортные процедуры и функции **не должны** содержать параметров мутабельных типов (`СправочникОбъект`, `ДокументОбъект` и т.п.) — их передача из/в клиентский код невозможна.

---

### 2.3. Клиентские общие модули

**Назначение:** Клиентская бизнес-логика (функциональность, определённая **только для клиента**).

**Признаки модуля:**
- ✅ **Клиент (управляемое приложение)**
- ✅ **Клиент (обычное приложение)**

**Именование:** Постфикс **«Клиент»** (`Client`)
- `РаботаСФайламиКлиент`
- `FilesOperationsClient`

---

### 2.4. Клиент-серверные общие модули

**Назначение:** Процедуры и функции, содержание которых **одинаково** на сервере и на клиенте. Позволяют избежать дублирования кода.

**Признаки модуля:**
- ✅ **Клиент (управляемое приложение)**
- ✅ **Сервер** (флажок «Вызов сервера» **сброшен**)
- ✅ **Клиент (обычное приложение)**
- ✅ **Внешнее соединение**

**Именование:** Постфикс **«КлиентСервер»** (`ClientServer`)
- `РаботаСФайламиКлиентСервер`
- `FilesOperationsClientServer`

⚠️ **Важно:** Если возникает необходимость ветвить код на серверный и клиентский — **не используйте инструкции препроцессора**. Вместо этого реализуйте функциональность в модулях соответствующего типа (см. пп. 2.1 и 2.3).

---

## 3. Правила именования

### 3.1. Основные правила

- Название должно совпадать с названием **подсистемы или механизма**
- **Избегать** общих слов: «Процедуры», «Функции», «Обработчики», «Модуль», «Функциональность»
- Использовать **постфиксы** для различения контекста выполнения

### 3.2. Дополнительные постфиксы

| Постфикс | Англ. | Назначение |
|----------|-------|------------|
| **Глобальный** | Global | Глобальные модули (постфикс «Клиент» не добавлять) |
| **ПолныеПрава** | FullAccess | Привилегированные модули (признак «Привилегированный») |
| **ПовтИсп** | Cached | Серверные модули с повторным использованием возвращаемых значений |
| **КлиентПовтИсп** | ClientCached | Клиентские модули с повторным использованием возвращаемых значений |
| **Переопределяемый** | Overridable | Серверные модули библиотек, допускающие изменение реализации |
| **КлиентПереопределяемый** | ClientOverridable | Клиентские модули библиотек, допускающие изменение реализации |
| **Локализация** | Localization | Модули с национальной спецификой |
| **КлиентЛокализация** | ClientLocalization | Клиентские модули с национальной спецификой |

**Примеры:**
- `РаботаСФайламиСлужебныйГлобальный`
- `РаботаСФайламиСлужебныйПолныеПрава`
- `РаботаСФайламиСлужебныйКлиентПовтИсп`
- `РаботаСФайламиКлиентПереопределяемый`

## 4. Сводная таблица постфиксов

| Контекст | Постфикс (рус.) | Постфикс (англ.) |
|----------|-----------------|------------------|
| Серверный | (без постфикса) или Сервер | (none) или Server |
| Вызов с клиента | ВызовСервера | ServerCall |
| Клиентский | Клиент | Client |
| Клиент-серверный | КлиентСервер | ClientServer |
| Глобальный | Глобальный | Global |
| Привилегированный | ПолныеПрава | FullAccess |
| С кэшированием (сервер) | ПовтИсп | Cached |
| С кэшированием (клиент) | КлиентПовтИсп | ClientCached |
| Переопределяемый | Переопределяемый | Overridable |
