# #std662 Сдвиг границы последовательности документов

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## Основная рекомендация

❌ **Не рекомендуется** двигать границу последовательности при проведении документов.

Это приводит к:
- Ожиданиям на блокировках
- Снижению общей производительности системы

✅ **Решение:** вынести операцию в **регламентные задания** с заданной частотой.

---

## Почему возникают блокировки

**Граница последовательности** по одному набору значений измерений — это **один ресурс**.

При движении границы по одному набору измерений разные пользователи пытаются захватить **один и тот же ресурс** → блокируют друг друга.

| Ситуация | Результат |
|----------|-----------|
| 2 пользователя проводят документы по одной организации | Взаимная блокировка |
| Много одновременных проведений | Очередь ожидания |

---

## Пример: партионный учёт в УПП

### Проблема

В УПП 1.x при включённой настройке **«Списывать партии при проведении документов»**:

- Последовательность «Партионный учет» имеет измерение **Организация**
- При проведении расходного документа граница сдвигается на момент документа
- Два пользователя с документами по **одной организации** → блокировка

### Почему это не баг

Это требование алгоритма — необходимо знать **точную последовательность** документов. Все конкурирующие по времени документы должны выстроиться друг за другом.

### Решение

1. **Отключить** флажок «Списывать партии при проведении документов»
2. Использовать **регламентную обработку** для расчёта себестоимости с заданной частотой

## Сводка

| Правило | Описание |
|---------|----------|
| Граница последовательности | Один ресурс на набор измерений |
| При проведении | ❌ Не двигать границу |
| Расчёт себестоимости | В регламентном задании |
| Конкурентные документы | Выстраиваются в очередь |
