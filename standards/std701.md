# #std701 Разработка планов обмена с отборами

> Область применения: управляемое приложение, мобильное приложение.

> *Рекомендация (полезный совет)*

---

## 1. Общие положения

### 1.1. Обмен частью данных

Для синхронизации данных между конфигурациями и для организации РИБ используется технология планов обмена. Часто возникает задача обмена **не всеми данными**, а только частью (в разрезе организаций, складов, подразделений и пр.).

Для определения узлов-получателей использовать события:
- **ПередЗаписью**
- **ПередУдалением**

В этих событиях предусмотреть логику регистрации изменений данных на узлах планов обмена.

> При использовании подсистемы «Обмен данными» БСП логика регистрации может быть задана декларативно в **правилах регистрации объектов (ПРО)**, разрабатываемых в «Конвертации данных».

### 1.2. Особенности логики регистрации

| Особенность | Описание |
|-------------|----------|
| Произвольный порядок загрузки | Данные из сообщения загружаются в произвольном порядке — на момент выполнения логики регистрации необходимые данные могут быть ещё не загружены |
| Выполнение в контексте загрузки | Логика регистрации выполняется в транзакции записи объекта, признак `ОбменДанными.Загрузка` игнорируется. Любые ошибки приведут к аварийному завершению загрузки |
| Неполный состав данных в РИБ | В РИБ могут участвовать не все данные (например, движения без регистраторов) |
| Обращение «через точку» | Приводит к неявному соединению с дополнительными таблицами → снижение производительности |

> При использовании подсистемы «Обмен данными» БСП для синхронизации (не РИБ, по правилам конвертации) первые два пункта не требуется учитывать для **ссылочных типов**, т.к. их регистрация выполняется отложенно после загрузки всех данных.

## 2. Рекомендации

### 2.1. Обеспечить самодостаточность данных

Таблицы данных (справочники, документы, регистры), участвующие в обмене, должны содержать **все необходимые данные** для выполнения логики регистрации.

❌ Логика регистрации **не должна** обращаться к полям связанных таблиц

✅ Логика регистрации должна оперировать **только данными основной таблицы**

**Пример:**
- Данные регистрируются в разрезе организаций
- В обмене участвуют: документ и регистр накопления с движениями
- И документ, и регистр **самодостаточны** — оба содержат ссылку на организацию
- При записи логика регистрации отрабатывает **независимо** для документа и для набора записей регистра

### 2.2. Исключить из обмена вторичные данные

Данные, которые могут быть **вычислены независимо** в каждой из информационных баз, следует **исключить** из состава плана обмена.

**Пример:**
- Данные регистрируются в разрезе организаций
- В обмене участвуют только документы поступления товаров
- Регистр сведений для прав доступа к документам **не самодостаточен** (нет ссылки на организацию) → **не участвует** в обмене
- Данные регистра вычисляются независимо в каждом узле при загрузке документов

### 2.3. Регистрировать изменения связанных данных

Если в обмене участвуют несколько **логически взаимосвязанных таблиц**:
- Логика регистрации должна регистрировать к выгрузке данные **всех взаимосвязанных таблиц**
- Логика регистрации **не должна аварийно прерываться** при отсутствии необходимых данных

**Пример:**
- Данные регистрируются в разрезе организаций
- В обмене участвуют: справочник «Основные средства» и регистр сведений «Основные средства организаций» (связь ОС с организацией)
- При записи элемента справочника **и** при записи набора записей регистра к выгрузке регистрируются **оба объекта**
- Если сначала загружается элемент справочника — он записывается, но не регистрируется (набор записей ещё не загружен)
- При последующей загрузке набора записей выполняется регистрация **и** набора записей, **и** элемента справочника

## Сводка

| Правило | Описание |
|---------|----------|
| Самодостаточность | Таблицы должны содержать все данные для логики регистрации |
| Исключение вторичных данных | Вычисляемые данные не участвуют в обмене |
| Связанные данные | Регистрировать все взаимосвязанные таблицы |
| Устойчивость к ошибкам | Не прерываться при отсутствии данных |
| Производительность | Избегать обращений «через точку» |
