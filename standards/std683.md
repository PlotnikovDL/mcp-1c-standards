# #std683 Общие сведения об организации хранения данных

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

> *Методическая рекомендация (полезный совет)*

---

## 1. Введение

При проектировании системы одной из задач является выбор типов объектов метаданных для реализации хранения соответствующих сущностей предметной области.

⚠️ **Неправильный выбор** типов объектов ведёт к:
- Неэффективности прикладного решения
- Невозможности последующего развития
- Невозможности адаптации к изменениям задач

---

## 3. Три блока хранения данных

### 2.1. Условно-постоянная информация (Блок 1)

Информация, которая:
- Вводится один раз
- Сравнительно редко изменяется
- Многократно используется

**Примеры:** классификаторы, настройки, перечни, реестры, НСИ

### 2.2. События процессов предметной области (Блок 2)

События, которые:
- Привязаны ко времени
- Могут порождать сведения
- Изменяют значения показателей

**Примеры:** документооборот, учёт, заявки, звонки

### 2.3. Накопленные сведения, значения показателей (Блок 3)

Данные, которые:
- Имеют необъектную природу
- Не являются самостоятельными сущностями
- Характеризуют процессы и текущее состояние

**Примеры:** история продаж, остатки на складах, бухгалтерский баланс, курсы валют

---

## 4. Выбор блока для сущности

### 4.1. Простая схема выбора

| Условие | Блок |
|---------|------|
| Редко изменяющаяся информация, не привязана ко времени | Блок 1 (условно-постоянная) |
| Регистрация событий с документальным подтверждением, отслеживание последовательности | Блок 2 (события) |
| Всё остальное | Блок 3 (сведения и показатели) |

### 4.2. Подробные критерии выбора блока

| Критерий | Блок 1 | Блок 2 | Блок 3 |
|----------|--------|--------|--------|
| **Основное предназначение** | НСИ, реестры | Регистрация событий, документальное подтверждение | Характеристика процессов и состояния |
| **Отслеживание состояния** | Не требуется | Регистрация к учёту, отмена, движения | Не требуется |
| **Иерархия, группировка** | Требуется | Не требуется | Не требуется |
| **Ключевые свойства** | Наименование, код | Дата, номер | Не требуется |
| **Доп. реквизиты** | Редко изменяемые | Ссылки и параметры события | Значения для других объектов |
| **Нумерация** | Серии кодов по типу или иерархии | Серии номеров по типу или периоду | Не требуется |

## 5. Выбор типа объекта внутри блока

### 5.1. Блок 1: Условно-постоянная информация

#### Специализированные объекты (управляемое/обычное приложение)

| Условие | Тип объекта |
|---------|-------------|
| Учёт по принципам двойной записи | **План счетов** |
| Учёт начислений и удержаний | **План видов расчета** |
| Список характеристик, определяемых пользователем | **План видов характеристик** |

#### Общие объекты

| Условие | Тип объекта |
|---------|-------------|
| Одиночное значение, редактируемое администратором | **Константа** |
| Фиксированный список, не редактируемый пользователем | **Перечисление** |
| Всё остальное | **Справочник** |

#### Подробные критерии

| Критерий | Константа | Перечисление | ПВХ | Справочник |
|----------|-----------|--------------|-----|------------|
| **Назначение** | Одиночные значения | Неизменный список | Характеристики сущностей | Список объектов с атрибутами |
| **Редактирование** | Только значение | Нет | Полное | Полное |
| **Иерархия** | Нет | Нет | В пределах сущности | Да, включая между сущностями |
| **Доп. реквизиты** | Нет | Нет | Да | Да |
| **Табличные части** | Нет | Нет | Да | Да |
| **Ввод на основании** | Нет | Нет | Да | Да |
| **Нумерация** | Нет | Нет | Серии кодов | Серии кодов |

### 5.2. Блок 2: События процессов предметной области

#### Специализированные объекты (управляемое/обычное приложение)

| Условие | Тип объекта |
|---------|-------------|
| Одиночные события, адресованные исполнителю, без движений | **Задача** |
| Регулярный процесс из последовательности действий | **Бизнес-процесс** (+ Задача) |

#### Общий объект

| Условие | Тип объекта |
|---------|-------------|
| Всё остальное | **Документ** |

#### Подробные критерии

| Критерий | Задача | Бизнес-процесс | Документ |
|----------|--------|----------------|----------|
| **Назначение** | Одиночные события исполнителям | Последовательность событий | Регистрация событий, движения |
| **Вложенность** | Нет | Иерархия задач | Нет |
| **Журналы** | Нет | Нет | Объединение в журналы |
| **Состояния** | Новый, Выполнено | Новый, В работе, Завершён | Проведён, Не проведён |
| **Нумерация** | По виду или периоду | По виду или периоду | Сквозная или по периоду |

### 5.3. Блок 3: Накопленные сведения и показатели

#### Специализированные объекты (управляемое/обычное приложение)

| Условие | Тип объекта |
|---------|-------------|
| Учёт по принципу двойной записи | **Регистр бухгалтерии** |
| Результаты расчёта начислений и удержаний | **Регистр расчета** |

#### Общие объекты

| Условие | Тип объекта |
|---------|-------------|
| Изменения показателей (приход/расход), остатки и обороты | **Регистр накопления** |
| Всё остальное | **Регистр сведений** |

#### Подробные критерии

| Критерий | Регистр накопления | Регистр сведений |
|----------|-------------------|------------------|
| **Назначение** | Изменения данных (приход/расход) | Наборы записей, сведения |
| **Получение данных** | Остатки, обороты | Срез на момент времени, текущие значения |
| **Связь с документом** | Обязательна | Не обязательна |

## 6. Пример выбора типа объекта

**Задача:** Организация занимается периодическим анкетированием. При заполнении указывается дата. Анкета содержит вопросы, результат — ответы.

**Анализ:**
1. Сущность «Анкета» привязана к дате
2. Порождает статистику — ответы на вопросы

**Решение:**
1. Периодическое событие, привязано к дате, порождает параметры → **Блок 2** (события)
2. Анкета формирует вторичные данные (результаты ответов) → **Документ**
