# #std769 Поставка международной версии конфигурации

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

> Применим для локализуемых конфигураций (и входящих в них библиотек), на базе которых выпускаются национальные прикладные решения для различных стран или регионов.

---

## Общие положения

Для упрощения работы локализаторов при первичной локализации и последующих обновлениях следует выпускать **международную версию** конфигурации, подготовленную для создания национальных версий.

Разработку локализованных версий рекомендуется вести на базе международной версии.

Все требования группы стандартов «Требования по локализации» одинаково применимы к обеим версиям. Национальные версии также могут поставляться с интерфейсами на нескольких языках.

**Пример:** ERP для России с англоязычным интерфейсом для иностранцев в одной ИБ с русскоговорящими пользователями.

---

## 1. Выделение национальной специфики

Национальную (российскую) специфику в программном коде и формах необходимо выделить в **отдельные объекты метаданных**, которые должны отсутствовать в международной версии.

**Неправильно:** форма загрузки классификатора внутри справочника `КлассификаторБанковРФ`

**Правильно:** справочник `КлассификаторБанков` + отдельная обработка `ЗагрузкаКлассификатораБанков`

### 1.1. Реквизиты национальной специфики

Реквизиты объектов, относящиеся к национальной специфике, рекомендуется **оставлять в объектах**, но обеспечить работоспособность конфигурации в случае их удаления.

### 1.2. Элементы форм

В формах, где к национальной специфике относится лишь часть элементов, рекомендуется выносить такие элементы в **отдельную форму**.

**Пример:** форма валюты с кнопкой «Параметры прописи валюты», открывающей отдельную форму для настройки склонений.

### 1.3. Алгоритмы

К национальной специфике могут относиться и алгоритмы (например, загрузка курсов валют). Их также следует выделять в отдельных объектах метаданных.

### 1.4. Модули с постфиксом Локализация

Когда подсистема или объект в большей части является международным, но есть необходимость реализации национальной специфики — создавать общие модули с постфиксом **Локализация**.

**Правила:**
- Процедуры размещать в области **ПрограммныйИнтерфейс**
- В международной поставке модули **Локализация** не должны содержать прикладного кода
- В национальной конфигурации код обрамлять комментариями `// Локализация` и `// Конец Локализация`

**Пример в национальной конфигурации:**

```1c
Процедура ПриОпределенииСимволовНациональногоАлфавита(СимволыНациональногоАлфавита, ДополнительныеДопустимыеСимволы) Экспорт

  // Локализация
  СимволыНациональногоАлфавита = "абвгдеёжзийклмнопрстуфхцчшщъыьэюя";
  // Конец Локализация

КонецПроцедуры
```

**В международной поставке:**

```1c
Процедура ПриОпределенииСимволовНациональногоАлфавита(СимволыНациональногоАлфавита, ДополнительныеДопустимыеСимволы) Экспорт

КонецПроцедуры
```

### Правильное использование модулей Локализация

❌ **Неправильно** — обрамлять код национальной специфики в обычных модулях:

```1c
Функция АдресВОблачномСервисе(Сервис, Href) Экспорт

  АдресОбъекта = "";

  Если Сервис = "Box" Тогда
    АдресОбъекта = "https://app.box.com/files/0/";
  // Локализация
  ИначеЕсли Сервис = "Yandex" Тогда
    АдресОбъекта = "https://disk.yandex.ru/client/disk/";
  // Конец Локализация
  ИначеЕсли Сервис = "Dropbox" Тогда
    АдресОбъекта = "https://www.dropbox.com/home/";
  КонецЕсли;

  Возврат АдресОбъекта + Href;

КонецФункции
```

✅ **Правильно** — делегировать в модуль Локализация:

```1c
Функция АдресВОблачномСервисе(Сервис, Href) Экспорт

  АдресОбъекта = "";

  Если Сервис = "Box" Тогда
    АдресОбъекта = "https://app.box.com/files/0/";
  ИначеЕсли Сервис = "Dropbox" Тогда
    АдресОбъекта = "https://www.dropbox.com/home/";
  Иначе
    РаботаСФайламиЛокализация.ПриОпределенииАдресаОблачногоСервиса(Сервис, АдресОбъекта);
  КонецЕсли;

  Возврат АдресОбъекта + Href;

КонецФункции
```

В общем модуле **РаботаСФайламиЛокализация**:

```1c
Процедура ПриОпределенииАдресаОблачногоСервиса(Сервис, АдресОбъекта)

  // Локализация
  Если Сервис = "Yandex" Тогда
    АдресОбъекта = "https://disk.yandex.ru/client/disk/";
  КонецЕсли;
  // Конец Локализация

КонецПроцедуры
```

### 1.5. Подсистемы целиком

Когда национальная специфика занимает большую часть подсистемы — относить к национальной специфике **всю подсистему**.

**Пример:** подсистема «Склонение представлений объектов» целиком является национальной спецификой.

### 1.6. Файл ЛокализуемыеОбъекты

Перечислить объекты метаданных, содержащих национальную специфику, в файле **ЛокализуемыеОбъекты\<...\>.txt** и включить его в дистрибутив.

**Формат:** имена объектов как возвращает `ОбъектМетаданных.ПолноеИмя()`, каждое с новой строки.

**Пример:**

```
// Банки
Обработка.ЗагрузкаКлассификатораБанков
РегламентноеЗадание.ЗагрузкаКлассификатораБанков
Справочник.КлассификаторБанков.Реквизит.ИНН

// Валюты
Обработка.ЗагрузкаКурсовВалют
РегламентноеЗадание.ЗагрузкаКурсовВалют
```

## 2. Юзабилити

Удобство пользовательского интерфейса **не должно страдать** при выделении специфики.

Если юзабилити формы значительно ухудшается при выносе части в отдельные формы — рекомендуется **всю форму** относить к национальной специфике.

## 3. Переопределяемые модули

В процедурах переопределяемых модулей допустимо помещать **только вызовы процедур** конфигурации.

❌ **Неправильно:**

```1c
// В модуле ВариантыОтчетовПереопределяемый

Процедура ОпределитьРазделыСВариантамиОтчетов(Разделы) Экспорт
  Разделы.Добавить(ВариантыОтчетовКлиентСервер.ИдентификаторНачальнойСтраницы(),
    НСтр("ru = 'Главное'"));

  Разделы.Добавить(Метаданные.Подсистемы.CRMИМаркетинг,
    НСтр("ru= 'Отчеты по CRM и маркетингу'"));
  // ...
КонецПроцедуры
```

✅ **Правильно:**

```1c
// В модуле ВариантыОтчетовПереопределяемый

Процедура ОпределитьРазделыСВариантамиОтчетов(Разделы) Экспорт
  ВариантыОтчетовУТ.ОпределитьРазделыСВариантамиОтчетов(Разделы);
КонецПроцедуры

// В модуле ВариантыОтчетовУТ

Процедура ОпределитьРазделыСВариантамиОтчетов(Разделы) Экспорт
  Разделы.Добавить(ВариантыОтчетовКлиентСервер.ИдентификаторНачальнойСтраницы(),
    НСтр("ru = 'Главное'"));

  Разделы.Добавить(Метаданные.Подсистемы.CRMИМаркетинг,
    НСтр("ru= 'Отчеты по CRM и маркетингу'"));
  // ...
КонецПроцедуры
```

## 4. Работоспособность международной версии

Необходимо обеспечивать **работоспособность** международной конфигурации.

---

## 5. Синхронный выпуск версий

Следует выпускать международную и российскую версии **синхронно**.

### Схемы разработки

**Схема A:** Единое хранилище
- Разработка российской версии в одном хранилище
- Автоматическое изготовление международной версии при сборке
- Удаление объектов российской специфики и кода в модулях `Локализация`

**Схема B:** Два хранилища
- Российская версия на поддержке у международной
- Российская специфика в добавляемых объектах и модулях `Локализация`

### Для локализаторов

**На базе международной версии:**
1. Поставить национальную конфигурацию на поддержку международной
2. Добавить объекты из файла `ЛокализуемыеОбъекты<…>.txt` (образец — российская версия)
3. Вписать реализацию в модули `Локализация`

**На базе российской версии:**
1. Поставить национальную конфигурацию на поддержку российской
2. Снять с поддержки и локализовать объекты из `ЛокализуемыеОбъекты<…>.txt`
3. Снять с поддержки и локализовать модули `Локализация`

## Сводка

| Элемент | Международная версия | Национальная версия |
|---------|---------------------|---------------------|
| Объекты национальной специфики | Отсутствуют | Присутствуют |
| Модули `Локализация` | Пустые процедуры | Код в `// Локализация ... // Конец Локализация` |
| Файл `ЛокализуемыеОбъекты.txt` | В дистрибутиве | В дистрибутиве |

| Правило | Описание |
|---------|----------|
| Выделение специфики | В отдельные объекты метаданных |
| Модули Локализация | Для доопределения поведения |
| Юзабилити | Не должно страдать |
| Переопределяемые модули | Только вызовы, без кода |
