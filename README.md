# MCP 1C Standards

Минимальный Python MCP-сервер для качественного поиска по стандартам разработки 1С.

## Источник данных

Сервер читает только markdown-стандарты:

```text
C:\projects\1c-tools\1c-docs\standards
```

## Что сервер делает

- `search_standards` - ищет стандарты по смыслу запроса через Qwen3 Embedding и, кроме режима `fast`, пересортировывает кандидатов через Qwen3 Reranker.
- `read_standard` - читает конкретный `.md` стандарт.
- `list_standards` - показывает список доступных стандартов.

Автообучения, feedback-базы, синтакс-помощника и EDT-контура здесь нет.

## Общий процесс и память

Редакторы по-прежнему запускают `server.py` через stdio. Каждый такой процесс служит лёгким
MCP-прокси и передаёт вызовы общему рабочему процессу через локальный HTTP. Настройки
подключения в редакторах менять не требуется.

Общий процесс запускается автоматически при первом вызове. `list_standards` и
`read_standard` не импортируют `sentence_transformers` и не загружают модели; embedding
и reranker создаются лениво при поиске, которому они нужны. После 300 секунд простоя
рабочий процесс полностью завершается и освобождает загруженные модели. Следующий вызов
автоматически запускает его снова; первый поиск после простоя может занять больше времени.
Дисковый embeddings-кэш сохраняется.

Рядом с каталогом сервера должен находиться общий runtime:

```text
C:\projects\1c-tools\mcp-1c-standards\server.py
C:\projects\1c-tools\mcp-shared-runtime\shared_runtime.py
```

Время простоя задаётся переменной `ONEC_SHARED_IDLE_SECONDS` (по умолчанию `300`).
`ONEC_SHARED_RUNTIME_DIR` задаёт каталог служебных файлов общего процесса; это отдельный
каталог, не заменяющий `ONEC_STANDARDS_CACHE_DIR` с embeddings.

## Режимы поиска

`search_standards` принимает параметр `mode`:

| mode | Что делает | Когда использовать |
|---|---|---|
| `fast` | Semantic search top-12 без reranker | Быстрый первичный поиск. |
| `normal` | Semantic top-12 + Qwen3 Reranker | Режим по умолчанию для разработки. |
| `deep` | Semantic top-30 + Qwen3 Reranker | Сложные задачи и внимательное ревью. |

Параметры `candidate_limit` и `use_reranker` можно передать вручную, если нужно временно переопределить режим.

## Кэш

Embeddings стандартов сохраняются в технический кэш:

```text
C:\projects\1c-tools\mcp-1c-standards\.cache
```

В кэше лежат:

- `embeddings.npy` - векторы фрагментов стандартов.
- `manifest.json` - список файлов, размеры, даты изменения и модель.

В новом экземпляре индекса перед использованием дискового кэша сравнивается manifest: каталог корпуса, имя embedding-модели, инструкция поиска, количество фрагментов и имена/размеры/время изменения файлов. Ревизия весов и версии библиотек в manifest не записаны.

**Ограничения текущей реализации:** уже загруженный индекс не перепроверяет изменения документов; запись двух файлов кэша не является транзакционной; восстановление после повреждения массива и проверка его формы/конечных значений неполны. Изменение документа во время вычисления embeddings также может связать старые векторы с новыми метаданными файла. Эти дефекты ещё не исправлены.

Рабочий кэш не удалять и не пересобирать без отдельного согласования: пересчёт может потребовать загрузки моделей, времени и памяти. Ошибку чтения кэша нельзя обходить включением небезопасного pickle.

## Модели

По умолчанию используются:

```text
Qwen/Qwen3-Embedding-0.6B
Qwen/Qwen3-Reranker-0.6B
```

Реальный поиск, включая `fast`, загружает embedding-модель и может обращаться к Hugging Face за весами. Наличие локального кэша само по себе не гарантирует offline-режим. Использование настоящих моделей и политика сети согласуются отдельно.

## Переменные окружения

Путь к стандартам:

```powershell
$env:ONEC_STANDARDS_DIR = "C:\projects\1c-tools\1c-docs\standards"
```

Путь к кэшу:

```powershell
$env:ONEC_STANDARDS_CACHE_DIR = "C:\projects\1c-tools\mcp-1c-standards\.cache"
```

Embedding-модель:

```powershell
$env:ONEC_STANDARDS_EMBEDDING_MODEL = "Qwen/Qwen3-Embedding-0.6B"
```

Reranker-модель:

```powershell
$env:ONEC_STANDARDS_RERANKER_MODEL = "Qwen/Qwen3-Reranker-0.6B"
```

Инструкция для поиска:

```powershell
$env:ONEC_STANDARDS_QUERY_INSTRUCTION = "Given a Russian 1C:Enterprise development task or code review question, retrieve relevant passages from 1C development standards that help solve or review the task."
```

## Изолированные проверки без моделей

Из корня проверяемой рабочей копии:

```powershell
& "C:\projects\1c-tools\mcp-1c-standards\.venv\Scripts\python.exe" -I -S -B .\tests\run_isolated.py
```

Используется уже установленный NumPy; пакеты не устанавливаются. Флаги обязательны: запуск изолирован, `.pth` / `sitecustomize` не обрабатываются, bytecode-кэш не записывается. Скрипт явно добавляет путь к пакетам выбранного Windows-venv, не запуская обработчики site.

- Проверки индекса используют синтетические Markdown-документы, временный кэш и детерминированные подставные embedding/reranker.
- Контракт трёх инструментов проверяется через AST: модуль сервера и общий runtime не импортируются. Это не проверка реального MCP-протокола или совместимости SDK.
- Python-level защита запрещает импорт библиотек моделей, сетевые операции, дочерние процессы, чтение за пределами разрешённых каталогов и запись вне временных fixtures. Это защита доверенных тестов, а не системная песочница для произвольного нативного кода.
- Четыре самопроверки защиты используют синтетические audit-события и прямую проверку импортного фильтра: они не пытаются реально создать файл вне fixtures, подключиться к сети или запустить процесс.
- Контролируются неизменность кода сервера/индекса/зависимостей, источник импортированного NumPy, отсутствие библиотек моделей и удаление временных fixtures. Настройки окружения изменяются только в тестовом процессе.

Коды завершения: `0` — проверки этого набора прошли без пропусков и известных сбоев; `1` — неожиданный сбой, изменение исходников либо нарушение защиты; `2` — воспроизведены известные неисправленные дефекты или есть пропуски покрытия; `3` — неверный способ запуска/отсутствующее окружение. `OK (expected failures=...)` в выводе unittest не означает исправность индекса: обёртка выводит эти случаи отдельно и возвращает `2`. Неожиданно успешный тест с отметкой expectedFailure требует пересмотра отметки и завершает прогон кодом `1`.

Тесты на символические ссылки используют только собственный временный каталог; при отсутствии системной поддержки/привилегии соответствующие случаи явно пропускаются. Чтение реального корпуса, проверка настоящих моделей, WMI/HTTP-workers, MCP `initialize` / `tools/list`, нагрузка и подключение Harness в этот набор не входят. Для них требуется отдельный согласованный этап.
