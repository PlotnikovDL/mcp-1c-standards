# #std474 Имя, синоним, комментарий

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Синоним

### 1.1. Общие требования

**Синоним** объекта должен быть определён так, чтобы **осмысленно и лаконично** описывать объект. Заполняется **обязательно**.

Синонимы участвуют в формировании пользовательского интерфейса (формы, отчёты, командный интерфейс). Требование распространяется на:
- Объекты метаданных
- Реквизиты объектов
- Табличные части и их реквизиты
- Измерения, ресурсы регистров
- Другие объекты с синонимом

**Пример:**
| Неправильно | Правильно |
|-------------|-----------|
| Что | Предмет контроля |

### 1.2. Сокращения

⛔ Не рекомендуется использовать сокращения в синонимах.

✅ **Исключения:**
- Общеупотребительные сокращения: `Сумма (регл.)`
- Аббревиатуры: `НДС`, `МСФО`

### 1.3. Терминология

Должны использоваться **общепринятые термины**, понятные пользователю.

⛔ **Запрещено:**
- Сленг
- Искажение названий продуктов и компаний
- Англоязычные фразы русскими буквами
- Русскоязычные фразы английскими буквами

**Пример:**
| Неправильно | Правильно |
|-------------|-----------|
| Загрузка данных из Эксель | Загрузка данных из Microsoft Excel |
| Загрузка данных из MS Excel | Загрузка данных из Microsoft Excel |

### 1.4. Стандартные реквизиты

Для стандартных реквизитов (стандартных табличных частей) следует указывать синонимы исходя из **прикладного смысла** каждого реквизита.

### 1.5. Родитель и Владелец

Для стандартных реквизитов **Родитель** и **Владелец** следует **всегда** указывать синонимы, отличные от синонимов по умолчанию.

**Пример:** Справочник `Файлы` со стандартным реквизитом `Владелец` типа `СправочникСсылка.ПапкиФайлов`:

| Неправильно | Правильно |
|-------------|-----------|
| Владелец (по умолчанию) | Папка |
| | Папка с файлом |

**Другие примеры:**
| Справочник | Стандартный реквизит | Синоним |
|------------|---------------------|---------|
| Файлы | Наименование | Имя файла |
| ФизическиеЛица | Наименование | ФИО |

### 1.6. Схожие объекты

Когда есть два или более объекта со схожим назначением, синонимы должны **полностью** описывать каждый объект.

**Пример со справочниками:**
| Неправильно | Правильно |
|-------------|-----------|
| Банковские счета | Банковские счета организаций |
| Банковские счета контрагентов | Банковские счета контрагентов |

**Пример с реквизитами** (табличная часть «Товары» документа «Пересчет товаров»):
| Неправильно | Правильно |
|-------------|-----------|
| Количество | Количество (в наличии) |
| Количество (по учету) | Количество (по учету) |

**Пример со стандартным реквизитом** (справочник «Номенклатура»):
| Неправильно | Правильно |
|-------------|-----------|
| Наименование | Рабочее наименование |
| Полное наименование | Наименование для печати |

## 2. Имя

### 2.1. Формирование имени из синонима

**Имя** объекта рекомендуется строить на основе синонима:
- Удалить пробелы и недопустимые символы
- Первые буквы слов — прописные

**Примеры:**
| Неправильно | Правильно |
|-------------|-----------|
| Справочник «Дополнительные свойства» → `НаборыДополнительныхРеквизитовИСведений` | Справочник «Наборы дополнительных реквизитов и сведений» → `НаборыДополнительныхРеквизитовИСведений` |
| Команда «Файлы присоединенные» → `ПрисоединенныеФайлы` | Команда «Присоединенные файлы» → `ПрисоединенныеФайлы` |

**Допустимые сокращения имени:**
- `Длительность ожидания сервера (сек)` → `ДлительностьОжиданияСервера`
- `Количество единиц измерения` → `КоличествоЕдиниц`
- `Значение скидки или наценки` → `ЗначениеСкидкиНаценки`

### 2.2. Исключения

- Объекты с префиксом **Удалить** (см. #std534)
- Объекты с требованиями обратной совместимости (библиотеки)

### 2.3. Длина имени

Имена объектов метаданных **не должны превышать 80 символов**.

### 2.4. Имена подчинённых объектов

⛔ Не использовать имена, совпадающие с именами объектов-владельцев.

**Пример:** Регистр сведений `ИсполнителиЗадач`, измерение типа `СправочникСсылка.Пользователи`:
| Неправильно | Правильно |
|-------------|-----------|
| Пользователь | Исполнитель |

### 2.5. Зарезервированные имена

⛔ Не использовать имена таблиц языка запросов: `Документ`, `Справочник`, `РегистрСведений` и т.д.

**Причина:** Ошибки при выполнении запросов, затруднения в конструкторе запросов.

```1c
// Ошибка выполнения:
ВЫБРАТЬ
    Сведения.Сведения
ИЗ
    РегистрСведений.Сведения КАК Сведения
```

## 3. Комментарий

### 3.1. Когда использовать

**Комментарий** задаётся только когда необходимо дать участнику разработки пояснения по объекту.

**Примеры комментариев:**
- `Индексирование поставлено для оптимизации отчетов с отбором по виду контрагента`
- `Используется в регламентированном учете`

### 3.2. Оформление

- Начинается с **прописной буквы**
- Точки ставятся **только после сокращений**

---

## 4. Буква «ё»

⛔ В именах, синонимах и комментариях **не допускается** использовать букву «ё».
