# #std541 Уточнение сущности объекта метаданных

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Разные типы объектов для разных сущностей

При описании структуры прикладного решения следует использовать **разные типы объектов метаданных** для реализации разных по смыслу сущностей.

**Пример:**
- Сущность «организации» → справочник **Организации**
- Сущность «подразделение» → справочник **Подразделения**

---

## 2. Уточнение сущности через реквизиты

Для уточнения сущности объекта у него могут быть заведены реквизиты, в зависимости от значения которых меняется его **смысловая нагрузка и поведение**.

**Примеры:**
- В справочнике **Организации** — «обычные» организации и обособленные подразделения
- В справочнике **Сотрудники** — принятые на работу и уволенные сотрудники

---

## 3. Рекомендация: явные реквизиты вида/состояния

✅ Рекомендуется заводить **отдельные реквизиты**, которые однозначно определяют вид или состояние объекта:
- Реквизиты типа **Булево**
- Перечисления с видами объекта

⛔ **Не следует** трактовать вид объекта по косвенным признакам (в зависимости от заполнения того или иного реквизита).

---

## 4. Пример: справочник Организации

### Неправильно

Заводить реквизит **ГоловнаяОрганизация**, в зависимости от заполнения которого прикладная логика трактует вид организации — «обычная» или обособленное подразделение.

```1c
// Неправильно: определение вида по косвенному признаку
Если ЗначениеЗаполнено(Организация.ГоловнаяОрганизация) Тогда
    // Это обособленное подразделение
КонецЕсли;
```

### Правильно

Помимо реквизита **ГоловнаяОрганизация**, завести булев реквизит **ОбособленноеПодразделение**, в зависимости от значения которого (`Истина` или `Ложь`) однозначно трактуется вид организации.

```1c
// Правильно: явный реквизит вида
Если Организация.ОбособленноеПодразделение Тогда
    // Это обособленное подразделение
    // Реквизит ГоловнаяОрганизация должен быть заполнен
КонецЕсли;
```

---

## 5. Исключение: несколько состояний

Если у справочника **Сотрудники** имеются реквизиты **ДатаПриема** и **ДатаУвольнения**, то введение пары реквизитов булево типа **ПринятНаРаботу** и **Уволен** **не оправдано**.

✅ Для сущностей с несколькими состояниями целесообразно завести **один реквизит типа перечисление** со статусами.

**Пример:**

```1c
// Перечисление СтатусыСотрудников
// Значения: Работает, Уволен, (можно расширить)

Если Сотрудник.Статус = Перечисления.СтатусыСотрудников.Уволен Тогда
    // Сотрудник уволен
КонецЕсли;
```

---

## 6. Сводная таблица

| Ситуация | Рекомендация |
|----------|--------------|
| Два варианта (да/нет) | Реквизит типа **Булево** |
| Несколько вариантов | Реквизит типа **Перечисление** |
| Определение по косвенным признакам | ⛔ Не рекомендуется |
| Разные по смыслу сущности | Разные объекты метаданных |
