# #std485 Использование привилегированного режима

> Область применения: управляемое приложение, обычное приложение.

---

## 1. Назначение привилегированного режима

### 1.1. Что позволяет

- Выполнить операции с данными от лица пользователей, которым данные недоступны
- Ускорить работу (не накладываются ограничения на доступ к данным)

### 1.2. Когда использовать

- Когда требуется с логической точки зрения **отключить проверку прав**
- Когда допустимо отключить проверку прав для **ускорения работы** и при этом работа с данными логически не нарушает установленные права пользователя

---

## 2. Типовые сценарии использования

### 2.1. Подчинённые регистры (движения документов) для отчётов

Если регистры требуются пользователю для отчётов:
- Регистры оставить доступными **только для чтения**
- Запись в регистры выполнять в привилегированном режиме
- Проверка прав выполняется только для регистратора

**Пример:**
- `Документ.ОприходованиеТоваров`
- `РегистрНакопления.ОстаткиНаСкладах`
- `Отчет.ОстаткиНаСкладах`

Документ делает движения по регистру в привилегированном режиме. Пользователю дать только право чтения регистра.

### 2.2. Регистры, не нужные пользователю

Если регистры не требуются ни для отчётов, ни в командном интерфейсе:
- **Не давать** пользователю права на чтение
- Чтение/запись выполнять в привилегированном режиме

**Пример:** регистр сведений `ВерсииПодсистем` — доступ только через функции общего модуля.

### 2.3. Недоступные данные для разрешённой операции

Если для разрешённой операции требуются недоступные данные:
- Получать их в привилегированном режиме
- **Гарантировать** предотвращение передачи данных на клиент
- **Гарантировать** использование только для запланированной операции

**Пример:**
- Проведение документа от лица кладовщика изменяет регистр продаж (недоступный кладовщику)
- При проведении проверяется состояние взаиморасчётов (недоступных кладовщику)

### 2.4. Повышение производительности

Допустимо использовать привилегированный режим для ускорения, если это **не приводит** к выполнению неразрешённых действий или получению недоступных данных.

**Пример 1:** значения параметров отбора запроса уже прошли проверку RLS — сам запрос можно выполнить в привилегированном режиме.

**Пример 2:** параметр сеанса «Текущий пользователь» недоступен ни в одной роли:

```1c
Функция ТекущийПользователь() Экспорт
  УстановитьПривилегированныйРежим(Истина);
  Возврат ПараметрыСеанса.ТекущийПользователь;
КонецФункции
```

## 3. Безопасность

### 3.1. Опасность экспортных процедур

⚠️ Потенциально опасны экспортные процедуры/функции, которые выполняют действия с безусловной установкой привилегированного режима — это отключает проверку прав текущего пользователя.

❌ **Неправильно:**

```1c
Процедура ИзменитьИлиУдалитьДанные(...) Экспорт
  УстановитьПривилегированныйРежим(Истина); // Отключаем проверку прав
  // Изменяем данные в привилегированном режиме
  ...
КонецПроцедуры
```

✅ **Правильно:**

```1c
Процедура ИзменитьИлиУдалитьДанные(...) Экспорт
  // Изменяем данные
  // (при недостатке прав будет вызвано исключение)
  ...
КонецПроцедуры
```

**Исключение:** действие разрешено абсолютно всем категориям пользователей.

### 3.2. Проверка прав перед привилегированным режимом

При обращении с недостаточным уровнем прав должно вызываться **исключение**. Обычно это происходит автоматически:
- При выполнении запроса без `РАЗРЕШЕННЫЕ`
- При вызове `ПолучитьОбъект()` для недоступной ссылки
- При вызове недоступного метода глобального контекста

Для ручной проверки: метод **`ВыполнитьПроверкуПравДоступа`**.

```1c
Процедура ИзменитьИлиУдалитьДанные(...) Экспорт
  ВыполнитьПроверкуПравДоступа(...); // Если нет прав — исключение
  УстановитьПривилегированныйРежим(Истина);
  // Изменяем данные в привилегированном режиме
  ...
КонецПроцедуры
```

### 3.3. Точечное включение

Включать привилегированный режим **точечно**, чтобы остальной код не терял возможности проверки прав.

❌ **Неправильно:**

```1c
Процедура ПодготовитьДанные()
  УстановитьПривилегированныйРежим(Истина);
  // Код подготовки запроса (требуется проверка прав)
  // Код выполнения запроса
  Выборка = Запрос.Выполнить().Выбрать();
  // Обработка результатов (требуется проверка прав)
```

✅ **Правильно:**

```1c
Процедура ПодготовитьДанные()
  // Код подготовки запроса

  УстановитьПривилегированныйРежим(Истина);
  Выборка = Запрос.Выполнить().Выбрать();
  УстановитьПривилегированныйРежим(Ложь);

  // Обработка результатов запроса
```

## 4. Способы перехода в привилегированный режим

| Способ | Применение |
|--------|------------|
| Свойства документа «Привилегированный режим при проведении» и «Привилегированный режим при отмене проведения» | Обработчики `ОбработкаПроведения`, `ОбработкаУдаленияПроведения` |
| Свойство бизнес-процесса «Привилегированный режим» | Создание задач |
| Свойство «Привилегированный режим при получении» | Функциональные опции |
| `УстановитьПривилегированныйРежим(Истина/Ложь)` | Произвольное место любого модуля |
| Свойство общего модуля «Привилегированный» | Все процедуры и функции модуля |

### Использование УстановитьПривилегированныйРежим

```1c
УстановитьПривилегированныйРежим(Истина)
// фрагмент кода в привилегированном режиме
// …
УстановитьПривилегированныйРежим(Ложь)
```

### Когда снимать свойства документа

Если логика проведения работает с выборкой данных, состав которой **должен ограничиваться** для пользователя — снять свойства документа и использовать `УстановитьПривилегированныйРежим`.

## Сводка

| Сценарий | Рекомендация |
|----------|--------------|
| Движения документов для отчётов | Регистры — только чтение, запись в привилегированном режиме |
| Технические регистры | Не давать прав, работать в привилегированном режиме |
| Недоступные данные для операции | Привилегированный режим с гарантией безопасности |
| Повышение производительности | Только если не нарушает права |
| Экспортные процедуры | Не устанавливать привилегированный режим безусловно |
| Включение режима | Точечно, с немедленным отключением после операции |
