# MCP 1C Standards

Локальный MCP-сервер для поиска по стандартам разработки 1С. Редактор или ИИ-агент может найти правило по задаче, прочитать стандарт целиком и дать ссылку на оригинал ИТС. В репозитории есть сервер, тексты стандартов и иллюстрации.

## Установка по ссылке

Если у ИИ-агента есть доступ к терминалу и настройкам редактора, ему можно передать такую задачу.

> Установи https://github.com/PlotnikovDL/mcp-1c-standards по README в отдельное окружение Python. Подключи сервер к моему MCP-клиенту, проверь поиск «Поиск в коллекциях значений» и прочитай найденный `std452.md` через инструменты клиента.

Понадобятся Git, Python 3.11 или новее с `venv` и MCP-клиент с транспортом stdio. Для установки пакетов нужен доступ к PyPI, для загрузки моделей - к Hugging Face. Веса двух моделей по умолчанию занимают около 2,4 ГБ на диске, дополнительно потребуется место для окружения Python. Процессу сервера нужны права на запись в `.cache` репозитория и в кэш моделей Hugging Face. Сервер работает без учётной записи и API-ключа. Основная проверенная среда - Windows.

### Windows PowerShell

Выполните команды в каталоге, где будет храниться репозиторий. Команда `python --version` должна показать версию 3.11 или новее.

```powershell
git clone https://github.com/PlotnikovDL/mcp-1c-standards.git
cd mcp-1c-standards
python --version
python -m venv .venv
$standardsPython = (Resolve-Path .\.venv\Scripts\python.exe).Path
& $standardsPython -m pip install -r requirements.txt
& $standardsPython -m pip check
& $standardsPython scripts/verify_mcp.py
& $standardsPython scripts/verify_mcp.py --query "Поиск в коллекциях значений" --expect-file std452.md --mode normal
```

### Linux и macOS

Для оболочки POSIX используются `python3` и каталог `.venv/bin`.

```sh
git clone https://github.com/PlotnikovDL/mcp-1c-standards.git
cd mcp-1c-standards
python3 --version
python3 -m venv .venv
standards_python="$(pwd -P)/.venv/bin/python"
"$standards_python" -m pip install -r requirements.txt
"$standards_python" -m pip check
"$standards_python" scripts/verify_mcp.py
"$standards_python" scripts/verify_mcp.py --query "Поиск в коллекциях значений" --expect-file std452.md --mode normal
```

Скрипт сам запускает `server.py` через stdio. Первый вызов проверяет `initialize`, список трёх инструментов, каталог стандартов и совпадение прочитанного документа с файлом. Второй загружает модели, при необходимости строит индекс и проверяет наличие `std452.md` среди первых пяти результатов. При проверке в Windows на Ryzen 9 9950X с 12 вычислительными потоками и весами на диске первый индекс из 321 документа (986 фрагментов) построился за 21 минуту. Все режимы используют один индекс. Скрипт отводит на вызов поиска до часа. При успехе он печатает `search_standards OK` и завершается с кодом `0`.

### Подключение к Codex или другому редактору

Для регистрации в Codex CLI из корня репозитория выполните команду для своей оболочки.

**Windows PowerShell**

```powershell
codex mcp add mcp-1c-standards -- (Resolve-Path .\.venv\Scripts\python.exe).Path (Resolve-Path .\server.py).Path
```

**Linux и macOS**

```sh
codex mcp add mcp-1c-standards -- "$(pwd -P)/.venv/bin/python" "$(pwd -P)/server.py"
```

В другом редакторе добавьте в существующие настройки один MCP-сервер с именем `mcp-1c-standards`. Выберите транспорт `stdio`, в `command` укажите абсолютный путь к Python из созданного `.venv`, в `args` передайте один элемент - абсолютный путь к `server.py`. Эти же значения можно посмотреть в Codex командой `codex mcp get mcp-1c-standards`. Сервер запускает сам клиент.

Откройте новую сессию клиента и отправьте сообщение «Через `mcp-1c-standards` вызови `search_standards` с запросом “Поиск в коллекциях значений” в режиме `normal`, затем прочитай `std452.md` через `read_standard` и назови заголовок». Проверьте оба вызова инструментов в журнале клиента. Для документа из комплектного корпуса ожидается заголовок `#std452 Поиск в коллекциях значений`. Если редактор прерывает долгий первый поиск, дождитесь построения индекса скриптом выше. В Codex лимит времени на вызов можно увеличить через `tool_timeout_sec` в существующем разделе `[mcp_servers.mcp-1c-standards]`. [Настройки MCP в Codex](https://developers.openai.com/codex/mcp)

## Инструменты

| Инструмент | Назначение |
|---|---|
| `search_standards(query, mode="normal", limit=5)` | Возвращает подходящие фрагменты, имя файла, заголовок и оценки. Число результатов от 1 до 20. |
| `read_standard(path)` | Читает полный Markdown по имени файла, например `std452.md`. В тексте есть источник ИТС и относительные ссылки на иллюстрации. |
| `list_standards()` | Возвращает имена файлов, пути и заголовки. Поиск и загрузка моделей для этого вызова не нужны. |

По умолчанию в режиме `fast` модель `Qwen/Qwen3-Embedding-0.6B` выбирает 12 кандидатов по смыслу, если в корпусе достаточно фрагментов. В `normal` кандидатов дополнительно оценивает `Qwen/Qwen3-Reranker-0.6B`. В `deep` набор кандидатов увеличивается до 30. Параметры `candidate_limit` и `use_reranker` позволяют изменить эти настройки для одного запроса. `read_standard` и `list_standards` читают файлы без загрузки моделей.

## Корпус и права на материалы

В каталоге `corpus/standards` хранятся 321 документ `std<ID>.md` и 320 иллюстраций в PNG и JPEG. В каждом документе дана прямая ссылка на его оригинал на ИТС. № 788 - журнал изменений стандартов, который 1С ведёт отдельно. [Каталог файлов](corpus/CATALOG.md) · [Формат корпуса](corpus/README.md) · [Журнал изменений на ИТС](https://its.1c.ru/db/v8std/content/788/hdoc)

Исключительные права на материалы ИТС принадлежат ООО «1С». При размещении материалов на другом ресурсе 1С требует ссылку на `its.1c.ru`. Для тиражирования и иного использования материалов в коммерческой деятельности 1С указывает на необходимость разрешения правообладателя. [Условия использования сайта](https://its.1c.ru/docs/terms_of_use) · [Об информационной системе ИТС](https://its.1c.ru/db/content/aboutitsnew/src/%D0%B8%D1%81%201%D1%81%20%D0%B8%D1%82%D1%81.htm)

## Процесс сервера и настройки

Из одного клона сервер работает автономно. Каждый MCP-клиент запускает свой `server.py`, а при первом поиске загружает нужные модели в память своего процесса. Если на компьютере уже есть совместимый `../mcp-shared-runtime/shared_runtime.py`, сервер автоматически передаёт вызовы общему рабочему процессу через локальный HTTP. Тот запускается при первом вызове и по умолчанию завершается после 300 секунд простоя. Дисковый кэш сохраняется в обоих режимах.

Настройки передаются процессу сервера через окружение выбранного клиента.

| Переменная | Для чего нужна |
|---|---|
| `ONEC_STANDARDS_STANDALONE=1` | Выбирает автономный режим даже при наличии соседнего runtime. |
| `ONEC_STANDARDS_DIR` | Задаёт каталог стандартов. По умолчанию `corpus/standards` относительно каталога сервера. |
| `ONEC_STANDARDS_CACHE_DIR` | Задаёт каталог кэша поискового индекса. По умолчанию `.cache` рядом с сервером. |
| `ONEC_STANDARDS_EMBEDDING_MODEL`, `ONEC_STANDARDS_RERANKER_MODEL` | Меняют модель поиска или повторного ранжирования. Для автономной машины можно указать локальные каталоги совместимых моделей. |
| `ONEC_STANDARDS_QUERY_INSTRUCTION` | Заменяет инструкцию, с которой модель обрабатывает поисковый запрос. |
| `ONEC_SHARED_IDLE_SECONDS`, `ONEC_SHARED_RUNTIME_DIR` | В общем режиме задают таймаут простоя и каталог служебных файлов рабочего процесса. |

### Файлы корпуса и кэш

Сервер перечисляет Markdown-файлы верхнего уровня. Он разрешает ссылки на обычные `.md` внутри корпуса и отклоняет ссылки за его пределы. Битая ссылка, каталог или файл другого типа прерывают операцию. В списке и поисковой выдаче сохраняется имя найденной записи, а чтение возвращает имя её разрешённой цели. Проверка рассчитана на доверенный локальный корпус. Она не покрывает конкурентную подмену ссылок и сетевые обращения ОС при разрешении UNC-путей.

Кэш состоит из `manifest.json` со сведениями о корпусе и `embeddings.npy` с векторами. Перед поиском сервер проверяет разрешённые пути, размеры и время изменения файлов. При обнаружении изменений индекс перестраивается. Если состав корпуса меняется во время поиска, сервер возвращает ошибку и предлагает повторить запрос. Модели остаются в памяти процесса.

Manifest версии 1 хранит корень корпуса, модель, инструкцию поиска, количество фрагментов и метаданные файлов. Перенос корпуса делает старый кэш непригодным для нового пути. При чтении NumPy-матрицы отключён pickle. Проверяются тип, число строк, непустая ширина и конечность значений после преобразования в `float32`. Повреждённый массив, архив или некорректный manifest приводят к пересчёту.

Изменение содержимого с теми же путём, размером и временем может остаться незамеченным. Сверка не подтверждает конкретную ширину вектора модели, ревизию весов и версии библиотек. Два файла кэша записываются отдельно. Защита от исчерпания памяти при чтении произвольно больших файлов отсутствует. Удаление рабочего кэша потребует нового расчёта всех векторов.

## Проверки для разработки

Изолированный набор запускается из корня проверяемой копии в Windows PowerShell.

```powershell
& .\.venv\Scripts\python.exe -I -S -B .\tests\run_isolated.py
```

Он использует установленный NumPy, синтетические Markdown-документы и подставные модели. Контракт MCP проверяется по AST. Проверки запрещают импорт библиотек моделей, сетевые вызовы, дочерние процессы, открытие рабочего корпуса и кэша, запись вне временного каталога. Защита действует на уровне Python для доверенного тестового кода. Операции `stat` и `exists` она не отслеживает. Флаги `-I -S -B` обязательны. Обработчики `.pth` и `sitecustomize` при запуске не выполняются.

| Код выхода | Результат изолированного набора |
|---|---|
| `0` | Все проверки прошли без известных сбоев и пропусков. |
| `1` | Неожиданный результат или нарушение изоляции. |
| `2` | Воспроизведён известный дефект (`expectedFailure`) или есть пропуски. |
| `3` | Неверный запуск или отсутствует нужное окружение. |

После изменения рабочего Python-кода отдельно проверьте импорты в подготовленной копии. Запускайте эту проверку без флага оптимизации `-O`. Порядок согласования проверок для сопровождающих описан в [AGENTS.md](AGENTS.md).

```powershell
& .\.venv\Scripts\python.exe -I -S -B .\tests\check_imports.py
```

Проверка импортирует сервер и индекс, проверяет регистрацию трёх инструментов в автономном режиме. При наличии подготовленной соседней копии runtime она дополнительно проверяет импорт общего режима. Скрипт работает из временного каталога с явными путями к установленному pywin32. Вызовы инструментов через настоящий stdio проверяет `scripts/verify_mcp.py` из раздела установки.
