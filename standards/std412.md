# #std412 Упорядочивание результатов запроса

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Когда использовать УПОРЯДОЧИТЬ ПО

### 1.1. Обязательно использовать

Если алгоритм зависит от порядка записей или результат показывается пользователю — используйте `УПОРЯДОЧИТЬ ПО`.

Без `УПОРЯДОЧИТЬ ПО` **невозможно** делать предположения о порядке записей.

**Типичные проблемы** (могут возникать непредсказуемо):
- Разная последовательность строк табличной части
- Разный порядок данных в отчётах
- Разное заполнение движений документа

**Риск повышается при:**
- Переносе ИБ на другую СУБД
- Смене версии СУБД
- Изменении параметров СУБД

⚠️ **Примечание:** упорядочивание движений оправдано только если это часть алгоритма (например, FIFO). Иначе — избыточная нагрузка на СУБД.

### 1.2. Сортировка по полям с NULL

При сортировке по полю, которое может содержать `NULL`, порядок **отличается** в разных СУБД.

❌ **Неправильно:**

```1c
ВЫБРАТЬ
    СправочникНоменклатура.Ссылка КАК НоменклатураСсылка,
    ЗапасыОстатки.КоличествоОстаток КАК КоличествоОстаток
ИЗ
    Справочник.Номенклатура КАК СправочникНоменклатура
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.Запасы.Остатки КАК ЗапасыОстатки
    ПО (ЗапасыОстатки.Номенклатура = СправочникНоменклатура.Ссылка)

УПОРЯДОЧИТЬ ПО
    КоличествоОстаток
```

✅ **Правильно:**

```1c
ВЫБРАТЬ
    СправочникНоменклатура.Ссылка КАК НоменклатураСсылка,
    ЕСТЬNULL(ЗапасыОстатки.КоличествоОстаток, 0) КАК КоличествоОстаток
ИЗ
    Справочник.Номенклатура КАК СправочникНоменклатура
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.Запасы.Остатки КАК ЗапасыОстатки
    ПО (ЗапасыОстатки.Номенклатура = СправочникНоменклатура.Ссылка)

УПОРЯДОЧИТЬ ПО
    КоличествоОстаток
```

### 1.3. Сортировка для пользователя

Если результаты отображаются пользователю:
- Упорядочивайте по полям **примитивных типов**
- Ссылочные типы заменяйте на **строковые представления**

Иначе порядок выглядит для пользователя случайным.

### 1.4. Когда НЕ использовать

`УПОРЯДОЧИТЬ ПО` **не нужен** когда:
- Алгоритм не зависит от порядка
- Результат не показывается пользователю
- Результат — заведомо одна запись

В таких случаях **не добавляйте** `УПОРЯДОЧИТЬ ПО` — это лишние затраты времени.

---

## 2. РАЗЛИЧНЫЕ + УПОРЯДОЧИТЬ ПО

При использовании `РАЗЛИЧНЫЕ` упорядочивайте **только по полям из выборки** (секция `ВЫБРАТЬ`).

**Причина:** поля упорядочивания неявно добавляются в выборку, что может привести к появлению «дубликатов».

---

## 3. АВТОУПОРЯДОЧИВАНИЕ

### 3.1. Запрет

⛔ **Запрещено:** `ПЕРВЫЕ` + `АВТОУПОРЯДОЧИВАНИЕ`

### 3.2. Рекомендация

`АВТОУПОРЯДОЧИВАНИЕ` **не рекомендуется** — разработчик не контролирует поля сортировки.

**Допустимо** только когда:
- Конкретный порядок не важен
- Но порядок должен быть одинаковым на разных СУБД

**Обязательно:** комментарий перед запросом с причиной использования.

---

## 4. Сводка

| Ситуация | Решение |
|----------|---------|
| Алгоритм зависит от порядка | `УПОРЯДОЧИТЬ ПО` обязательно |
| Результат для пользователя | Сортировка по примитивным типам |
| Поле может быть NULL | `ЕСТЬNULL()` |
| Результат одна запись | Без сортировки |
| `РАЗЛИЧНЫЕ` | Только по полям из `ВЫБРАТЬ` |
| `ПЕРВЫЕ` | ⛔ Не с `АВТОУПОРЯДОЧИВАНИЕ` |
