# #std411 Установка параметров выбора и связей параметров выбора

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Общее правило

Ограничения бизнес-логики (ограничения выбора) должны быть **одинаковыми для всех форм**, в которых редактируется тот или иной объект.

Поэтому задавать **параметры выбора** и **связи параметров выбора** рекомендуется в **свойствах объектов метаданных** — в реквизитах справочников, документов и т.п.

---

## 2. Исключение — уточнение в форме

Могут встречаться случаи, когда ограничения выбора зависят от **конкретного сценария работы**. В таких случаях параметры выбора могут быть **уточнены по месту**, в конкретной форме.

---

## Пример

**Исходные данные:**

- Справочник **Сотрудники** с реквизитами:
  - `Организация`
  - `ВидСотрудника` (перечисление: Основной / Совместитель)

- Документ **ПриказОПриеме** с реквизитами:
  - `Организация`
  - `Сотрудник` — для него задана связь параметра выбора `Отбор.Организация` с реквизитом `Организация`

**Задача:** реализовать выбор только основных сотрудников в зависимости от функциональной опции `ВыбратьТолькоИзОсновныхСотрудников`.

**Решение:**

1. В форме документа **ПриказОПриеме** создать дополнительный реквизит формы `ВидыСотрудников`
2. Для поля формы **Сотрудник** установить связь параметра выбора `Отбор.ВидСотрудника` с реквизитом формы `ВидыСотрудников`
3. Реквизит формы `ВидыСотрудников` заполняется на основании анализа функциональной опции

**Результат:** при выборе сотрудника в форме приказа отбор в списке сотрудников будет установлен:

- По организации (из свойств реквизита метаданных)
- По виду сотрудника (из свойств поля формы)

Обе связи параметра выбора будут работать **одновременно**.

---

## Сводка

| Где задавать | Когда использовать |
|--------------|-------------------|
| Свойства реквизита метаданных | Общие ограничения для всех форм |
| Свойства поля формы | Дополнительные ограничения для конкретного сценария |
