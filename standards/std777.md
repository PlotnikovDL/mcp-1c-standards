# #std777 Использование временных таблиц

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.
>
> Раздел ИТС: Реализация обработки данных / Оптимизация запросов
>
> Источник: https://its.1c.ru/db/v8std/content/777/hdoc
>
> Проверено по источнику: 2026-10-07

<a id="1"></a>1\. В общем случае, временные таблицы рекомендуется использовать для повышения производительности и стабильности выполнения запросов. Их можно использовать для других целей (например, для улучшения архитектуры кода), но при этом, нужно понимать, что это может в некоторых случаях приводить к снижению производительности.

<a id="2"></a>2\. Есть ситуации, когда временные таблицы не следует создавать или создание временных таблиц необходимо минимизировать.

<a id="2.1"></a>2.1. Не следует создавать временные таблицы с очень большим объемом данных (сотни тысяч записей). Иначе это приведет к существенному снижению производительности при записи и исчерпанию свободного места на диске. Если алгоритму требуется работать с большим объемом данных, то он должен выполнять обработку этих данных порциями.

<a id="2.2"></a>2.2. Следует максимально ограничивать количество данных, выбираемых во временную таблицу. Не следует помещать во временную таблицу больше данных, чем требуется последующим запросам.

<a id="2.3"></a>2.3. Не следует помещать во временную таблицу поля, которые не используются в последующих запросах, т.к. время и место для их размещения тратится впустую.

<a id="2.4"></a>2.4. Не следует создавать и удалять временные таблицы в цикле, если можно создать одну временную таблицу до выполнения цикла.

<a id="2.5"></a>2.5. Не следует копировать одну временную таблицу в другую только ради того, чтобы переименовать первую таблицу во вторую. Вместо этого, следует передавать имя таблицы.

<a id="3"></a>3\. Временные таблицы следует всегда индексировать, когда это даст прирост производительности.

<a id="3.1"></a>3.1. Индекс следует строить если:

<a id="3.1.1"></a>3.1.1. Большая временная таблица участвует в соединении (не важно, с какой стороны). В индекс следует добавлять поля, участвующие в условии **ПО**.

<a id="3.1.2"></a>3.1.2. Обращение к временной таблице выполняется в подзапросе конструкции логического оператора **В (...)**. В индекс следует добавлять поля временной таблицы из списка выбора, соответствующие перечисленным с левой стороны логического оператора **В (...)**.

> *См. также:* стандарт 652 «[Несоответствие индексов и условий запроса](<https://its.1c.ru/db/v8std/content/652/hdoc>)».

<a id="3.2"></a>3.2. Маленькие временные таблицы индексировать не нужно (менее 1000 записей).

<a id="3.3"></a>3.3. Если условий выбора или соединений с временной таблицей больше одного, и только одно из них проверяется часто, то индекс следует строить для наиболее часто проверяемого условия.
