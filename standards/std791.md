# #std791 Дополнительные индексы

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## Определение

**Дополнительный индекс** — индекс сразу по нескольким полям объекта метаданных с возможностью включения **дополнительных неиндексируемых полей**.

---

## 1. Область применения

| Лицензия | Использование дополнительных индексов |
|----------|---------------------------------------|
| КОРП | ✅ Можно использовать |
| ПРОФ | ❌ Нельзя использовать |

Дополнительные индексы — только для конфигураций, которые могут использоваться на **крупных предприятиях** с КОРП лицензиями.

---

## 2. Требования к производительности

| Объём данных | Требование |
|--------------|------------|
| 100 000 – 1 000 000 записей | Приемлемая производительность **без** дополнительных индексов |
| > 1 000 000 записей | Приемлемая производительность **с** дополнительными индексами |

⚠️ При разработке тестируйте производительность **в обоих режимах** — с включёнными и отключёнными дополнительными индексами.

---

## 3. Приоритет обычных индексов

Если приемлемая производительность достижима **на любом объёме данных** без дополнительных индексов — используйте **обычные индексы**.

---

## 4. Одна ветка кода

✅ **Рекомендуется:** Одна ветка кода с дополнительными индексами.

❌ **Не рекомендуется:** Несколько веток — одна с дополнительными индексами, другая с альтернативными решениями.

### 4.1. Исключение

Альтернативное решение допустимо, если на небольшом объёме данных **невозможно** обеспечить минимальную производительность с отключёнными дополнительными индексами.

**Минимальная производительность:**
- Интерактивные операции (открытие форм списков) — не более **1 секунды**
- Формирование отчётов — замедление не более чем **в 2 раза**

---

## 5. Ключевые и включаемые поля

| Тип поля | Использование в запросах | Рекомендация |
|----------|--------------------------|--------------|
| **Ключевое** (индексируемое) | В условиях `ГДЕ`, `ПО` | Добавить в индекс |
| **Включаемое** (дополнительное) | Только в `ВЫБРАТЬ` (для исключения обращения к таблице) | Сделать включаемым |

✅ Поля, не используемые в условиях, делайте **включаемыми** — это позволит добавить больше ключевых полей при необходимости.

---

## Сводка

| Правило | Описание |
|---------|----------|
| Только КОРП | Дополнительные индексы недоступны в ПРОФ |
| Тестирование | В обоих режимах — с индексами и без |
| Обычные индексы | Приоритет, если достаточно для любого объёма |
| Одна ветка кода | Не дублировать логику для разных режимов |
| Включаемые поля | Для полей только в SELECT |
