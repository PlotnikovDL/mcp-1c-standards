# #std452 Поиск в коллекциях значений

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Индексирование таблиц значений

При двух и более операциях поиска в объекте **ТаблицаЗначений** с большим количеством строк рекомендуется:

- Индексировать колонки, по которым выполняется поиск
- Но только те из них, которые обладают **хорошей селективностью** (т.е. каждому значению этой колонки должно соответствовать небольшое количество строк)

В противном случае индексирование не даст эффекта, либо он будет отрицательным (потрачено лишнее время на индексирование).

> **Примечание:** следует ориентироваться на **1000 строк и более**, а также учитывать не только размер таблицы, но и сколько раз выполняется поиск. Например, даже если таблица относительно небольшая (100 строк), но поиск выполняется 100 раз — её тоже имеет смысл индексировать. В то же время нет смысла индексировать таблицу из-за одной единственной операции поиска.

---

## 2. Методы поиска в таблице значений

Для поиска значений предусмотрены два метода объекта **ТаблицаЗначений**:

- **Найти**
- **НайтиСтроки**

При поиске значения в **одной колонке** оба метода одинаково эффективно используют индекс, если он был задан.

Однако при поиске по **нескольким колонкам** необходимо учитывать следующие ограничения.

### 2.1. Метод Найти — не использует индекс при поиске по нескольким колонкам

**Не следует** использовать метод **Найти** для поиска по нескольким колонкам в больших таблицах, даже если все колонки проиндексированы. Метод **Найти** выполняет поиск с применением индекса **только по одному полю**.

```1c
ТЗ.Индексы.Добавить("Колонка1");
ТЗ.Индексы.Добавить("Колонка2");
... = ТЗ.Найти("найдется все", "Колонка1, Колонка2"); // Индекс НЕ используется!
```

В этом примере, несмотря на наличие индексов, поиск будет выполняться перебором всех строк.

### 2.2. Метод НайтиСтроки — индекс должен точно соответствовать структуре поиска

При использовании метода **НайтиСтроки** в больших таблицах следует обеспечить, чтобы **список полей индекса был точно таким же**, как он задан в структуре поиска (порядок полей не важен).

**❌ Неправильно — индекс не используется:**

```1c
ТЗ.Индексы.Добавить("Колонка1"); // Индекс1
ТЗ.Индексы.Добавить("Колонка2"); // Индекс2

... = ТЗ.НайтиСтроки(Новый Структура("Колонка1, Колонка2", "Ищу1", "Ищу2")); // Индекс НЕ используется!
... = ТЗ.НайтиСтроки(Новый Структура("Колонка1", "Ищу1")); // OK - используется Индекс1
... = ТЗ.НайтиСтроки(Новый Структура("Колонка2", "Ищу2")); // OK - используется Индекс2
```

**✅ Правильно — составной индекс:**

```1c
ТЗ.Индексы.Добавить("Колонка1,Колонка2");

... = ТЗ.НайтиСтроки(Новый Структура("Колонка1, Колонка2", "Ищу1", "Ищу2")); // OK - индекс используется
... = ТЗ.НайтиСтроки(Новый Структура("Колонка2, Колонка1", "Ищу2", "Ищу1")); // OK - индекс используется
... = ТЗ.НайтиСтроки(Новый Структура("Колонка1", "Ищу1")); // Индекс НЕ используется!
... = ТЗ.НайтиСтроки(Новый Структура("Колонка2", "Ищу2")); // Индекс НЕ используется!
```

### 2.3. Метод Скопировать

Аналогичное ограничение действует и для метода **Скопировать** таблицы значений при вызове с параметром **ПараметрыОтбора** (Структура).

## 3. Сортировка таблиц значений

При сортировке по колонкам, содержащим **ссылочные значения**, система для каждой ссылки выполняет обращение к информационной базе за представлением.

**Рекомендации:**

- Если требуется сортировка по наименованию — добавлять дополнительные колонки с представлениями на этапе заполнения
- В остальных случаях — сортировать «по ссылке», а не по представлению, используя **СравнениеЗначений**:

```1c
ОбъектСравнения = Новый СравнениеЗначений;
ТаблицаДокументов.Сортировать("Дата,Ссылка", ОбъектСравнения);
```

Это особенно важно для таблиц с большим количеством строк (несколько сотен и тысяч).

## 3.1. Поиск в массивах

При поиске в объекте **Массив** с большим количеством элементов следует отказаться от массива в пользу:

| Условие | Рекомендуемая коллекция |
|---------|------------------------|
| Порядок элементов не важен | **Соответствие** |
| Порядок элементов значим | Индексированная **ТаблицаЗначений** |

Это обусловлено тем, что поиск в **Соответствие** и индексированной таблице занимает константное время, а в массиве — пропорционален количеству элементов.

> **Примечание:** следует ориентироваться на **1000 элементов и более**. Если поиск выполняется многократно (в цикле), рекомендация действительна и для массивов меньшего размера.

### 3.2. Уникальность элементов массива

При необходимости обеспечить уникальность элементов в большом массиве следует **однократно в конце алгоритма** вызвать:

- Функцию **СвернутьМассив**
- Или процедуру **ДополнитьМассив** с параметром `ТолькоУникальныеЗначения = Истина`

(модуль **ОбщегоНазначения** Библиотеки стандартных подсистем)

---

## 4. Дерево значений

Объект **ДеревоЗначений** не поддерживает индексы — поиск выполняется перебором (как в массиве).

В случаях, когда требуется быстрый поиск, **ДеревоЗначений** следует заменять индексированным объектом **ТаблицаЗначений**.

---

## Сводка

| Коллекция | Поиск | Рекомендация |
|-----------|-------|--------------|
| ТаблицаЗначений (большая) | Многократный | Индексировать колонки поиска |
| ТаблицаЗначений | По нескольким колонкам | Составной индекс + НайтиСтроки |
| Массив (большой) | Многократный | Заменить на Соответствие или индексированную ТЗ |
| ДеревоЗначений | Многократный | Заменить на индексированную ТЗ |
