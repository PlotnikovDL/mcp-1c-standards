# #std686 Работа с параметром «Отказ» в обработчиках событий

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Не присваивать Ложь параметру Отказ

В обработчиках событий с параметром **Отказ** (`ПриЗаписи`, `ОбработкаПроверкиЗаполнения`, `ТоварыПередНачаломДобавления` и т.п.) **не следует** присваивать этому параметру значение `Ложь`.

### Причина

- В коде может быть несколько последовательных проверок (или несколько подписок на одно событие)
- К моменту выполнения очередной проверки параметр `Отказ` уже может содержать `Истина`
- Можно ошибочно сбросить его обратно в `Ложь`
- При доработках число проверок может увеличиться

### Примеры

**❌ Неправильно:**

```1c
Процедура ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)
  ...
  Отказ = ЕстьОшибкиЗаполнения();  // Может сбросить Истина в Ложь!
  ...
КонецПроцедуры
```

**✅ Правильно:**

```1c
Процедура ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)
  ...
  Если ЕстьОшибкиЗаполнения() Тогда
    Отказ = Истина;
  КонецЕсли;
  ...
КонецПроцедуры
```

**✅ Или короткая форма:**

```1c
Отказ = Отказ Или ЕстьОшибкиЗаполнения();
```

## 2. Аналогичные параметры

Те же требования справедливы для других параметров:
- **СтандартнаяОбработка**
- **Выполнение**
- и др.

**Пример:**

```1c
Процедура ОбработкаПолученияДанныхВыбора(ДанныеВыбора, Параметры, СтандартнаяОбработка)

  Если Параметры.Свойство(...) Тогда
    СтандартнаяОбработка = Ложь;  // Здесь допустимо — мы отменяем стандартную обработку
    ...
  КонецЕсли;

КонецПроцедуры
```

## 3. Обязательно информировать пользователя

❌ **Неприемлемо** в событиях `ПриЗаписи`, `ПередЗаписью`, `ПередУдалением`, `ОбработкаПроведения`, `ОбработкаПроверкиЗаполнения` устанавливать `Отказ = Истина` **без информирования пользователя** о причинах.

### Проблема

Сообщение об ошибке становится неинформативным и скрывает истинные причины:

> Не удалось записать "Заказ покупателя"!

Расследование такой ошибки требует значительных временных затрат.

**❌ Неправильно:**

```1c
Процедура ОбработкаПроведения(Отказ, РежимПроведения)

  Если Не ТоваровНаСкладеДостаточно() Тогда
    Отказ = Истина;
    Возврат;  // Пользователь не узнает причину!
  КонецЕсли;

  ...

КонецПроцедуры
```

**✅ Правильно:**

```1c
Процедура ОбработкаПроведения(Отказ, РежимПроведения)

  Если Не ТоваровНаСкладеДостаточно() Тогда

    ТекстСообщения = СтрШаблон(
      НСтр("ru='Не хватает %1 %2 товара %3, на складе %4'"),
      Количество, ЕдиницаИзмерения, Товар, Склад);
    ОбщегоНазначения.СообщитьПользователю(ТекстСообщения,, "Объект.Товары",, Отказ);

  КонецЕсли;

  ...

КонецПроцедуры
```

---

## Сводка

| Правило | Требование |
|---------|------------|
| `Отказ = Ложь` | ❌ Никогда не присваивать |
| `Отказ = Истина` | ✅ Только устанавливать в `Истина` |
| Короткая форма | `Отказ = Отказ Или Проверка()` |
| СтандартнаяОбработка | Аналогичные правила |
| Информирование | ❌ Нельзя отменять без сообщения пользователю |
| Способ информирования | `СообщитьПользователю()` или исключение |
