# #std534 Удаление устаревших объектов метаданных из конфигурации

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Общие правила удаления

При удалении объекта метаданных (реквизита, измерения, ресурса), связанного с записями ИБ, необходимо принять решение об **удалении или переносе данных**.

### 1.1. Пометка как устаревший

⛔ **Не удалять** устаревшие объекты безвозвратно.

✅ Пометить как устаревшие, добавив префикс:

| Элемент | Префикс (рус.) | Префикс (англ.) |
|---------|----------------|-----------------|
| **Имя** | `Удалить` | `Obsolete` |
| **Синоним** | `(не используется)` | `(not used)` |

**Примеры:**
- Имя: `ОсновнойДоговор` → `УдалитьОсновнойДоговор`
- Синоним: `Основной договор` → `(не используется) Основной договор`

### 1.2. Перенос данных

После изменения структуры метаданных — обеспечить **перенос данных** из устаревших объектов в новую структуру.

### 1.3. Устаревшие документы-регистраторы

Если удаляемый документ является **регистратором движений**, а регистры остаются:

| Действие | Описание |
|----------|----------|
| 1. Запретить генерацию движений | При проведении документов этого вида |
| 2. Запретить снятие пометки удаления | Для документов этого вида |
| 3. Изменить регистратор | Во всех движениях — на замещающий документ (`ПереносДанных`, `Операция`) |
| 4. Пометить на удаление | Все документы этого вида |

### 1.4. Замена обращений

Произвести замену **во всей конфигурации** обращений к устаревшим объектам на новые данные:

- ⛔ Исключить из всех ролей (кроме `ПолныеПрава` и `АдминистраторСистемы`)
- ⛔ Исключить из подписок на события
- ⛔ Удалить код, формы, макеты, команды

**Исключение:** Код переноса данных из устаревших объектов.

### 1.5. Сортировка в дереве метаданных

Следовать общим требованиям к конфигурации.

### 1.6. Очистка устаревших данных

✅ Рекомендуется выполнить очистку, чтобы данные не влияли на:
- Размер базы
- Резервное копирование
- Реструктуризацию

⚠️ При сложных алгоритмах переноса — очистку проводить **через один или несколько релизов** (для возможности исправления ошибок).

---

## 2. Изменение измерений регистров сведений

Необходимость в переносе данных возникает при:
- Удалении измерения регистра сведений
- Сокращении типа измерения

### 2.1. Проблема

При реструктуризации может возникнуть ошибка: **«Записи регистра стали неуникальными»**

### 2.2. Решения

| Вариант | Когда применять |
|---------|-----------------|
| Создать новый регистр | Данные нужно сохранить, перенести записи из старого в новый |
| Установить `Режим сокращения типа` = `Удалять данные` | Данные можно удалять |

### 2.3. Когда устанавливать «Удалять данные»

Свойство `Режим сокращения типа` = `Удалять данные` устанавливать, если:
- В измерении используется универсальный тип (`СправочникСсылка`, `ДокументСсылка`, …)
- Измерение регистра библиотеки настраивается в типовых решениях

### 2.4. Когда новый регистр НЕ требуется

- Добавляется новое измерение
- У измерения составного типа **расширяется** состав типов

## 3. Безвозвратное удаление

Удалять устаревшие объекты с префиксом `Удалить` безвозвратно **только при соблюдении одного из условий:**

### 3.1. Последовательное обновление

Переход со «старой» версии на новые **всегда выполняется последовательно** через версию с переносом данных.

**Пример:**
```
Версия 1.0 → Версия 1.1 (перенос данных) → Версия 2.0 (удаление)
```

⛔ Непосредственный переход 1.0 → 2.0 технически невозможен.

### 3.2. Нулевая вероятность использования

Вероятность использования «старой» версии стала **нулевой или пренебрежимо малой**.

### 3.3. Промежуточный релиз

Может потребоваться выпустить **промежуточный релиз** для очистки устаревших данных (см. п.1.6), иначе реструктуризация регистров с ссылками на устаревшие данные может завершиться ошибкой.

---

## 4. Сводная таблица

| Этап | Действие |
|------|----------|
| Пометка | Префикс `Удалить` в имени, `(не используется)` в синониме |
| Перенос данных | Обработчик обновления ИБ |
| Очистка кода | Удалить из ролей, подписок, форм, макетов |
| Очистка данных | Через 1-2 релиза (при сложных алгоритмах) |
| Безвозвратное удаление | После гарантированного обновления всех ИБ |
