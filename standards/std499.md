# #std499 Перехват исключений в коде

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Общее правило

**Не следует перехватывать исключения**, кроме случаев, описанных ниже.

Необработанное исключение:
- Выводится пользователю
- Записывается в журнал регистрации для администратора
- При необходимости отправляется в сервис регистрации ошибок средствами платформы 1С:Предприятие

Для распространенных исключений в платформе предусмотрены категории ошибок и шаблоны с соответствующими сообщениями и рекомендациями.

---

## 2. Когда допустимо перехватывать исключения

В ряде случаев технологический текст исключения непонятен, поэтому его нужно дополнить прикладной, понятной пользователю информацией, типовыми причинами или рекомендациями по устранению возникшей проблемы.

К этой категории проблем относятся:
- Недоступность внешних ресурсов и каналов связи
- Некорректная работа внешних сервисов
- Некорректные входные данные
- Некорректные настройки используемых внешних приложений
- Проблемы взаимодействия с почтовыми серверами, веб-сервисами, принтерами, криптопровайдерами

### 2.1. Перехват и проброс с уточнением

Допустимо перехватить и пробросить исключение **без потери исходного содержания** с необходимым уточнением.

**Важно:** Не следует открывать большие блоки `Попытка-Исключение`, а расставлять их локально на конкретные потенциально проблемные места, вызовы конкретных методов платформы, чтобы исключить перехват других несвязанных ошибок.

Для проверки вывода исключений пользователю рекомендуется запускать 1С:Предприятие без отладки и без режима технического специалиста.

### 2.2. Собственная обработка с расширенной диагностикой

В особых случаях может быть предусмотрена собственная обработка исключений с расширенной диагностикой проблем (например, в обработчиках обновления информационной базы).

**Следует:**
- Фильтровать и отправлять ошибки программного кода в сервис регистрации ошибок — см. `ИнформацияОбОшибке.ЯвляетсяОшибкойКатегории` и `ОтчетОбОшибке.Отправить`
- Фиксировать причину ошибки в журнале регистрации
- Записывать в журнал регистрации **подробное представление** исключения — см. `ОбработкаОшибок.ПодробноеПредставлениеОшибки`
- Сообщение для пользователя добавлять через `ОбработкаОшибок.СообщениеОбОшибкеДляПользователя`

**Не следует:**
- Использовать `ОписаниеОшибки` вместо `ОбработкаОшибок.ПодробноеПредставлениеОшибки` — она неинформативна, не возвращает стек
- Использовать `ОбработкаОшибок.КраткоеПредставлениеОшибки` вместо `ОбработкаОшибок.СообщениеОбОшибкеДляПользователя` — она не возвращает уточнений, добавленных при пробросе

## 3. Частные случаи некорректного перехвата

> Область применения (уточнение): управляемое приложение, обычное приложение.

### 3.1. Анализ текста исключений

**Не следует** анализировать текст исключений с целью интерпретации причины ошибки. Текст исключения может меняться в зависимости от локализации версий платформы и конфигурации.

Следует выдавать пользователю тексты исключений «как есть». Для понятности текст можно уточнить описанием прикладной операции, а также дополнить пояснением возможных причин.

**Пример:**

```1c
Попытка
    ЗагрузитьФайлИзИнтернета(...);
Исключение
    ИнформацияОбОшибке = ИнформацияОбОшибке();
    ТекстСообщения = ОбработкаОшибок.СообщениеОбОшибкеДляПользователя(ИнформацияОбОшибке);
    ТекстСообщения = НСтр("ru = 'Не удалось загрузить файл классификатора АУЦ:'")
        + Символы.ПС + ТекстСообщения
        + Символы.ПС + НСтр("ru = 'Возможные причины:
        | • Нет подключения к Интернету;
        | • На веб-узле возникли неполадки;
        | • Брандмауэр или другое промежуточное ПО (антивирусы и т.п.) блокируют попытки программы подключиться к Интернету;
        | • Подключение к Интернету выполняется через прокси-сервер, но его параметры не заданы в программе.'");
    ДляАдминистратора = ДиагностикаСоединенияСИнтернет(); // В подробное представление ошибки для журнала регистрации.
    ВызватьИсключение(ТекстСообщения,,, ДляАдминистратора, ИнформацияОбОшибке);
КонецПопытки;
```

**При использовании БСП** — применять функцию `ОбщегоНазначенияКлиентСервер.УточнениеИсключения`:

```1c
Попытка
    ЗагрузитьФайлИзИнтернета(...);
Исключение
    ИнформацияОбОшибке = ИнформацияОбОшибке();
    Уточнение = ОбщегоНазначенияКлиентСервер.УточнениеИсключения(ИнформацияОбОшибке,
        НСтр("ru = 'Не удалось загрузить файл классификатора АУЦ:'"));
    Уточнение.Текст = Уточнение.Текст + Символы.ПС + НСтр("ru = 'Возможные причины:
        | • Нет подключения к Интернету;
        | • На веб-узле возникли неполадки;
        | • Брандмауэр или другое промежуточное ПО (антивирусы и т.п.) блокируют попытки программы подключиться к Интернету;
        | • Подключение к Интернету выполняется через прокси-сервер, но его параметры не заданы в программе.'");
    ДляАдминистратора = ДиагностикаСоединенияСИнтернет(); // В подробное представление ошибки для журнала регистрации.
    ВызватьИсключение(Уточнение.Текст, Уточнение.Категория,, ДляАдминистратора, ИнформацияОбОшибке);
КонецПопытки;
```

### 3.2. Бесследный перехват исключений

**❌ Недопустимо** перехватывать любые исключения бесследно для системного администратора:

```1c
Попытка
    // код, приводящий к вызову исключения
    ....
Исключение // перехват любых исключений
КонецПопытки;
```

Такая конструкция скрывает реальную проблему, которую впоследствии невозможно диагностировать.

**✅ Правильно:**

```1c
Попытка
    // код, приводящий к вызову исключения
    ....
Исключение
    // Пояснение причин перехвата всех исключений "незаметно" от пользователя.
    // ....
    // И запись события в журнал регистрации для системного администратора.
    ЗаписьЖурналаРегистрации(НСтр("ru = 'Выполнение операции'"),
        УровеньЖурналаРегистрации.Ошибка,,,
        ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
КонецПопытки;
```

## Сводка

| Ситуация | Рекомендация |
|----------|--------------|
| Обычные ошибки | Не перехватывать — платформа обработает сама |
| Внешние ресурсы, сервисы | Перехватить, уточнить текст, пробросить дальше |
| Собственная диагностика | Записать в журнал, отправить в сервис ошибок |
| Пустой блок `Исключение` | ❌ Недопустимо — всегда записывать в журнал |
| Анализ текста исключения | ❌ Не анализировать — текст может меняться |
