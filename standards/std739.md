# #std739 Размещение сведений о настройках подсистемы

> Область применения: управляемое приложение, обычное приложение.

---

Для задействования возможностей по настройке функциональности [библиотеки](#std551) для работы в конкретной конфигурации-потребителе используются [переопределяемые объекты](#std553).

Все настройки подсистемы, доступные для изменения разработчикам на внедрении, можно разделить на:
- **Общие** для всех объектов подсистемы (или для группы объектов)
- **Специфичные** для конкретных объектов

---

## 1. Общие настройки подсистемы

Настройки подсистемы, общие для всех объектов или для группы объектов метаданных, рекомендуется задавать в **переопределяемом модуле**.

### Процедура ПриОпределенииНастроек

Создать одну процедуру с именем **ПриОпределенииНастроек** и параметром **Настройки** типа **Структура**, которая предварительно заполнена значениями по умолчанию.

**Преимущество:** использование структуры позволяет расширять программный интерфейс, добавляя новые свойства, без нарушения [обратной совместимости](#std644).

**Пример** — общий модуль `ВариантыОтчетовПереопределяемый`:

```1c
Процедура ПриОпределенииНастроек(Настройки) Экспорт
  Настройки.ВыводитьОтчетыВместоВариантов = Истина;
  Настройки.ВыводитьОписания = Истина;
  Настройки.ДругиеОтчеты.ПоказыватьФлажок = Истина;
КонецПроцедуры
```

### 1.1. Определение списка объектов подсистемы

❌ **Не следует** использовать перебор объектов метаданных с [конструкцией Попытка Исключение](#std499).

✅ Рекомендуется создавать **отдельную процедуру** переопределяемого модуля, в которой перечислять такие объекты.

**Пример:** `ПриОпределенииПодключенныхОтчетов` — содержит список отчётов конфигурации, подключённых к подсистеме.

### 1.2. Переопределение бизнес-логики для всех объектов

Процедуры, позволяющие переопределить бизнес-логику сразу для всех объектов, с которыми работает подсистема, также рекомендуется размещать в переопределяемом модуле.

**Правила именования:**
- Имена выбирать исходя из выполняемого действия
- Для каждого выполняемого действия создавать отдельную процедуру

**Пример:** `ПриРегистрацииИзмененийКлючейВариантовОтчетов` — описывает изменения имён вариантов отчётов.

## 2. Настройки, специфичные для отдельного объекта

Настройки или обработчики, специфичные для отдельного объекта, рекомендуется размещать в **модуле менеджера** этого объекта.

### Процедура ПриОпределенииНастроек<ИмяПодсистемы>

Для процедуры, содержащей информацию о свойствах, реквизитах или наличии методов объекта, рекомендуется использовать имена вида:

**ПриОпределенииНастроек\<ИмяПодсистемы\>**

**Пример:** `ПриОпределенииНастроекВариантовОтчетов`

### Переопределяемая бизнес-логика объекта

Процедуры, задающие переопределяемую бизнес-логику, специфичную для конкретного объекта, также рекомендуется размещать в модуле менеджера.

**Правила:**
- Для каждого выполняемого действия создавать отдельную процедуру
- Наличие процедуры в модуле менеджера задаётся в процедуре `ПриОпределенииНастроек<ИмяПодсистемы>`

Это позволяет избежать использования [конструкции Попытка Исключение](#std499) для проверки наличия процедуры.

**Пример** — модуль менеджера отчёта:

```1c
Процедура ПриОпределенииНастроекВариантовОтчетов(Настройки) Экспорт
  Настройки.ОпределитьНастройкиФормы = Истина;
  Настройки.Размещение.Вставить(ВариантыОтчетовКлиентСервер.ИдентификаторНачальнойСтраницы(), "Важный");
  Настройки.ПриПолученииДанныхОтчета = Истина; // Наличие процедуры.
КонецПроцедуры

Процедура ПриПолученииДанныхОтчета(Данные) Экспорт
  Данные.Очистить();
  // Своя процедура получения данных.
КонецПроцедуры
```

Процедура **ПриОпределенииНастроекВариантовОтчетов** определяет настройки конкретного отчёта и сообщает о наличии процедуры **ПриПолученииДанныхОтчета**, в которой задана переопределяемая обработка данных отчёта.

## Сводка

| Тип настроек | Где размещать | Пример процедуры |
|--------------|---------------|------------------|
| Общие для всех объектов | Переопределяемый модуль | `ПриОпределенииНастроек` |
| Список объектов подсистемы | Переопределяемый модуль | `ПриОпределенииПодключенныхОтчетов` |
| Бизнес-логика для всех объектов | Переопределяемый модуль | `ПриРегистрацииИзмененийКлючей...` |
| Специфичные для объекта | Модуль менеджера объекта | `ПриОпределенииНастроек<Подсистема>` |
| Бизнес-логика объекта | Модуль менеджера объекта | `ПриПолученииДанныхОтчета` |

| Правило | Описание |
|---------|----------|
| Параметр Структура | Позволяет расширять интерфейс без нарушения обратной совместимости |
| Отдельные процедуры | Для каждого действия — своя процедура |
| Флаги наличия процедур | Избегать Попытка/Исключение для проверки наличия метода |
