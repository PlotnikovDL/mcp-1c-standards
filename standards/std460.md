# #std460 Использование управляемого режима блокировки

> Область применения: управляемое приложение, обычное приложение.

---

## Основное требование

Используйте **управляемый** режим блокировок:

```
Конфигурация → Режим управления блокировкой данных = Управляемый
```

---

## Особенности управляемого режима

### 1. Чтение данных другими транзакциями

Чтение заблокировано **только** если в текущей и других транзакциях установлены **несовместимые** управляемые блокировки.

### 2. Когда устанавливать явную блокировку

Управляемая блокировка устанавливается **перед** чтением данных, если:

| Ситуация | Требуется блокировка |
|----------|---------------------|
| Данные будут изменены | ✅ Да |
| Данные должны быть неизменны до конца транзакции | ✅ Да |
| Только чтение без изменения | ❌ Нет |

### 3. Минимальная область блокировки

Блокируйте **только** те записи, которые будут обработаны.

### 4. Конструкция ДЛЯ ИЗМЕНЕНИЯ

❌ **Не используйте** `ДЛЯ ИЗМЕНЕНИЯ` в запросах — в управляемом режиме она **не имеет смысла**.

---

## Автоматический vs Управляемый режим

| Режим | Особенности |
|-------|-------------|
| **Автоматический** | Высокая изоляция на уровне СУБД, нет нужды в явных блокировках, но возможны **избыточные** блокировки |
| **Управляемый** | Меньше избыточных блокировок, но требует **явного** управления блокировками в коде |

### Причины избыточных блокировок в автоматическом режиме

- Особенности реализации механизмов блокировок в СУБД
- СУБД не учитывает структуру объектов метаданных 1С:Предприятия

---

## Сводка

| Правило | Описание |
|---------|----------|
| Режим | Управляемый |
| Явная блокировка | Перед чтением данных для изменения |
| Область блокировки | Только нужные записи |
| `ДЛЯ ИЗМЕНЕНИЯ` | Не использовать |
