# #std498 Использование журнала регистрации

> Область применения: управляемое приложение, обычное приложение.

---

## 1. Назначение

Журнал регистрации предназначен для хранения событий, возникающих в процессе работы пользователей с информационной базой. При администрировании эту информацию часто необходимо анализировать в различных разрезах для того, чтобы например, узнать какие события происходили в определенный момент времени, какие действия выполнял тот или иной пользователь.

---

## 2. Когда записывать в журнал регистрации

Рекомендуется производить запись в журнал регистрации из встроенного языка в тех случаях, когда администратору необходимо сообщить дополнительную диагностическую информацию о событиях, которые не записываются платформой **1С:Предприятие**.

Такая необходимость может возникнуть как при выполнении бизнес-логики, вызываемой при интерактивной работе, так и в фоновых (регламентных) заданиях.

**Важно:** Одна запись журнала должна соответствовать одному событию.

---

### 2.1. Строковый идентификатор типа события

Типы событий рекомендуется группировать по функциональному признаку: `«Название группы событий.Название события»`.

**✅ Правильно:**
- `Поручения.Уведомление о новых задачах`
- `Поручения.Уведомление о зависших задачах`

**❌ Неправильно** (плоские типы):
- `Уведомление о новых задачах`
- `Уведомление о зависших задачах`

**❌ Неправильно** (конкретные значения в типе события):
- `Не удалось отменить проведение документа <Реализация КП00-00002 от 11>`
- `В информационной базе не найден сотрудник Найденова, банковская карта 3333`

**✅ Правильно** (общие типы + данные в параметрах):
- `Проведение документов.Не удалось отменить проведение`
- `Сотрудники.В информационной базе не найден сотрудник`

Метаданные помещать в параметр **Метаданные**, а данные — в параметр **Данные** метода `ЗаписьЖурналаРегистрации`.

Текст типа события — **локализуем**, при этом всегда задается основной язык конфигурации.

---

### 2.2. Уровень важности события

| Уровень | Назначение |
|---------|------------|
| **Ошибка** | Критичные события, требующие повышенного внимания администратора (ошибки бизнес-логики, сбои в программе) |
| **Предупреждение** | Потенциальные проблемы и не фатальные ошибки |
| **Информация** | Информационные сообщения об успешном завершении операции |
| **Примечание** | Более низкий уровень важности |

---

### 2.3. Комментарий

Содержит текстовую неструктурированную информацию о событии. В случае ошибок — информацию, необходимую для расследования причины проблемы.

**❌ Неправильно** — несколько событий в одном комментарии:

```
[01.01.2010 00:00:01] Начало инициализации обмена данными по настройке "Обмен данными выгрузка", номер строки настройки: 1
[01.01.2010 00:00:02] Окончание инициализации обмена данными (успешно)
[01.01.2010 00:00:03] Начало процесса обмена данными по настройке "Обмен данными выгрузка", номер строки настройки: 1
[01.01.2010 00:00:04] Начало записи изменений в файл обмена
[01.01.2010 00:00:05] Окончание записи изменений в файл обмена (успешно)
[01.01.2010 00:00:06] Окончание процесса обмена данными по настройке "Обмен данными выгрузка", номер строки настройки: 1
[01.01.2010 00:00:07] Выполнено, Выгрузка данных, Обработано 1 объектов
```

**✅ Правильно** — записать столько событий, сколько их реально произошло.

**Ограничения:**
- Не помещать текстовые данные неизвестного размера (содержимое файлов, ответы веб-сервисов и т.п.)
- Максимальный размер — ориентироваться на **10 Кб**

Текст комментария — **локализуем**.

Для записи информации об исключении:

```1c
ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())
```

---

## Пример

```1c
Попытка
    ЗаписьЖурналаРегистрации(
        НСтр("ru = 'Мой механизм.Действие с возможной ошибкой'", КодОсновногоЯзыка),
        УровеньЖурналаРегистрации.Информация, , ,
        НСтр("ru = 'Начато действие'"));

    ДействиеСВозможнойОшибкой(ОбъектДействия);

    ЗаписьЖурналаРегистрации(
        НСтр("ru = 'Мой механизм.Действие с возможной ошибкой'", КодОсновногоЯзыка),
        УровеньЖурналаРегистрации.Информация, , ,
        НСтр("ru = 'Завершено действие'"));
Исключение
    ЗаписьЖурналаРегистрации(
        НСтр("ru = 'Мой механизм.Действие с возможной ошибкой'", КодОсновногоЯзыка),
        УровеньЖурналаРегистрации.Ошибка, , ,
        НСтр("ru = 'Во время выполнения действия произошла неизвестная ошибка.'") + Символы.ПС +
        ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
КонецПопытки;
```

где переменная **КодОсновногоЯзыка** содержит код языка для хранения данных в информационной базе.

---

## 3. Производительность выборки

**Не следует** использовать выборку из журнала регистрации в задачах, где критична высокая скорость выполнения выборки. При больших объемах журнала скорость выборки падает пропорционально увеличению его объема.

**Рекомендации:**
- Заводить отдельный регистр для протоколирования интересующих событий
- Обращаться к специализированным объектам платформы (например, `МенеджерФоновыхЗаданий` для выборки истории выполнения фоновых заданий)

Эту особенность нужно также учитывать при разработке отчетов по журналу регистрации.
