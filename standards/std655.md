# #std655 Ограничения на соединения с вложенными запросами и виртуальными таблицами

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Соединения с вложенными запросами

### 1.1. Запрет соединений с вложенными запросами

**Не используйте** соединения с вложенными запросами. Соединяйте только:
- Объекты метаданных
- Временные таблицы

❌ **Неправильно:**
```1c
ВЫБРАТЬ ...
ИЗ Документ.РеализацияТоваровУслуг
ЛЕВОЕ СОЕДИНЕНИЕ (
    ВЫБРАТЬ ИЗ РегистрСведений.Лимиты
    ГДЕ ...
    СГРУППИРОВАТЬ ПО ...
) ПО ...
```

### Последствия нарушения

| Проблема | Описание |
|----------|----------|
| Катастрофическое замедление | До нескольких порядков |
| Нестабильная работа | Иногда быстро, иногда очень медленно |
| Разница между СУБД | Значительная разница во времени выполнения |
| Зависимость от статистик | После обновления — быстро, потом — медленно |

### Причина

Оптимизатор СУБД не может определить размер выборки вложенного запроса → выбирает неправильный алгоритм соединения.

### 1.2. Решение — временные таблицы

✅ **Правильно:**
```1c
// Создать менеджер временных таблиц
МенеджерВТ = Новый МенеджерВременныхТаблиц;
Запрос = Новый Запрос;
Запрос.МенеджерВременныхТаблиц = МенеджерВТ;

Запрос.Текст = "
    // Заполняем временную таблицу
    |ВЫБРАТЬ ...
    |ПОМЕСТИТЬ Лимиты
    |ИЗ РегистрСведений.Лимиты
    |ГДЕ ...
    |СГРУППИРОВАТЬ ПО ...
    |ИНДЕКСИРОВАТЬ ПО ...;
    |
    |// Основной запрос с временной таблицей
    |ВЫБРАТЬ ...
    |ИЗ Документ.РеализацияТоваровУслуг
    |ЛЕВОЕ СОЕДИНЕНИЕ Лимиты
    |ПО ...";
```

**Преимущества:**
- СУБД легко определяет размер каждой выборки
- Гарантированно выбирается оптимальный план
- Одинаково хорошо работает на всех СУБД
- Лучше читается и отлаживается

---

## 2. Соединения с виртуальными таблицами

Если запрос с соединением с виртуальной таблицей (например, `РегистрНакопления.Товары.Остатки`) работает медленно — **вынесите** обращение к виртуальной таблице в отдельный запрос с временной таблицей.

---

## 3. Вложенные соединения

### 3.1. Проблема

Вложенные соединения создают **неявные подзапросы**.

❌ **Неправильно:** (вложенное соединение)
```1c
ВЫБРАТЬ ...
ИЗ Справочник.Номенклатура
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах
        ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыОрганизаций
        ПО ...
    ПО ...
```

Это эквивалентно:
```1c
ВЫБРАТЬ ...
ИЗ Справочник.Номенклатура
    ЛЕВОЕ СОЕДИНЕНИЕ (
        ВЫБРАТЬ ...
        ИЗ РегистрНакопления.ТоварыНаСкладах
            ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыОрганизаций
            ПО ...)
    ПО ...
```

### 3.2. Решение — последовательные соединения

✅ **Правильно:**
```1c
ВЫБРАТЬ ...
ИЗ Справочник.Номенклатура
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах
    ПО ...
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыОрганизаций
    ПО ...
```

⚠️ **Важно:** Вложенные и последовательные соединения — **разные запросы** с потенциально разными результатами. Анализируйте логику перед заменой.

---

## 4. Сводка

| Ситуация | Решение |
|----------|---------|
| Соединение с вложенным запросом | Временная таблица |
| Соединение с виртуальной таблицей (медленно) | Временная таблица |
| Вложенное соединение | Последовательное соединение или временная таблица |
