# #std728 Ограничения на использование реквизитов составного типа

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Составные типы в запросах

### 1.1. Только ссылочные типы

Реквизиты составного типа, используемые в:
- Условиях соединений
- Отборах
- Упорядочивании

должны содержать **только ссылочные типы** (`СправочникСсылка.[…]`, `ДокументСсылка.[…]` и пр.).

⛔ **Не рекомендуется** включать нессылочные типы:
- `Строка`
- `Число`
- `Дата`
- `УникальныйИдентификатор`
- `Булево`
- `ХранилищеЗначения`

**Причина:** Производительность запросов заметно снижается из-за особенностей физического хранения составных типов в колонках таблиц СУБД.

### 1.2. Обходное решение

**Проблема:** Реквизит `Адрес` составного типа включает ссылку на справочник `Контакты` и строку для произвольных значений.

**Решение:**
1. Создать отдельный справочник `ПроизвольныеАдреса`
2. Указать его в реквизите `Адрес` вместо строки
3. Добавление новых элементов — автоматически при записи документа («незаметно» от пользователя)
4. Удаление ненужных элементов — посредством регламентного задания

### 1.3. Исключение

✅ Таблицы с **малым объёмом данных** (до 1000 записей) — допускается использование смешанных составных типов.

---

## 2. Запрет широких составных типов

### 2.1. Явное определение состава типов

⛔ **Не следует использовать** для типизированных объектов метаданных:
- `ЛюбаяСсылка`
- `СправочникСсылка`
- `ДокументСсылка`
- Аналогичные широкие типы

✅ Состав типов должен определяться **явным образом**.

**Исключение:** Универсальные механизмы (алгоритмы), действительно рассчитанные на работу с произвольными ссылочными объектами.

### 2.2. Проблемы избыточных составных типов

| Проблема | Описание |
|----------|----------|
| **Деградация производительности** | При обращении «через точку» без `ВЫРАЗИТЬ` — неявное соединение со ВСЕМИ таблицами составного типа |
| **Избыточная реструктуризация** | При удалении ссылочного объекта метаданных (значения перечисления, точки маршрута бизнес-процесса) |
| **Усложнение алгоритмов** | Избыточный расчёт на широкий набор объектов, не требуемых для прикладной задачи |
| **Сложность анализа** | Затруднения для внедренцев и сторонних разработчиков |
| **Неудобный выбор** | В полях форм — выбор из очень большого списка типов (когда реально нужно 3-5 типов) |
| **Избыточные блокировки** | При удалении помеченных объектов — анализ и блокировки таблиц при поиске ссылок |

## 3. Определяемые типы

> *Область применения (уточнение): управляемое приложение, обычное приложение.*

### 3.1. Когда использовать

✅ Если составной тип **массово используется** в объектах подсистемы или всей конфигурации — рекомендуется использовать **определяемые типы**.

### 3.2. Исключение для библиотечных механизмов

Для **ведущих измерений регистров** универсальных (библиотечных) механизмов, рассчитанных на работу с произвольными ссылочными объектами, использование широких типов (`ЛюбаяСсылка`, `СправочникСсылка`, `ДокументСсылка`) **оправданно**.

**Причина:** При сужении состава определяемого типа в конфигурации придётся пересоздавать библиотечный регистр, что недопустимо.

---

## 4. Сводная таблица

| Ситуация | Рекомендация |
|----------|--------------|
| Составной тип в соединениях/отборах/сортировке | Только ссылочные типы |
| Нужна строка в составном типе | Создать отдельный справочник |
| Малая таблица (до 1000 записей) | Допускается смешанный тип |
| Типизация объектов метаданных | Явное определение состава типов |
| Массовое использование составного типа | Определяемый тип |
| Библиотечные регистры | Допускается ЛюбаяСсылка и аналогичные |
