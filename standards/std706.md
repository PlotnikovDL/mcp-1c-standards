# #std706 Ограничения на переименование объектов метаданных

> Область применения: управляемое приложение, мобильное приложение, обычное приложение.

---

## 1. Запрет: переименование + создание нового с тем же именем

### 1.1. Общие модули

⛔ **Запрещается:** Переименовать общий модуль и создать новый с тем же именем.

✅ **Правильно:** Создать новый модуль с **новым именем**, код исходного модуля перенести в новый.

**Причина:** При сравнении/объединении с конфигурацией поставщика подписки на события установят связь по имени с **новым** модулем (а не переименованным), где нет требуемых процедур.

### 1.2. Другие объекты метаданных

При необходимости удалить объект и создать новый с тем же именем (например, при «сужении» измерений регистра):

✅ **Правильно:** Переименовать устаревший объект, добавив префикс **«Удалить»**.

**Причина:** Если в конфигурации на поддержке в устаревший объект вносились изменения с сохранением поддержки, он не будет удалён при объединении → два объекта с одинаковым именем → ошибка обновления конфигурации БД.

---

## 2. Хранение ссылок на объекты метаданных (рекомендация)

### 2.1. Без БСП

Использовать **строковые реквизиты** (`Строка`, 255) для хранения полных имён объектов метаданных.

**Примеры:**
- Справочник `ШаблоныСообщений` → реквизит `ПолноеИмяТипаПараметраВводаНаОсновании`
- Регистр сведений `НастройкиПечатиОбъектов` → измерение `ТипОбъекта`

⚠️ При переименовании/удалении объектов метаданных — **обязательно** предусмотреть замену/удаление всех хранимых имён при обновлении ИБ.

### 2.2. С БСП

Использовать ссылки на справочник **ИдентификаторыОбъектовМетаданных**.

**Преимущества:**
- Централизованное хранение ссылок
- Автоматическое отслеживание переименований, удалений, добавлений
- Нет массовых операций по замене имён
- Меньший размер записей (ссылка вместо строки 255)

### 2.3. Исключение: роли и подсистемы

Для **ролей и подсистем** переименования **не отслеживаются автоматически** — требуется явно описать переименования.

**Последствия без явного описания:**
- Старый элемент помечается на удаление, создаётся новый
- Варианты отчетов исчезают из панели отчётов
- Дополнительные отчёты/обработки пропадают из разделов
- Переименованные роли не назначаются пользователям

### 2.4. Объекты других конфигураций

Справочник `ИдентификаторыОбъектовМетаданных` **не предназначен** для хранения ссылок на объекты метаданных других конфигураций. Для интеграции — использовать строковые реквизиты.

## 3. Параллельные ветки разработки

При ведении параллельных веток (например, версии 2.0 и 3.0, или исправительные + функциональные релизы):

⛔ **Запрещается** в текущей и младших версиях:
- Переименование с последующим созданием нового объекта с тем же именем
- Двойное переименование

✅ **Правильно:** Выполнять такие переименования только в **самой последней версии** (3.0).

**Причина:** При переходе с младшей версии на старшую переименование учтётся дважды → рассогласование ссылок.

При использовании `ИдентификаторыОбъектовМетаданных` БСП этот запрет действует **только для ролей и подсистем**.

---

## 4. Сводная таблица ограничений

| Действие | Разрешено | Правильный способ |
|----------|-----------|-------------------|
| Переименовать модуль + создать новый с тем же именем | ⛔ Нет | Создать модуль с новым именем |
| Удалить объект + создать новый с тем же именем | ⛔ Нет | Добавить префикс «Удалить» к старому |
| Переименовать роль/подсистему (БСП) | ⚠️ С оговоркой | Явно описать переименование |
| Двойное переименование в младшей версии | ⛔ Нет | Только в последней версии |
